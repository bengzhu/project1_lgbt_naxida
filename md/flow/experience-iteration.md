# 大版本自迭代体验验证流程

> 只规范版本后的用户视角验证、产物和记忆；不新增产品功能、模型路径或 CI workflow。

## 1. 触发与闸门

只在 `smalldata_test` 完成一个工程大版本（版本号递增、当前提交已有必要的 full receipt）后触发一次；普通修复提交、文档提交和同一版本的重复 push 不触发。体验验证通过前，状态文件中的 `next_goal` 不得进入下一版本开发。

固定循环：

```text
读取状态 -> 核对 exact SHA / 唯一 latest build -> 清理上一轮产物
  -> 固定基准设备跑一次首次使用主路径
  -> 写操作日志，最多保留 3 张辅助截图
  -> 自动检查体验底线
      -> pass：记录结论，解锁下一版本
      -> fail：记录问题，修复后用同一场景重跑
      -> blocked：记录外部阻塞，停在当前版本
```

正常的 pass/fail 分支可无人值守串行运行；同一问题最多自动重跑 3 次，仍失败或缺少设备/build 时标记 `blocked`，不得绕过闸门继续升版本。

## 2. 固定用户与基准

- 人设是“第一次使用、毫无经验的普通用户”，不读开发文档、不使用快捷路径；从干净的 App 状态开始。
- 本项目是 iOS App，默认基准为紧凑 iPhone 竖屏 `393 × 852 pt`；每轮同时记录实际设备、系统、逻辑尺寸和 scale。基准不可用时标记 `blocked`，不静默换设备。
- 每轮只跑一条主路径和必要的一条恢复路径，目标控制在合理时间内（通常不超过 10 分钟）；不重复下载模型、不录视频、不因小提交频繁触发。

## 3. 首次使用场景

按版本实际功能选择主路径，但至少覆盖：

| 场景 | 观察点 |
| --- | --- |
| 启动/进入首页 | 是否立即知道主要操作和下一步 |
| 输入图片或内容 | 是否存在多余点击、状态是否立即反馈 |
| 等待识别/处理 | 进度、阶段和等待原因是否清楚 |
| 查看结果 | 文字、控件、状态和结果是否看得清、看得懂 |
| 失败/取消/低置信结果（若暴露） | 是否能柔和恢复，是否保留可用结果 |
| 完成后操作 | 复制、导出、重新开始或继续操作是否明确 |

每一步都写入操作日志；不得用截图单独判定“体验通过”。

## 4. 体验底线

以下均为硬门：

1. 一次点击能完成的事不拆成两步；可撤销操作免确认。
2. 每次交互在 `100 ms` 内出现可见或可访问反馈。这里检查的是“收到反馈”，不是要求 OCR/翻译在 100 ms 内完成；超时即缺陷。
3. 用户始终知道下一步做什么；等待、成功、失败和空态都必须有下一步提示。
4. 误操作使用柔和、可理解的提示；不得无反应或弹出无法行动的报错框。
5. 基准分辨率下正文、状态和按钮可读，热区至少 `44 pt`，文字/图标/颜色共同表达状态，不依赖颜色单独传达。
6. 同类操作在页面和版本间保持相同的名称、位置、手势和反馈语义。

任一硬门失败即 `fail`；无法观察或证据不完整即 `blocked`，不按“可能没问题”放行。

## 5. 操作日志与判定

`test/experience/latest/run.jsonl` 是主要证据，每个操作一行 JSON，至少包含：

```text
timestamp, operation, target, startAt, feedbackAt, completionAt,
feedbackMs, completionMs, expected, observed, achieved, extraSteps, screenshot
```

判定规则：

- `feedbackMs > 100`、`achieved=false`、出现未解释的额外步骤或 `observed` 为空，均为失败项。
- `completionMs` 只用于记录等待体验；长任务必须有及时的阶段反馈和可取消/重试语义。
- 日志必须能回答“做了什么、何时做、多久有反馈、是否达到预期”；缺字段不算通过。
- `summary.md` 只写本轮 `pass/fail/blocked`、失败操作、下一步和产物清单，不复制历史轮次。

## 6. 产物边界

每轮唯一产物根目录为 `test/experience/latest/`：

```text
test/experience/latest/
├── build/                 # 只放当前 exact SHA 的一个 latest build
├── run.jsonl              # 主证据
├── summary.md             # 本轮结论
└── screenshots/           # 0–3 张辅助 PNG
```

- 新一轮开始前，只枚举并清理这个目录内的旧文件/子目录；先确认其 `realpath` 正是项目根下的 `test/experience/latest` 且不是符号链接，再对已枚举的子项使用 `trash`。禁止 `rm -rf`、通配项目根、清理 `output/`、源码、系统文件或其他项目。
- 每轮最多 3 张截图，只用于字号、对比度、布局、热区和下一步可见性；禁止录视频。
- `build/` 只保留一个当前构建，不按版本累积副本；构建必须能对应本轮 exact SHA。
- 产物目录之外不得产生或宣称本轮体验证据；旧轮次不归档。

## 7. 精简记忆与持续循环

根目录 [`experience_state.md`](../../experience_state.md) 只保留当前状态，采用覆盖更新而不是追加历史：

```text
current_version: 当前版本
last_review: 上轮 pass/fail/blocked + 一句结论
unresolved: 未解决问题；无则 none
next_goal: 下一步目标；未通过时必须是修复/重跑，不得是升版本
```

每轮结束更新状态：`pass` 才允许 `next_goal` 指向下一版本；`fail` 保留当前版本并指向修复；`blocked` 保留当前版本并写明外部阻塞。新会话先读本文和状态文件，再从 `next_goal` 继续，不重新猜测上轮结论。

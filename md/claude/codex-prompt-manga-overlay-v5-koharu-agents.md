# Codex 任务 v5：基于 Koharu 调研，分 Agent 落地几何约束优化

这份任务基于你自己产出的 `Koharu 图像识别链路研究` 报告。那份报告的分析和优先级排序质量很高，不需要重新论证，直接拿来作为本次执行计划的依据。**不要重新去读 Koharu 的源码或模型，本轮只是把报告里已经提炼出的轻量算法思路，用 Swift 原生实现到 AITRANS 现有链路里，不引入新模型、不移植 Koharu 的代码或权重。**

任务拆成 9 个 Agent 阶段，按顺序执行。**每完成一个 Agent，必须先构建、跑一次相关探针、确认验收标准通过，再进入下一个 Agent**。如果某个 Agent 卡住或者发现现有代码结构和报告描述不一致，停下来报告问题，不要跳过去硬做下一个 Agent，也不要为了"看起来完成了"而放宽验收标准。

## 贯穿所有 Agent 的硬性约束（每个阶段都要遵守，不是只读一次）

这些是 Koharu 报告"风险与边界"一节已经点出来的，本轮提到的每个 Agent 都必须遵守，违反任何一条都算这个阶段没做对：

1. **`test/1.ground_truth.json` 只能用来验证效果，不能参与生产环境的任何候选选择/合并/判定逻辑**。任何一个 Agent 如果发现"用真值能让数字更好看"，那是错误方向，不能采用。
2. **不允许为了提升相似度分数而强行做跨气泡合并**。气泡边界是硬约束，不是可以为了凑分数绕过的东西。
3. **轻量二值化/连通域分析容易把网点、速度线、角色轮廓当成文字**，任何用到这类算法的步骤，连通域必须同时满足"落在气泡内部"和"与 Vision OCR bbox 有重叠"两个条件才算有效文字区域，缺一不可。
4. **批量翻译（Agent 8）不能替代逐块翻译流程**，必须保留逐块 fallback 和详细诊断，只作为对照分支存在。
5. **气泡安全区/渲染碰撞检查改善的是"覆盖图好不好看、文字有没有越界"，不是"OCR 识别准不准"**。这两类指标在探针报告里必须分开记录，不能因为渲染变好看了就顺便把 OCR 准确率相关的字段也跟着改了口径。
6. 任何新增的汇总/统计数字，必须遵循之前已经定下的规则：从明细数组现场算出来，不能用单独维护、可能不同步的变量，且要有一致性校验（这是从上一轮"双框架对比数字自相矛盾"里学到的教训，不要再犯）。

## Agent 1（P0）：把气泡升级为主几何信号

这是优先级最高的一步，且不引入新模型。

### 目标

让"气泡"从一个孤立的 bbox 列表，变成贯穿后续所有处理的几何主信号：每个 OCR 识别结果都要归属到某个气泡 ID，归属不明确的要明确标记，不能含糊处理。

### 具体要求

1. 新增结构化数据（命名和具体字段可以按你的代码风格调整，但语义要覆盖到）：
   - 气泡候选：ID、bbox、（mask 这步可选，先用 bbox，不强求）、面积、置信度。
   - 文字区域：bbox、所属气泡 ID（可为空）、来源（整图 OCR / bubble-first / 后续 slice OCR）、置信度。
2. 每个 Vision OCR observation，通过 bbox 重叠面积或中心点投票的方式，判断它属于哪个气泡 ID。如果和任何气泡的重叠都不够（具体阈值你定），标记为"未归属气泡"，不要强行分配。
3. 合并逻辑改成：**只在同一气泡 ID 内部做合并，跨气泡禁止合并**，即使两个文字块在视觉上靠得很近，只要分属不同气泡 ID，也不能合并成一个块。
4. OCR crop（重新裁切再识别这一步）的裁切范围，要被限制在所属气泡的 bbox 内，不能扩张到相邻气泡的区域。
5. 探针报告新增字段：`bubbleID`、`bubbleAssignmentMethod`（说明是用重叠面积还是中心点投票判断的）、`crossBubbleMergeRejected`（记录有没有出现"本来想合并但因为跨气泡被拒绝"的情况，这本身是个有用的诊断信号）。

### 验收标准

- `totalBlocksDetected` 不应该毫无解释地大幅波动——如果变化很大，要说明是因为气泡归属让原来被错误合并/拆分的块变了，不是算法变得更激进或更保守导致的副作用。
- 重点检查这几个上一轮表现差的块有没有改善（不要求全部解决，但要看到方向性变化，如实报告）：
  - "GET PESULTE / SAMING CLUE TO SAVE THE / POOM BENG"（这一块和它下面相邻的"What are you even talking about"是不是因为气泡边界不清导致互相串扰）
  - "What Whet are / every you! / talking"
- 广告横幅、浏览器 UI 这些区域不能被气泡检测误判出气泡 ID——确认裁切逻辑仍然在生效，这些区域根本不应该进入气泡归属流程。

## Agent 2（P1）：长图 / 局部 tile OCR（slice OCR）

### 目标

对长宽比较大的截图，按竖向切片分别做 OCR，避免整页缩放导致小字丢失。

### 一个需要你先判断的问题

`test/1.png` 本身是手机单屏截图，长宽比未必能达到触发分片的阈值。请先确认这张图是否需要分片；如果不需要，**自己构造一张测试用的长图素材**（比如把 `test/1.png` 纵向拼接两三次，明确标注这是合成测试图，不是真实漫画内容，只用来验证分片机制本身能不能正常工作），不要因为现有素材不触发这个功能就跳过整个 Agent。如果手上有更合适的真实长截图素材，优先用真实素材。

### 具体要求

1. 长宽比超过一定阈值的图，按竖直方向切片，切片之间保留 15%~25% 的重叠。
2. 每片单独跑 Vision OCR。
3. 把每片识别到的 bbox 的 y 坐标还原回原图坐标系。
4. 对切片重叠区域产生的重复识别结果去重：可以结合 IoU、包含关系、文本相似度、以及 Agent 1 的气泡 ID 一起判断是不是同一块内容被识别了两次。
5. 探针新增字段：`sliceIndex`、`sliceOverlapDeduped`。

### 验收标准

- 用合成的长图测试样本，确认切片、坐标还原、去重这一整条链路能跑通，且没有出现"同一段文字被算成两个不同的块"这种去重失败的情况。
- 在 `test/1.png` 这张不需要分片的图上，确认这个新功能默认不触发、不影响现有结果。

## Agent 3（P1）：OCR crop 自适应扩张

### 目标

替换掉现在固定比例的裁切扩张逻辑，改成根据文字方向和字号自适应。

### 具体要求

1. 用文字块 bbox 的短边估算字号。
2. 横排文本：纵向（y）padding 应该大于横向（x）padding；竖排文本反过来。
3. 裁切范围必须被限制（clamp）在 Agent 1 确定的所属气泡 bbox 范围内。
4. 如果裁切收紧之后重新 OCR，结果反而丢失了原本在更宽裁切范围里能识别到的词，要有回退机制，退回到原来的裁切范围。
5. 探针新增字段：`cropPaddingX`、`cropPaddingY`、`cropClampedByBubble`、`cropCandidatePreservesRawWords`。

### 验收标准

- 对比固定比例裁切和自适应裁切在 `test/1.png` 上的识别结果差异，哪些块变好、哪些块变差，如实列出来，不要只报告变好的部分。
- 确认"丢词回退"机制至少在某个人为构造的场景下被触发过一次（比如故意把裁切收得过紧，确认系统能检测到丢词并回退），证明这个机制不是写了但没生效。

## Agent 4（P1）：气泡安全区（简化版，先用 bbox inset，不做 distance transform）

### 目标

给覆盖绘制提供一个比"直接画在 OCR bbox 上"更稳的安全区域。

### 具体要求

1. 这一步先做轻量版：对每个气泡 bbox 做 inset（横排文本短边 inset 大约 12%，竖排大约 20%，具体数值可以根据实际效果微调），不需要做距离变换（distance transform）这种更重的算法，报告里已经说明这是后续可以再加的方向，本轮不强求。
2. 如果一个气泡内只有一个文字块，安全区就是这个气泡的 inset 范围。
3. 如果一个气泡内有多个独立的文字块（比如因为换行被 Vision 拆成了多个 observation，但确认属于同一气泡），保留各自的位置范围，不要把它们粗暴合并成一个大安全区，避免几段译文抢同一块地方。
4. 探针新增字段：`safeLayoutRect`。

### 验收标准

- 找一个多块同气泡的真实案例（如果 `test/1.png` 上没有，构造一个测试场景），确认每块都有自己独立的安全区，没有出现互相覆盖的范围。

## Agent 5（P1）：离屏渲染碰撞检查 + 字号回退

### 目标

让覆盖绘制的译文不会画出气泡范围。

### 具体要求

1. 先把译文渲染到一个离屏的 sprite/mask 上，不直接画到最终图上。
2. 检查这个 sprite 里所有非透明像素，是否都落在 Agent 4 给出的安全区（或者气泡 bbox）范围内。
3. 如果越界，缩小字号重新渲染，重复这个过程直到不越界，或者达到一个最小字号阈值后改成换行/截断（具体策略你定，但不能无限循环）。
4. 透明像素不计入越界判断。

### 验收标准

- 找一个文字偏长、容易越界的真实块（比如之前的"SUGSESTION THE / OVERRULED AND IT WAS..."这种长句），确认这套机制能让它在合理字号下被限制在气泡范围内，而不是简单地溢出或者被截断得不知所云。

## Agent 6（P2）：轻量文字像素 mask（glyph mask）

### 目标

判断气泡内哪些像素是真正的文字笔画，而不是直接假设整个 bbox 范围都是文字。

### 具体要求

1. 在气泡 crop 内做灰度化。
2. 自适应阈值/局部阈值二值化（不需要引入 UNet 等模型，传统图像处理方法即可）。
3. 连通域分析，过滤掉明显过大（很可能是背景线条/分割线）和过小（噪声）的连通域。
4. **连通域必须同时满足"落在气泡内部"和"与 Vision OCR bbox 有重叠"才算有效文字区域**——这是前面"贯穿约束"里反复强调的那条，这一步是它最容易被违反的地方，请特别注意。
5. 对筛选后的 glyph 区域做小半径膨胀。
6. 探针新增字段：`glyphMaskPixelCount`。

### 验收标准

- 在 `test/1.png` 几个有背景纹理或者角色线条穿过气泡的区域，确认这套逻辑没有把背景线条误判成文字（如果发现误判，要报告并说明怎么调整阈值/连通域过滤条件解决的）。

## Agent 7（P2）：纯色气泡背景填充

### 目标

对大量白底/纯色气泡，用背景色直接填充比现在的半透明覆盖更干净。

### 具体要求

1. 对每个气泡，采样 Agent 6 得到的 glyph mask 之外的像素。
2. 用每个颜色通道的中位数（不是平均值）估计背景色。
3. 计算颜色标准差，低于某个阈值才认为是"纯色气泡"，可以直接填充。
4. 只填充 glyph mask 膨胀后的区域，不是整个 bbox 都重新填一遍。
5. 标准差高（说明背景有纹理/插画）的气泡，保留现有的半透明覆盖策略，不强行用这套新逻辑。
6. 探针新增字段：`backgroundFillApplied`、`backgroundColorStdDev`。

### 验收标准

- 挑几个明显是纯色白底气泡的块，确认背景填充被正确触发，视觉上比之前的半透明覆盖更干净。
- 挑一个背景有插画穿过的气泡，确认没有被错误地当成纯色气泡处理。

## Agent 8（P2）：批量 tagged 翻译对照（诊断分支，不替代主流程）

### 目标

测试"给模型更多上下文、用编号强约束输出顺序"这种方式，是否能改善翻译质量，但这只是一个对照实验，不能动现有主流程。

### 具体要求

1. 新增一个独立的诊断分支：把多个文字块格式化成带编号的形式（`[1]...`、`[2]...`），要求模型保留编号、不合并、不拆分、不解释，整体送一次翻译。
2. 解析返回结果时按编号 tag 拆回到各个块。
3. 记录 tag 缺失、重复、顺序错乱这几类解析失败情况。
4. 这个分支的结果只用来和现有逐块翻译流程做对比，**不能替换现有流程，现有逐块 fallback 和详细诊断必须完整保留**。

### 验收标准

- 对比批量翻译和逐块翻译在同样输入下的通过率差异，如实报告哪个更好、好多少，特别是如果发现批量翻译让本来就偏弱的模型输出格式直接崩掉（比如完全不按编号回复），要如实记录这个负面结果，不要因为这不是我们期望的结果就少报告。

## 本轮明确不做的事

- 不引入 Koharu 用到的任何专用检测/分割/inpainting 模型（`pp-doclayout-v3`、`comic-text-detector`、`speech-bubble-segmentation`、`lama-manga` 等），这些属于报告里的 P3，本轮不评估迁移成本，只做轻量几何算法层面的优化。
- 不更换当前的 OCR 引擎（Apple Vision）和翻译模型，这两者的取舍仍然取决于上一轮（v4）干净文本诊断的结果，本轮不重新讨论。
- 不涉及音频、ReplayKit、悬浮窗。
- Agent 8 的批量翻译分支不能成为默认/主流程。

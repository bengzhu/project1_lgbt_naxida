# AITRANS v1.47 -> v1.86 大更新说明

日期：2026-07-10

本次更新把 v1.46 之后分散的 40 个版本收束为一个可验收版本。主线从
native-lite 报告继续推进到 Koharu 四件套契约、真实 artifact 云端交接、
身份一致性闭环和方向感知 shadow OCR，并在 v1.86 扩展到 Apple Speech
本机识别诊断与音频 UI。

## 总览

- Koharu 路径从“只看 proxy 报告”推进到可验证的四件套 contract、Release
  archive、CI 注入和 App runtime 回执。
- TextBox、BubbleMask、SegmentMask 的结构证据增加像素 safe rect、包含率、
  sibling 分区/碰撞和 TextBox -> SegmentMask linkage。
- external TextBox shadow OCR 增加方向元数据、90/180/270 度旋转尝试、
  partial/unsupported ledger 和 coverage gate。
- CI 结果包增加来源、范围、identity、convergence、native-lite 和 handoff
  摘要，Agent C 可以拒绝旧 run、错 commit、错 archive 或只含本地证明的包。
- 新增 native draft artifact 工具，允许用现有探针结果生成非 active 四件套
  草稿，但始终保持 `contractExampleOnly=true`，不能冒充真实 detector 输出。
- 音频文件和实时麦克风识别新增运行摘要、翻译中状态、取消入口、置信度和
  失败原因；异步回调按 run UUID 隔离，取消/重试不会被旧任务覆盖。

## 版本明细

### v1.47-v1.50：四件套准入与 TextBox 候选

- v1.47：新增 Native Artifact Contract Dry-Run，固定检查 manifest、
  TextBoxes、BubbleMask、SegmentMask 四件套路径、字段和 forbidden source。
- v1.48：GitHub Actions 支持从 Release 下载、校验和注入真实 Koharu archive；
  validator 强化 schema、路径逃逸、bbox 和 source policy。
- v1.49：detector-lite 从每块单候选扩展为每 bubble 多候选池，保留候选来源、
  排序信号和拒绝原因。
- v1.50：增加 detector-lite 竖排 rotation shadow OCR，结果仍只进报告，不替换
  主 OCR 或翻译输入。

### v1.51-v1.58：Mask 几何和 linkage 闭环

- v1.51：BubbleMask instance-lite 从像素证据派生 safe rect。
- v1.52：SegmentMask refinement-lite 增加文字像素包含率 gate。
- v1.53：同气泡 sibling 使用独立 safe rect，避免共享区域互相覆盖。
- v1.54：增加 block-scoped sprite containment preview。
- v1.55：增加 sibling sprite collision preview 和冲突 ledger。
- v1.56：建立 TextBox -> SegmentMask linkage gate，弱关联不能静默晋级。
- v1.57：linkage 状态进入 bundle-lite 和 promotion gate。
- v1.58：linkage work item / gate 继续进入 convergence，最终收敛层可阻塞弱关联。

### v1.59-v1.69：真实 artifact runtime 与身份闭环

- v1.59：云端注入 artifact 后增加 App-readiness smoke，证明运行时确实读取
  active 四件套。
- v1.60：validator 增加 `generatedBy` source policy，禁止 proxy、example 或
  手写理想框伪装 active artifact。
- v1.61：TextBox 方向、旋转和 line polygon 元数据进入契约校验。
- v1.62：external TextBox orientation shadow ledger 记录可执行、partial 和
  unsupported 路径。
- v1.63：对接近 90/180/270 度的 TextBox 执行有上限的 rotation shadow OCR。
- v1.64：partial / unsupported orientation 进入 convergence gate；任意角度
  deskew 和 line polygon warp 不再被误判为 closed。
- v1.65：validator 和 CI manifest 输出方向元数据摘要。
- v1.66：validator / CI 输出 artifact identity 摘要，并把 coverage gate 与
  contract dry-run、identity 条件绑定。
- v1.67：App runtime 输出 source image 与四件套文件的 size/SHA256 回执。
- v1.68：新增 identity reconciliation report，把 App 回执映射到 CI manifest
  字段并逐文件核对。
- v1.69：external shadow OCR coverage gate 要求 executed、candidate、OCR
  执行和成功数量均有真实证据。

### v1.70-v1.80：CI 可追溯性和 source image 硬门槛

- v1.70：请求 artifact 注入时禁止 `probe_mode=skip`；必须跑 `ci-fast/full`。
- v1.71：补齐 convergence dependency span 和 handoff 文档。
- v1.72：CI manifest 直接汇总 contract dry-run 与 convergence gate。
- v1.73：记录真实 cloud `ci-fast` 证据并清理 Swift warning 噪音。
- v1.74：CI manifest 增加 native-lite report / gate 摘要和 gap roadmap。
- v1.75：拆分超长 manifest workflow step，修复 workflow 启动问题。
- v1.76：修正 changed-files 范围计算和 skip probe artifact 清洁度。
- v1.77：结果包增加 repository、event、ref、run URL、changed files 和哈希。
- v1.78：缺少 before commit 时定向 fetch，记录 scope diff method 和 fallback。
- v1.79：active manifest 必须声明合法且匹配 `test/1.png` 的 SHA256。
- v1.80：App readiness、identity receipt 和 reconciliation 同样强制 source
  image SHA 匹配，不能只依赖 Python validator。

### v1.81-v1.85：Release handoff 和 draft 工具

- v1.81：validator 可生成 Release upload / workflow dispatch handoff packet，
  并打包唯一目录、四个标准 JSON 的 archive。
- v1.82：新增 archive inspection；packet 输出带 `--repo` 的 upload、dispatch
  和 run list 命令。
- v1.83：handoff packet 包含 archive inspection proof 和预期 CI identity echo。
- v1.84：补齐 run watch/download、结果包检查、App runtime、reconciliation、
  shadow OCR 和 stale-run rejection 清单。
- v1.85：新增 `make-koharu-native-draft-artifacts.py`，从 probe report 生成非
  active contract 草稿，供字段对齐和 validator smoke 使用。

### v1.86：语音识别诊断和音频 UI

- 新增 `SpeechRecognitionRunMode`、`SpeechRecognitionRunSummary` 和
  `AudioRecognitionState.translating`。
- 文件音频与实时麦克风统一记录输入名、locale、本机识别要求、设备支持、
  耗时、词数、分段数、平均置信度、文本和失败原因。
- 增加识别取消入口；主动结束实时采集时，Speech cancel error 不再覆盖成功
  或用户取消状态。
- 异步授权、Speech 回调和翻译完成按 run UUID 校验，旧任务不能污染新任务。
- 识别摘要改为无嵌套轻量布局并使用 Dynamic Type 语义字号。

## 合并验收补强

- App bundle ID 统一为 `com.local.aitransform114`。
- Xcode `MARKETING_VERSION` 更新为 `1.86`；纯数字版本分支在 CI artifact 中规范化为 `v1.86`。
- `AITRANS CI Results` 不再硬编码 bundle ID，而是从构建出的 App
  `Info.plist` 读取，再用于 `simctl get_app_container`、launch 和 output 导出。
- `1.*` 版本分支进入 CI push trigger，保证 `1.86` 合并前能产生与 HEAD 完全
  一致的未加密结果包。
- 新增 `scripts/test-speech-recognition-contract.py`，检查状态枚举、摘要字段、
  run ID 隔离、UI 取消/翻译状态和动态 bundle ID 解析，并接入 CI static checks。

## 不变边界

- 漫画主流程仍是 whole-page + bubble-first 融合、deterministic 探针翻译和
  失败块显式覆盖；本次不改变模型、翻译 prompt 或质量判定。
- ground truth 继续只用于探针评估，不能参与候选、bbox、OCR、route 或 promotion。
- native-lite、draft 和 contract example 仍不是生产 active artifact。
- 未注入真实 Koharu 四件套时，external readiness 必须保持 blocked / missing，
  不能因 proxy 或草稿变为 ready。

## 验收范围

- 本地：diff、plist、JSON、YAML、Python contract/validator smoke 和 Swift parse。
- 云端：当前 `1.86` HEAD 的 `AITRANS CI Results` 必须完成静态检查、Xcode
  build、manifest、JUnit、日志和未加密 artifact；语音权限和真实麦克风质量仍需
  真机人工验证。
- 本次没有改变漫画 OCR/翻译质量主流程，因此不追加
  `metrics/version_history.csv` 漫画指标行。

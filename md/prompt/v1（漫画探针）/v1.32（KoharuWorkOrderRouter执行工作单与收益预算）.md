## 当前判断
v1.31 已新增 `koharuPipelineResolverReport`，把 SourceImage、ContentCrop、Vision OCR、Bubble/TextBox/SegmentMask proxy、OcrText、Translations、RenderedSprites proxy、FinalRender 和 ExternalArtifacts 组织成 Koharu-like `needs / produces` shadow DAG，并输出 `executionQueue` 与 `opPreviews`。

但 v1.31 的 resolver 仍主要回答“依赖在哪里阻塞”。下一步更需要回答“下一轮到底该做哪类工作、为什么、预算是多少、如何验收、哪些方向已经停止”。这更贴近 Koharu 的工程结构：DAG resolver 不只是画依赖图，还要把可执行 Engine / Op 排序，并把不可执行项明确阻塞在缺 artifact、模型地板或 stoplist 上。

因此 v1.32 不新增 OCR/LLM 算法，也不继续调 crop/line/deskew 参数。v1.32 要从 v1.31 resolver 的节点、block traces、execution queue 和 op previews 派生一个更稳定的 “WorkOrder Router” 报告：

```text
Koharu Pipeline Resolver
  -> WorkOrder Router
  -> per-work-order priority / budget / gates / affected blocks
  -> next Agent B / Agent C 可执行验收清单
```

核心目标是让后续 Koharu 复刻不再散乱地加报告，而是能根据 AITRANS 探针证据稳定路由：

- OCR 输入质量问题是否已经证明本地 crop/line/deskew stoplist，需要真实 TextBoxes。
- 气泡归属 / 分割问题是否需要真实 BubbleMask。
- 清字 / glyph coverage / render mask 问题是否需要真实 SegmentMask 或仅保持 render lock。
- 翻译失败是否属于模型地板，不应继续归因给几何。
- 覆盖渲染是否已锁定，不应误当 OCR 瓶颈。
- 缺 `test/koharu_artifacts/` 时，哪些工作单只能记录 handoff，不能伪造 detector 输出。

本轮仍是 report-only / diagnostic-only。不得改变主 OCR、bubble-first 融合、post-fusion cleanup、翻译 prompt、模型选择、质量判定、覆盖渲染、`blockPassed`、失败分类、`safeLayoutRect`、`glyphMaskFillRects`、背景填充行为、输出 PNG、`configuration.currentBlockSource` 或 `metrics/version_history.csv`。

1. 以 `koharuPipelineResolverReport` 为上游，结合 convergence、translation floor、render lock、TextBox / BubbleMask / SegmentMask scoreboards、external artifact gate 和最终 blocks，输出下一步 work orders。

4. 输出 report-level budget ledger：ci-fast 可验收项、full-only 项、external-artifact-only 项、must-not-run-local-tuning 项。
5. 联动 `koharuArtifactConvergenceReport.referenceReports`、`workItemLedger` 或 `gateLedger`，证明 v1.32 是 v1.31 resolver 的下游收束。

- `WO-v132-request-real-segmentmask`：目标 SegmentMask；块来源应包含 `segmentMaskProxyCoverageScoreboardReport.needsRealSegmentMaskBlocks`、weak segment、cleanup / mask coverage 风险。
- `WO-v132-keep-render-lock`：目标 RenderedSprites / FinalRender；若 v1.30 没有 render issue，应 `closedReportOnly`，说明不要把渲染当 OCR 瓶颈。

- `WO-v132-external-artifact-package-handoff`：目标 `test/koharu_artifacts/` 四件套；缺 artifact 时只记录 handoff，不创建、不复制、不伪造 active artifact。
- `WO-v132-manual-review-unclassified`：只收未被上述分类解释的失败块，不能吞掉主要问题。

路由优先级建议：

1. 如果 v1.30 render lock 有真实 render issue，先路由到 `WO-v132-keep-render-lock`。
2. 如果失败是 `modelOutputFailure` / `translationLanguageQualityFailure` 或 v1.29 标记模型地板，路由到 `WO-v132-translation-model-floor-handoff`，不要归因给 OCR geometry。
3. 如果 block 在 stoplist / crop / line / deskew 已证伪列表，路由到 `WO-v132-request-real-textboxes` 和 `WO-v132-stop-local-crop-line-deskew`。
4. 如果 BubbleMask scoreboard 标记 assignment conflict / split risk / needs real mask，路由到 `WO-v132-request-real-bubblemask`。
5. 如果 SegmentMask scoreboard 标记 weak segment / needs real segment / cleanup risk，路由到 `WO-v132-request-real-segmentmask`。
6. 如果 external artifact 缺失但该块需要真实 TextBoxes / BubbleMask / SegmentMask，`requiresExternalArtifact = true` 且 `recommendedNextAction = collectRealKoharuArtifact`。
7. 如果块已通过且 render locked，路由到 `WO-v132-close-resolver-ledger` 或 `WO-v132-keep-render-lock`，不要制造新任务。
8. 只在无法分类时使用 `WO-v132-manual-review-unclassified`。

ground truth 只能放进 `evaluationSignals`，例如 `ocrSimilarityForEvaluation`、`groundTruthMatch`、`bestGroundTruthType`。不得用真值决定 `primaryWorkOrderID`、priority、budgetClass 或 nextAction。

## 当前判断
v1.22 到 v1.30 已经补齐一批 Koharu 对齐报告：

- `koharuArtifactDAGReport`：阶段 DAG、dependency edges、first blocking stage。
- `koharuStageGapReplicationReport`：canonical stage 差距、work package、promotion gate。
- `koharuNativeReplicationScoreboardReport`：AITRANS native/proxy scorecard。
- `nativeTextBoxProxyLedgerReport`、`bubbleMaskAssignmentSplitScoreboardReport`、`segmentMaskProxyCoverageScoreboardReport`：TextBoxes / BubbleMask / SegmentMask proxy 质量账本。
- `koharuArtifactConvergenceReport`：canonical artifact 收敛矩阵和 work item closure ledger。
- `translationModelFloorComparisonReport`：clean text / strict prompt 模型地板对照。
- `koharuRenderRegressionLockReport`：RenderedSprites / FinalRender 回归锁。

但这些报告仍偏“阶段汇总”和“账本聚合”。Koharu 的核心算法结构不是单个报告，而是：

```text
EngineInfo declares needs / produces
  -> DAG resolver sorts executable engines
  -> each engine reads upstream artifacts
  -> run() returns ops
  -> ProjectSession applies ops
  -> downstream engines consume produced artifacts
```

AITRANS 当前还没有一个 report-only 的 “resolver 影子层” 来回答这些问题：

1. 当前每个 Koharu-like stage 的 `needs` 是否满足，缺什么 artifact。
2. 哪些 stage 可以在本轮 AITRANS 探针内执行，哪些只是 proxy，哪些必须等真实 external artifact。
3. 一个 block 的端到端失败，沿 DAG 依赖传播后，第一阻塞节点和下游受影响节点是什么。
4. 下一轮应执行哪个 work package，是 ci-fast 可跑、full 才能跑，还是必须等待 `test/koharu_artifacts/`。
5. 哪些本地试参已经被 stoplist 关闭，不能继续消耗在 crop / line / deskew。

因此 v1.31 不再新增一个孤立质量评分板，而是新增 Koharu Pipeline Resolver 的影子账本：把 v1.22-v1.30 的阶段证据组织成“可执行性、依赖阻塞传播、调度队列、op preview”的算法结构框架。

本轮仍是 report-only / diagnostic-only。不得改变主 OCR、bubble-first 融合、post-fusion cleanup、翻译 prompt、模型选择、质量判定、覆盖渲染、`blockPassed`、失败分类、`safeLayoutRect`、`glyphMaskFillRects`、背景填充行为、输出 PNG 或 `configuration.currentBlockSource`。

## 本轮目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.31-koharu-pipeline-resolver
```

新增一个 AITRANS 自有探针驱动的 Koharu Pipeline Resolver 影子报告：

```text
koharuPipelineResolverReport
```

报告目标：

1. 用 Koharu 的 `needs / produces / executable / blocked / downstream impact` 思路，组织 AITRANS 当前所有探针证据。
2. 输出 stage node DAG：SourceImage、ContentCrop、VisionOCRCandidates、BubbleCandidates、BubbleMaskProxy、TextBoxProxy、SegmentMaskProxy、OcrText、FusionCleanup、Translations、GlyphEraseProxy、RenderedSpritesProxy、FinalRender、ExternalArtifacts。
3. 输出 per-block resolver trace：每块经过哪些节点、第一阻塞节点、阻塞原因、下游受影响节点、下一步可执行 work item。
4. 输出 execution queue / op preview：只描述“如果 resolver 调度，下一步应执行什么 report-only work package”，不真正修改主流程。
5. 把 v1.31 的 resolver report 联动进 `koharuArtifactConvergenceReport.referenceReports`、`workItemLedger` 或 `gateLedger`，证明这是 Koharu algorithm structure 的下一层收束，而不是重复 v1.28。
6. 继续用 AITRANS 自己的探针输出分析 OCR 准确率、气泡归属 / 分割、翻译失败分类、覆盖渲染和结构瓶颈；ground truth 只能进入 evaluation signals，不能参与调度、候选选择或 next action。

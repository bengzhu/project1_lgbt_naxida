## 核心目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.16-ci-probe-fastpath
```

完成云端 CI 分层加速和探针快模式：

1. 消除 CI 中重复 simulator build。
2. 增加 `ci-fast` 漫画探针模式，用于日常 codeb PR 云端验证。
3. 保留 `full` 漫画探针模式，用于人工 workflow_dispatch 或阶段回归。
4. `ci-fast` 必须仍使用 Local GGUF、真实 simulator app、真实 `test/1.png`、deterministic 解码和本轮沙盒输出，不能退化成 Mock、旧 output 或纯 JSON smoke。
5. `ci-fast` 跳过高成本 shadow-only / 对照层，但保留主 OCR、主融合、主逐块翻译、失败块绘制、核心报告、clean text diagnostic、Koharu readiness gate 和 external TextBoxes shadow OCR gate。
6. CI manifest 和 `manga_probe_progress.json` 必须记录 probe mode、耗时、跳过的诊断层、是否使用 fast path、输出文件清单和每个关键阶段耗时，方便 Agent C 判断“快”不是“少验证到不可验收”。

## 实现要求
### 1. CI：消除重复构建
当前 workflow 有两次构建：

```text
Xcode build
Build simulator app for manga probe
```

Agent B 应改成单次可复用构建：

- 保留 `.xcresult`、`xcodebuild.log` 和 JUnit / manifest 输出。
- 单次 build 产出的 Debug simulator app 必须能被后续 probe 安装。
- 如果保留两个 step 名称，第二个 step 只能定位和校验已构建 app，不应再次完整 `xcodebuild build`。
- `ci-artifact-manifest.json` 必须能看出：
  - `xcodeBuildOutcome`
  - `simulatorBuildOutcome` 或新的等价字段
  - 是否复用了 build app，例如 `simulatorAppReusedFromXcodeBuild = true`
  - app path，例如 `simulatorAppPath`

建议优先使用 `-configuration Debug -destination 'generic/platform=iOS Simulator' -resultBundlePath ... CODE_SIGNING_ALLOWED=NO build` 作为单次 build，既保留 result bundle，又产出 Debug simulator app。

### 2. CI：增加分层探针模式
在 `.github/workflows/ci-results.yml` 增加模式输入和默认策略：

- `workflow_dispatch` 支持 `probe_mode`：
  - `ci-fast`
  - `full`
  - `skip`
- `push` 到 `codeb/**` 默认使用 `ci-fast`。
- `push` 到 `smalldata_test` 默认使用 `ci-fast`，除非人工 dispatch 选择 `full`。
- `skip` 只允许用于文档-only 或人工明确跳过；manifest 必须写明 `probeSkippedReason`，不能伪装成通过探针。

建议 manifest 新增字段：

```json
{
  "probeMode": "ci-fast",
  "probeFastPathEnabled": true,
  "probeSkippedReason": null,
  "probeTimeoutSeconds": 1800,
  "probeStallTimeoutSeconds": 300,
  "probeDurationSeconds": 0,
  "probeOutputRequiredFiles": [],
  "probeOutputRetainedFiles": []
}
```

### 3. App DEBUG：探针参数化
在 DEBUG 启动路径读取环境变量、启动参数或 UserDefaults：

```text
AITRANS_MANGA_PROBE_MODE=ci-fast
AITRANS_MANGA_PROBE_MODE=full
AITRANS_MANGA_PROBE_MODE=skip
```

默认开发页按钮仍走 `full`，避免本地人工调试时丢诊断层。

建议新增一个轻量配置结构，例如：

```swift
enum MangaOverlayProbeRunMode: String, Codable {
    case full
    case ciFast = "ci-fast"
}

struct MangaOverlayProbeRunOptions {
    var mode: MangaOverlayProbeRunMode
    var runLexiconComparison: Bool
    var runVisionAPIComparison: Bool
    var runSyntheticSliceOCR: Bool
    var runPreprocessingCrop: Bool
    var runModelCorrection: Bool
    var runDeterministicCorrectionTranslation: Bool
    var runTaggedBatchTranslation: Bool
    var runCropExperiment: Bool
    var runLineCropExperiment: Bool
    var renderDiagnosticPNGs: Bool
    var renderContactSheet: Bool
    var runCleanTextDiagnostic: Bool
    var runDeterministicDecodingCheck: Bool
}
```

具体形态可按现有代码最小侵入实现，但 report / progress / manifest 必须能看见模式和跳过项。

### 4. `ci-fast` 必须保留的链路
`ci-fast` 不是 Mock smoke。它至少要跑：

```text
test/1.png
  -> 输出目录清理
  -> whole-page 0/90/180/270 Vision OCR
  -> bubble-first OCR
  -> fusedWholePageBubble 融合和 post-fusion cleanup
  -> deterministic OCR correction 字段可保留现有确定性规则，但不得调用高成本模型纠错分支
  -> 逐块 Local GGUF deterministic 翻译
  -> translationDecisionTrace / translationFailureDetail
  -> BubbleMask 基础 safe layout / render diagnostics
  -> externalArtifactReadinessReport
  -> externalTextBoxShadowOCRReport gate
  -> 核心 PNG：debug boxes + translated overlay
  -> 1_ocr_probe_text.txt
  -> clean_text_diagnostic.json
  -> probe_report.json
```

`ci-fast` 必须继续满足：

- `engineUsed = Local GGUF`
- `decodingMode = deterministic`
- `decodingSeed = 42`
- `totalBlocksDetected > 0`
- `blocks` 非空
- 失败块留在 `blocks` 明细中。
- `blockPassed = false` 的块仍有 `failureReasons`、`translationDecisionTrace`、`translationFailureDetail`。
- 覆盖图仍显示失败块，不静默跳过。
- 输出目录仍每轮清理。
- 低置信真值仍可拒绝为 `groundTruthMatch = "unmatched"`。
- dialogue / decorative 仍分开统计。

### 5. `ci-fast` 建议跳过的高成本层
为了提速，`ci-fast` 可以跳过这些 shadow-only 或对照层：

- `lexiconComparison`
- `visionAPIComparison`
- `syntheticSliceOCR`
- 模型 OCR 纠错后处理 `correctMangaProbeBlock`
- 确定性纠错文本再翻译对照
- `taggedBatchTranslationComparison`
- `cropExperimentReport`
- `textBoxPlanFailureReport`
- `lineTextBoxPlanReport`
- `lineCropExperimentReport`
- 诊断 PNG：`1_deterministic_correction_overlay.png`、`1_deterministic_translation_overlay.png`、`1_block_crops.png`、`1_preprocessed_content.png`、`1_probe_contact_sheet.png`
- `deterministicDecodingCheck`

跳过时不要让报告字段像“成功执行但为空”。应明确写：

```text
skippedInProbeMode = ci-fast
skipReason = ciFastPerformanceBudget
```

如果现有 Codable 模型不方便给每个 report 加 skip 对象，可以在 `configuration` 或新增 `probeRuntime` / `diagnosticExecution` 顶层字段集中列出：

```json
{
  "probeRunMode": "ci-fast",
  "skippedDiagnostics": [
    "lexiconComparison",
    "visionAPIComparison",
    "syntheticSliceOCR",
    "cropExperimentReport",
    "lineCropExperimentReport",
    "taggedBatchTranslationComparison",
    "deterministicDecodingCheck",
    "diagnosticPNGs"
  ]
}
```

### 6. external artifact gate 不能被快模式绕过
即使 `ci-fast` 跳过内部 crop / line shadow 实验，也必须继续运行：

- `externalArtifactReadinessReport`
- `externalTextBoxShadowOCRReport`

原因：

- v1.13-v1.15 已经把 Koharu artifact 接入作为下一阶段边界。
- 默认缺 active artifact 时，这两个 report 很轻，应该输出 `manifestMissing` / `executed = false`。
- 如果未来真实 `test/koharu_artifacts/` 到位，`ci-fast` 也必须能证明 `readyForShadowOCR` 和 `executed = true`，不能因为快模式跳过核心 Koharu gate。

### 8. 等待和停滞策略提速
`ci-fast` 建议：

- `PROBE_TIMEOUT_SECONDS = 1800`

`full` 可继续：

- `PROBE_TIMEOUT_SECONDS = 3600`
- `PROBE_STALL_TIMEOUT_SECONDS = 600`

不要为了快而吞掉失败。超时或停滞时仍必须复制已有 output、保留 `manga-probe.log`、`app-console.log`、`manga_probe_progress.json` 和失败摘要。

如果 B 不想大改 report schema，至少保证 `manga_probe_progress.json` 和 manifest 有这些字段；`probe_report.json.configuration` 也应有 `probeRunMode` 或等价字段。

## 风险和注意事项
- 最大风险是“快模式”削掉了 Agent C 验收所需证据。保留 Local GGUF、主 OCR / 融合 / 翻译、核心 PNG、clean text、external gate 是硬要求。
- 如果跳过内部 crop / line shadow 后某些 report 构造依赖 nil 崩溃，应优先让 report 接受 nil / skipped 状态，不要为了编译通过而伪造空成功。
- 如果单次 build 难以同时生成 `.xcresult` 和可安装 Debug app，先保守保留一处真正 build，另一处只做 app 查找和校验；不要让两个 step 都重新 build。
- 如果 `workflow_dispatch` input 在 push 事件下为空，要明确 fallback 到 `ci-fast`。
- 不要因为 CI 提速就删除失败时的日志收集。失败时的 artifact 反而更重要。
- 不要把本轮提速写成 OCR 准确率提升；除非 full probe 刷新并追加长期指标，否则只记录流程性能和验证制度变化。

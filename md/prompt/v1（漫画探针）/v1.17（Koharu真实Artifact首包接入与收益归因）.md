## 背景判断
Koharu 的价值在于结构化 artifact DAG：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> FontPredictions
  -> Translations
  -> Inpainted
  -> RenderedSprites
  -> FinalRender
```

AITRANS 已经把缺 artifact 的阻塞路径、contract examples、validator、App readiness gate、external TextBoxes shadow OCR report、CI manifest 摘要和 `ci-fast` 云端运行路径补齐。现在的关键不是继续模拟 Koharu，而是验证真实 Koharu / 外部 detector 输出能否在 AITRANS 的固定 `test/1.png` 上提供更好的 OCR crop 证据。

v1.17 的重点是“首包验收和收益归因”，不是“把 external OCR 切主流程”。即使 external candidate 明显更好，本轮仍只做 shadow-only report；是否晋级主流程必须等后续版本单独决策。

## 实现提示
优先级按路径不同处理。

### 路径 A 实现重点
- 先保护来源真实性，再看 validator。
- 优先修 artifact 转换问题，而不是修 App gate。
- App 只接受 bundle 内 `test/koharu_artifacts/` active 目录。
- 如果 active 文件进入 bundle 后 App readiness 仍失败，优先对齐 Swift parser 与 Python validator 的判定差异，不能让二者出现“validator ready、App missing”而没有解释。
- 如果 Swift parser 与 validator 对同一 artifact verdict 不一致，必须在 `ci-failure-summary.md` 或文档里写清差异字段并修到一致。
- 如果 `externalTextBoxShadowOCRReport.executed = true` 但 `candidateCount = 0`，这不是有效首包收益验证；必须说明是没有匹配 TextBox、IoU/中心点不足、bubble mismatch 还是面积比例问题。
- 如果 `candidateCount > 0` 但 `ocrSucceededCount = 0`，优先看 crop bbox、padding、Vision local OCR 空输出和 `1_ocr_probe_text.txt`。
- 如果 `betterThanControlCount > 0` 但 `wouldPromoteByExistingGateBlocks = []`，必须按 blockers 归因，不要直接放宽 gate。

### 路径 B 实现重点
- 保持代码不动或只改文档。
- 不要把 v1.15 已经足够清楚的 schema 长篇复制到多个文件。
- 输出应该帮助 Koharu 侧交付可验收首包，而不是继续描述 AITRANS 已知缺失。

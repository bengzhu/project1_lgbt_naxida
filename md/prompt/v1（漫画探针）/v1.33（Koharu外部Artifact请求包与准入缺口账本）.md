## 当前判断
v1.31 新增了 Koharu Pipeline Resolver 影子 DAG，v1.32 新增了 WorkOrder Router，把下一步工作路由到稳定 work orders。v1.32 已明确：继续本地 crop / line / deskew 调参应进入 stoplist；真实 TextBoxes / BubbleMask / SegmentMask 缺失时，不能用 Vision OCR、pre-crop plan、line plan、BubbleMask proxy、SegmentMask proxy、ground truth 或手写框伪造成 active artifact。

因此 v1.33 不应该再新增一个重复评分板，也不应该尝试提升 OCR 指标。v1.33 要执行 v1.32 的外部 artifact handoff 工作单：把 AITRANS 自己的探针证据、router work orders、external readiness gate 和现有 contract，整理成一个可审计的 “Koharu 外部 Artifact 请求包 / 准入缺口账本”。

该请求包的价值：

- 告诉 Koharu / 外部 detector 侧必须交付哪些文件、字段、坐标系和禁止来源。
- 告诉 Agent C 云端结果包应如何判断“仍缺 artifact”还是“artifact 已 ready”。
- 告诉后续 Agent B：缺 artifact 前只允许保持 report-only 阻塞，不许继续本地 OCR crop / line / deskew 试参。
- 当未来 `test/koharu_artifacts/` 到位时，同一 report 可以从 `blockedMissingArtifact` 切到 `readyForExternalShadowOCR`，并与 `externalTextBoxShadowOCRReport` 对齐。

本轮仍是 report-only / diagnostic-only。不得改变主 OCR、bubble-first 融合、post-fusion cleanup、翻译 prompt、模型选择、质量判定、覆盖渲染、`blockPassed`、失败分类、`safeLayoutRect`、`glyphMaskFillRects`、背景填充行为、输出 PNG、`configuration.currentBlockSource` 或 `metrics/version_history.csv`。


报告目标：

1. 以 `koharuWorkOrderRouterReport` 为上游，结合 `externalArtifactReadinessReport`、`externalTextBoxShadowOCRReport`、TextBox / BubbleMask / SegmentMask scoreboards、render lock、translation floor、convergence 和最终 blocks，输出真实 external artifact 交付需求。

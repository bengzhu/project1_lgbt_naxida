## 当前判断
v1.35 已新增 `koharuBubbleIndexShadowLedgerReport`，把现有 BubbleMask proxy、归属修正、split candidate、safeLayoutRect、same-bubble sibling 和 render lock 收成 Koharu `BubbleIndex` 影子账本。它解决的是“当前矩形 / mask-safe / sibling 证据能否被审计”的问题。

但 Koharu `BubbleIndex` 的核心算法不只是 ledger：它从气泡 instance ID mask 中计算 distance transform，找离边缘足够远的 safe pixels，再求可排版的安全区域。AITRANS 目前的 `makeApproximateBubbleMaskRuntime` 仍用 rounded-rect proxy，并把 safe rect 简化为 bbox inset；v1.35 没有独立记录 safe pixel、distance field、最大安全矩形、centroid fallback 或当前 safeLayoutRect 与 distance-field safe rect 的差距。

v1.36 应新增一个 report-only 的 `Koharu DistanceField SafeArea Shadow Report`：

- 继续只使用 AITRANS 自己已有的 rounded-rect BubbleMask proxy 和探针证据，不需要真实 Koharu artifact。
- 在 proxy ID mask 上复刻 Koharu 的 distance-field 安全区思想，输出每个 bubble 的 safe pixel / max distance / centroid / maximum safe rect 账本。
- 对每个 block 比较当前 `safeLayoutRect`、v1.35 shadow safe rect 和 distance-field safe rect 的 IoU、面积变化、是否覆盖 render sprite、是否会影响失败块 fallback 覆盖。
- 对 same-bubble sibling 组评估当前分区与 distance-field safe area 的冲突，不应用到主覆盖图。
- 与 convergence 联动，新增 v1.36 reference report、work item 和 gate，证明 DistanceField 安全区复刻已执行。

本轮是 Koharu renderer / BubbleIndex 的算法复刻评估，不是 OCR 提升版本。报告可以帮助后续决定是否值得把 distance-field safe rect 升级为主渲染候选；本轮只给证据，不改变行为。

## Distance-field 算法要求
实现位置由 Agent B 按代码结构决定：

- 如果需要访问当前 rounded-rect proxy ID mask，优先在 `MangaOverlayProbeService` 内靠近 `makeApproximateBubbleMaskRuntime` 实现，或把紧凑的 distance-field summary 作为报告输入传给 store。
- 不要把大型像素数组写入 JSON；只写 summary、bbox、计数和每块比较结果。
- 注意 Swift type-check 成本，避免一个大表达式堆完所有 ledger。把 bubble / block / sibling / gate 构造拆成小 helper。

每个 bubble 的 shadow 计算建议：

1. 只在 bubble bbox 内处理该 bubble ID 的 proxy mask 像素，避免整图 O(width * height * bubbleCount)。
2. 计算 `maskPixelCount` 和 `edgePixelCount`。edge 定义为相邻 4 或 8 邻域存在非本 bubble ID / 越界。
3. 计算距离到边界的近似 distance field。可以用两遍 chamfer distance 或 BFS；权重和单位要写进报告，例如 `distanceMetric = "twoPassChamfer8Neighbor"`。
4. 计算：
   - `maxDistance`
   - `maxDistancePoint`
   - `centroidPoint`
   - `centroidDistance`
   - `safeThresholdPx`
   - `safePixelCount`
   - `safePixelCoverageRatio`
   - `safePixelBBox`
5. 基于 safe pixel 求一个可解释的 `maximumSafeRect`。建议用每行 histogram 最大矩形算法；若实现复杂，可先求 safe pixel bbox，并明确 `maximumSafeRectAlgorithm = "safePixelBBoxFallback"`，但 gate 要标为 warning。
6. 若没有足够 safe pixels，fallback 到 v1.35 / 当前 `maskSafeRect` 或 bbox inset，并写 `fallbackReason`，但不得改主 `safeLayoutRect`。

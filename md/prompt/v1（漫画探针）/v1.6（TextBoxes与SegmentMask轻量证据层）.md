# AITRANS Agent B / Koharu 提示词：v1.6（TextBoxes 与 SegmentMask 轻量证据层）

## 版本号
v1.6（漫画探针 / TextBoxes 与 SegmentMask 轻量证据层）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入。v1.1 完成 post-fusion 重复/碎片清理与气泡分割审计。v1.2 接入 TextRegion crop OCR 候选层。v1.3 新增 `bubbleSubRegionReport` 和 subregion clamp。v1.4 新增轻量 `bubbleMaskReport`、mask-safe layout、crop mask coverage 和渲染 mask collision 诊断。v1.5 新增 BubbleMask 归属修正报告和保守 split candidate，并只在强护栏下用于 TextRegion crop clamp。

v1.5 的结果说明：几何候选更清楚了，但 TextRegion crop 仍是 `13 regions / 10 succeeded / 0 adopted / 13 rejected`，主要拒绝原因仍包括 `rawWordsLost`、`emptyCropText`、`wordCountRegression`、`sameAsFusedText`、`insufficientQualityGain`、`introducedLikelyOCRError`。这说明下一步不应放宽采用护栏，也不应继续只调 bubble bbox；应向 Koharu 的结构化中间层继续靠拢：补上可审计的 `TextBoxes` 和轻量 `SegmentMask` 证据层，让 OCR crop 的输入区域、文字像素、气泡 mask、glyph mask 和拒绝原因能闭环解释。

本轮是 v1.6：不引入新模型、不替换主流程、不用真值选候选；只把现有 Vision OCR observations、fused block bbox、bubble/split/corrected mask、glyph mask 和 crop 结果组织成更接近 Koharu 的 TextBoxes / SegmentMask 中间产物，并用报告证明哪些 crop 失败是“裁切框不准”、哪些是“Vision 在局部 crop 上更差”、哪些是“glyph/segment 证据不足”。

Koharu 的关键不是“把 OCR 后的字符串再修一遍”，而是让 `TextBoxes`、`SegmentMask`、`BubbleMask` 这些结构中间产物约束 OCR、清字、排版和渲染。AITRANS 现在已有近似 BubbleMask 和 glyph mask，但还没有把它们以 TextBoxes / SegmentMask 的形式独立汇总，也没有把 crop 失败归因到“文字框证据不足”或“文字像素 mask 不可信”。

## 问题定义
当前几何诊断仍有四个缺口：

1. TextRegion crop 只记录每块 crop 的结果和拒绝原因，但没有独立的 TextBox 候选报告说明“为什么选这个框、它来自哪些证据、和 glyph/mask 是否一致”。
2. `glyphMaskRect` 和 `glyphMaskFillRects` 已存在于 block 字段，但没有聚合成 SegmentMask 诊断，也没有统计其与 TextBox、bubble mask、safe rect 的关系。
3. crop 失败类型还不够结构化：`rawWordsLost`、`emptyCropText`、`introducedLikelyOCRError` 只是结果，不能直接区分是框不准、局部 Vision OCR 退化、segment 证据不足，还是近似 mask 错误。
4. Koharu 路线的 TextBoxes / SegmentMask / BubbleMask artifact 关系还没有在报告里形成可读 DAG，后续 Agent 很难判断下一步该修 TextBox、修 SegmentMask、修 bubble mask，还是换 OCR/翻译模型。

## 目标
实现一个轻量、可审计、可回退、ground-truth-free 的 `TextBoxes + SegmentMask` 证据层：

1. 新增 `textBoxCandidateReport` 或等价结构，逐块记录 TextBox 候选的来源、bbox、orientation、padding、bubble/split/corrected clamp、glyph overlap、bubble mask coverage、证据评分、是否可用于 crop、拒绝原因和风险 flags。
2. 新增 `segmentMaskReport` 或等价结构，把现有 glyph mask 聚合成轻量 SegmentMask 诊断：每块 glyph pixel 数、glyph rect、fill rect 数、与 TextBox 的重叠、与 bubble mask 的重叠、是否越出气泡、安全性、清字可用性、拒绝原因。
3. 在 `textRegionCropReport` 中补充 TextBox / SegmentMask 关联字段，至少能从每个 crop diagnostic 追溯到所用 TextBox ID、SegmentMask 质量、是否因为 segment 证据不足而只做诊断。
4. 增加 crop failure attribution 汇总，把每个拒绝块归入更明确类别，例如 `textBoxTooTight`、`textBoxTooWide`、`localVisionRegression`、`segmentMaskWeak`、`bubbleMaskConflict`、`sameAsFusedText`、`emptyLocalOCR`、`rawWordsLost`。
5. 不放宽 TextRegion crop 采用护栏。只有在现有护栏已通过、且 TextBox/SegmentMask 证据也通过时，才允许采用 crop；否则继续回退 fused 文本。
6. `1_ocr_probe_text.txt` 必须输出每块 TextBox 候选摘要、SegmentMask 摘要、crop failure attribution 和最终是否影响主输入。
7. 如实现成本可控，在 `1_probe_contact_sheet.png` 或 `1_bubble_debug.png` 中增加轻量可视化：TextBox 候选边框、glyph/segment rect、bubble mask safe rect 三者用不同颜色标出。若本轮不画图，最终回复必须说明只输出 JSON/TXT 证据。
8. 保持失败块报告和覆盖绘制规则不变：失败块必须在 `blocks` 明细中，覆盖图必须显示 `翻译失败 + OCR 原文`。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于 TextBox 选择、SegmentMask 评分、crop 采用、候选排序或回退。
- 不要放宽 TextRegion crop 采用规则来制造 `adoptedCount > 0`。
- 不要把 deterministic correction 纳入 `finalTextUsedForTranslation` 主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要为了提高 OCR 相似度跨气泡合并。
- 不要把轻量 SegmentMask 当作真实模型分割结果；必须继续标注它是传统图像处理近似。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 TextBox/SegmentMask 的诊断收益说成 OCR 准确率提升，除非真实探针数字证明。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严。

## 实现步骤
### 1. 先做基线核查
实现前从当前 `output/probe_report.json` 和 `output/1_ocr_probe_text.txt` 列出：

- 13 个块的 `index`、`bubbleID`、`bbox`、`safeLayoutSource`、`glyphMaskPixelCount`、`glyphMaskRect`、`textRegionClampSource`、`textRegionCropText`、`textRegionRejectionReasons`、`rawWordPreservationRatio`、`cropMaskCoverageRatio`、`failureCategory`。
- `textRegionCropReport.mainRejectionReasons`。
- `bubbleAssignmentCorrectionReport.recommendedCorrectionBlocks`、`appliedToCropClampBlocks`、`rejectedCorrectionBlocks`。
- `bubbleSplitCandidateReport.candidateCount`、`clampEligibleCount`、`appliedToCropClampBlocks`。
- `bubbleMaskReport.inconsistentBubbleAssignmentBlocks`、`renderMaskOverflowBlocks`、`bboxFallbackBlocks`。

把观察写进最终回复。不要只看覆盖图猜原因。

### 2. 新增 TextBox candidate 报告模型
在 `TranscriptModels.swift` 新增轻量 Codable 结构。命名可调整，但报告必须表达以下字段：

```swift
struct MangaOverlayTextBoxCandidateDiagnostic: Equatable, Codable, Sendable {
    var id: Int
    var blockIndex: Int
    var source: String
    var bbox: [Double]
    var seedBBox: [Double]
    var orientationHint: String
    var bubbleID: Int?
    var correctedBubbleID: Int?
    var splitCandidateID: Int?
    var clampSource: String
    var paddingX: Double
    var paddingY: Double
    var bubbleMaskCoverageRatio: Double?
    var glyphOverlapRatio: Double?
    var safeRectOverlapRatio: Double?
    var evidenceScore: Double
    var eligibleForCrop: Bool
    var usedForTextRegionCrop: Bool
    var rejectionReasons: [String]
    var riskFlags: [String]
    var notes: [String]
}

struct MangaOverlayTextBoxCandidateReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var evaluatedBlockCount: Int
    var candidateCount: Int
    var cropEligibleCount: Int
    var usedForCropBlocks: [Int]
    var rejectedBlocks: [Int]
    var diagnostics: [MangaOverlayTextBoxCandidateDiagnostic]
    var notes: [String]
}
```

候选来源建议最少覆盖：

- `fusedSeedBBox`：当前 fused block seed bbox。
- `textRegionCropBBox`：v1.2/v1.5 现有 crop bbox。
- `splitCandidateBBox`：v1.5 split candidate。
- `correctedBubbleClampBBox`：v1.5 corrected bubble clamp。
- `glyphMaskExpandedBBox`：由 glyph mask rect 适度扩张得到，只能诊断，默认不直接替换 crop。
- `maskSafeRect`：由 BubbleMask safe rect 得到，只能作为 overlap / containment 证据，不直接全框 OCR。

优先保持单块一个主 TextBox candidate，避免本轮产生多候选选择复杂度。若要支持多候选，必须在报告中清晰标出 active candidate 和 rejected candidates。

### 3. 新增轻量 SegmentMask 报告模型
在 `TranscriptModels.swift` 新增轻量 SegmentMask 诊断。它不是新分割模型，只聚合现有 glyph mask 与 bubble mask 证据：

```swift
struct MangaOverlaySegmentMaskDiagnostic: Equatable, Codable, Sendable {
    var blockIndex: Int
    var textBoxCandidateID: Int?
    var glyphMaskPixelCount: Int
    var glyphMaskRect: [Double]?
    var glyphMaskFillRectCount: Int
    var textBoxCoverageRatio: Double?
    var bubbleMaskCoverageRatio: Double?
    var safeRectCoverageRatio: Double?
    var glyphEscapesBubble: Bool
    var glyphEscapesTextBox: Bool
    var usableForCleanup: Bool
    var usableForCropEvidence: Bool
    var rejectionReasons: [String]
    var riskFlags: [String]
    var notes: [String]
}

struct MangaOverlaySegmentMaskReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var evaluatedBlockCount: Int
    var glyphMaskBlocks: Int
    var usableForCleanupBlocks: [Int]
    var usableForCropEvidenceBlocks: [Int]
    var weakSegmentBlocks: [Int]
    var diagnostics: [MangaOverlaySegmentMaskDiagnostic]
    var notes: [String]
}
```

SegmentMask 判定建议：

- `glyphMaskPixelCount <= 0`：`weakSegmentBlocks`，不可作为 crop 证据。
- glyph rect 与 TextBox overlap 太低：`glyphEscapesTextBox = true`，只做诊断。
- glyph rect 与 bubble mask / safe rect overlap 太低：`glyphEscapesBubble = true` 或 `segmentOutsideBubbleRisk`。
- 未归属块、decorative 标题、短保护文本默认保守，只能做 cleanup/render 证据，不能驱动主输入。
- 任何 SegmentMask 判定不得使用 ground truth。

### 4. 把 TextBox / SegmentMask 接入 crop 诊断，但不放宽采用
修改 `applyTextRegionCropCandidates(...)` 或相邻调度逻辑：

```text
fused blocks + bubble geometry + bubble mask + assignment correction + split candidate + glyph mask
  -> makeTextBoxCandidateReport
  -> makeSegmentMaskReport
  -> recognizeTextRegionCrop 仍使用现有保守 clamp
  -> textRegionCropReport 合并 textBoxCandidateID / segmentMask verdict / failure attribution
```

规则：

- 本轮可以让 TextBox candidate 作为 `recognizeTextRegionCrop` 的记录来源或 clamp 解释，但不要绕过 v1.2/v1.5 的 crop 护栏。
- 如果选择用 TextBox candidate 调整 crop bbox，只允许在 ground-truth-free 证据更强时收窄或微调，且必须记录 before/after bbox。
- 如果 crop 结果变差，必须回退 fused text，并把失败归因写进 `textRegionCropReport`。
- `adoptedCount` 仍可为 0；这是可接受结果，不是失败。

### 5. 新增 crop failure attribution
在 `MangaOverlayTextRegionCropDiagnostic` 或报告级汇总中增加字段：

```swift
var failureAttribution: [String]
```

报告级建议增加：

```swift
var failureAttributionBreakdown: [String: Int]
```

归因建议：

- `emptyLocalOCR`：局部 crop OCR 空。
- `rawWordsLost`：raw word preservation 明显不足。
- `wordCountRegression`：词数退化。
- `localVisionRegression`：局部 OCR 分数或质量明显低于 fused。
- `introducedLikelyOCRError`：引入新的明显 OCR 错。
- `textBoxTooTight`：TextBox 覆盖 glyph / seed 不足，或 crop bbox 过窄。
- `textBoxTooWide`：TextBox 与 sibling / split candidate overlap 太高，可能串扰。
- `segmentMaskWeak`：glyph mask 缺失或与 TextBox/bubble 不一致。
- `bubbleMaskConflict`：BubbleMask 归属冲突未安全解决。
- `sameAsFusedText`：候选与 fused 相同。
- `insufficientQualityGain`：有改善但不足以通过护栏。

同一个块可以有多个归因。归因是诊断，不是采用理由。

### 6. TXT / PNG 输出
更新 `1_ocr_probe_text.txt`，每块至少输出：

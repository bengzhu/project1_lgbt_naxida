## 背景判断
Koharu 的关键优势是结构化 artifact DAG：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> FontPredictions
  -> Translations
  -> Inpainted
  -> RenderedSprites
  -> FinalRender
```

AITRANS 已经补齐了很多内部近似层：whole-page + bubble-first 融合、post-fusion cleanup、BubbleMask 近似、SegmentMask proxy、pre-crop TextBox plan、crop experiment、line-level deskew shadow、external artifact readiness gate 和 external TextBoxes shadow OCR 入口。

但这些仍不是 Koharu 的真实 detector / segmenter 输出。v20 已判停继续试 block-level / line-level crop / deskew；v1.11-v1.13 已证明没有真实 active artifact 时必须阻塞。因此 v1.14 的优化重心应转向：

```text
真实 Koharu / 外部 detector 输出
  -> active artifact 注入与离线校验
  -> App bundle / CI 能读到 active artifact
  -> readiness = readyForShadowOCR
  -> externalTextBoxShadowOCRReport.executed = true
  -> 每块候选、OCR 文本、quality delta、blockers 可审计
  -> 不写回主流程
```

## 目标
建立真实 external artifact 的注入、验证和云端报告闭环。按实际条件分两条路径执行。

### 路径 A：本轮已有真实 Koharu / 外部 detector artifact
如果人工或 Koharu 侧已提供真实 `test/1.png` 对应输出，本轮必须：

1. 放入 active 目录 `test/koharu_artifacts/`，文件名建议：

```text
test/koharu_artifacts/
  1.manifest.json
  1.textboxes.json
  1.bubbles.json
  1.segment_mask.json
```

2. manifest 必须写：

```json
{
  "schemaVersion": "aitrans.koharu_artifact_contract.v1",
  "sourceImage": "test/1.png",
  "coordinateSpace": "originalImageTopLeftPixels",
  "contractExampleOnly": false,
  "generatedBy": "真实 detector / Koharu 输出来源",
  "textBoxesPath": "1.textboxes.json",
  "bubbleMaskPath": "1.bubbles.json",
  "segmentMaskPath": "1.segment_mask.json",
  "notes": []

```

3. 先跑离线 validator，必须达到 `readyForShadowOCR`。
4. 确认 `test/koharu_artifacts/` 进入 App bundle。若当前 Xcode project 的 folder resource 已包含 `test/`，只需验证云端 App 侧能读到；若没有被 bundle 收到，只做最小工程配置修复。
5. 推送 `codeb/v1.14-real-koharu-artifact-shadow-ocr` 并创建 PR，由 GitHub Actions 跑完整云端探针。
6. 云端结果包中必须看到：
   - `externalArtifactReadinessReport.readinessVerdict = readyForShadowOCR`
   - `externalArtifactReadinessReport.activeArtifactsDirectory = true`
   - `externalArtifactReadinessReport.contractExampleOnly = false`
   - `externalTextBoxesShadowOCRReport.executed = true`
   - `candidateCount > 0`
   - `ocrExecutedCount > 0`
   - 每块最多 1 个 `externalArtifact.textBoxCrop` candidate
   - `promotedExternalShadowBlocks = []`
   - `wouldPromoteByExistingGateBlocks` 仅为 report-only
7. 汇总 executed=true 的收益和失败归因：
   - 每块 selected TextBox ID、IoU、center containment、bubble alignment。
   - OCR 文本与 control 文本对比。
   - `betterThanControlCount`、`ocrSucceededCount`、`skippedBlocks`。
   - 关键 blockers：`emptyLocalOCR`、`rawWordsLost`、`wordCountRegression`、`sameAsFusedText`、`introducedLikelyOCRError`、`bubbleAlignmentMismatch`、`textBoxAreaTooLarge`。
   - 是否命中重点块：`#1`、`#2`、`#5/#6/#8/#9/#10/#11/#12` 等 OCR 问题块。

## 实现要求
### 1. 先判断是否存在真实 active artifact
实现前必须检查：

```sh
find test -maxdepth 2 -path 'test/koharu_artifacts*' -print
python3 scripts/validate-koharu-artifacts.py --root test/koharu_artifacts --allow-missing
```

若目录不存在或 validator 返回 `manifestMissing`，按路径 B 执行。若目录存在，必须确认不是 examples、不是手写真值、不是 Vision OCR 派生假数据，再按路径 A 执行。

### 2. executed=true 路径的最低要求
如果有真实 artifact，报告必须满足：

- `externalArtifactReadinessReport.textBoxCount > 0`
- `externalArtifactReadinessReport.bubbleInstanceCount > 0`
- `externalArtifactReadinessReport.segmentGlyphPixelCount` 存在或 `segmentMaskSizeMatches = true`
- `coordinateValidation.bboxValidationPassed = true`
- `coordinateValidation.errors = []`
- `blockAlignment.count == totalBlocksDetected`
- `externalTextBoxShadowOCRReport.executed = true`
- `externalTextBoxShadowOCRReport.candidateCount <= totalBlocksDetected`
- `externalTextBoxShadowOCRReport.blockSummaries.count == totalBlocksDetected`
- `externalTextBoxShadowOCRReport.candidates[].variantName = externalArtifact.textBoxCrop`
- `externalTextBoxShadowOCRReport.candidates[].groundTruthUsedForSelection = false` 等价信息必须在 notes 或字段中可见。

如果这些字段当前缺失，可小范围补齐 Swift 模型或 TXT 输出，但不要重构主探针。

### 3. App bundle / CI 可见性
真实 artifact 如果放在 `test/koharu_artifacts/`，必须确认云端 Debug app 能读到：

- 结果包里 `probe_report.json` 不是 checkout 旧文件。
- `externalArtifactReadinessReport.activeArtifactsDirectory = true`。
- `manifestPath` / `textBoxesPath` / `bubbleMaskPath` / `segmentMaskPath` 指向 App bundle 或已解析路径。
- `manga-probe.log` 或 `app-console.log` 有足够线索说明 App 读取的是本轮 bundle 内文件。

若 App bundle 没带上 active artifact，只修资源包含问题，不绕过 App 读取逻辑。

### 4. 报告与纯文本快照
`1_ocr_probe_text.txt` 每块必须继续包含：

- `externalArtifacts: readiness=... shadowOCRAllowed=... activeDirectory=... contractExampleOnly=...`
- `externalTextBoxShadowOCR: executed=... selectedTextBoxID=... candidateBBox=... ocrSucceeded=... ocrText=... qualityDelta=... wordPreservation=... promotionVerdict=... blockers=...`

executed=true 时必须能不用 `jq` 也看出每块为什么采用或跳过 external candidate。

### 5. 文档同步
按实际改动同步：

- `update_log.md`：记录 v1.14 目标、是否有真实 artifact、核心变更、验证结果、遗留问题。
- `md/flow/flow.md`：如执行路径或报告字段有变化，补充当前真实流程。
- `md/flow/flowchart.md`：与 flow 同步。
- `md/test/test.md`：补充 executed=true / missing artifact 的测试选择和验收口径。
- `md/koharu研究/artifact_contract/README.md`：若补强导入说明或 validator 输出，更新契约文档。

## 已知风险
- 当前仓库默认没有真实 `test/koharu_artifacts/`，所以 v1.14 可能只能完成验证闭环补强，不能证明 OCR 收益。
- 如果真实 artifact 的 TextBoxes 坐标来自裁切图而不是原图，validator 应拒绝；不要在 App 内偷偷重映射，除非 manifest 明确记录来源和转换。
- BubbleMask / SegmentMask 当前契约仍是 summary，不是真实 mask PNG；它足够 gate external TextBoxes OCR，但不足以替代 Koharu 的 mask-safe rendering / inpainting。
- Gemma 270M 仍不适合作翻译质量基准；即使 OCR 候选更好，端到端 `overallPassed` 仍可能为 false。

## 当前判断
v1.31 已把 Koharu 的 `EngineInfo.needs / produces`、DAG resolver 和 Op preview 映射成 AITRANS 影子 DAG。v1.32 已把 resolver 输出转成 work orders、budget gate 和 stoplist。v1.33 已把外部 TextBoxes / BubbleMask / SegmentMask 的真实交付需求固化为 request packet。

下一步不应重复新增 request packet，也不应等待真实 `test/koharu_artifacts/` 才继续推进。人工明确要求继续用 AITRANS 自己的探针输出分析 OCR 准确率、气泡归属 / 分割、翻译失败分类、覆盖渲染和结构瓶颈。因此 v1.34 应新增一个本地算法复刻执行矩阵：

- 从 AITRANS 现有报告中抽取 Koharu canonical stage 的本地可执行候选。
- 把候选分成 `nativeExecutableNow`、`shadowOnly`、`stoplisted`、`externalArtifactBlocked`、`modelFloorBlocked`、`renderLocked`。
- 对每个候选写出控制组、候选组、收益指标、风险、预算、晋级门槛和必须继续阻塞的理由。
- 使用 AITRANS 自己的探针输出做评估和路由，不用 ground truth 做候选选择或晋级决策；ground truth 只能进入 evaluation signals。
- 本轮仍是 report-only / diagnostic-only，不替换主 OCR、翻译输入、覆盖图或 `blockPassed`。

这个报告要回答一个更工程化的问题：在没有真实 Koharu artifacts 前，AITRANS 还能安全复刻哪些 Koharu 算法结构，哪些已经被探针证明应该停止，哪些只能等待真实 artifact，哪些问题其实是翻译模型地板或渲染锁，不该继续归因给 OCR。

从最新 `smalldata_test` 开分支：


报告目标：

1. 聚合 `koharuPipelineResolverReport`、`koharuWorkOrderRouterReport`、`koharuExternalArtifactRequestPacketReport`、`koharuArtifactConvergenceReport`、TextBox / BubbleMask / SegmentMask scoreboards、translation floor、render lock、final blocks 和 diagnostics。

3. 输出 native replay candidates，至少覆盖：
   - whole-page + bubble-first 融合证据保持。
   - post-fusion cleanup 保护与拒绝审计。
   - TextBox proxy / crop / line / deskew stoplist。
   - BubbleMask assignment / split / sibling layout 分析。
   - SegmentMask proxy / glyph cleanup / render mask 分析。
   - translation model floor handoff。
   - render regression lock。
   - external artifact blocked handoff。
4. 每个候选必须写明 control evidence、candidate evidence、expected metric impact、budget class、promotion gate、blockers、risk、next action、是否允许在 ci-fast 中继续评估。
5. 每个 block 必须有 replay route，说明该 block 现在最像 Koharu 哪个阶段的瓶颈，是否可用 AITRANS native evidence 继续复刻，或必须等待真实 artifact / 模型 / 人工审查。
6. 与 convergence 联动，新增 v1.34 reference report、work item 或 gate，证明 v1.34 是 v1.31-v1.33 之后的本地执行矩阵收口。

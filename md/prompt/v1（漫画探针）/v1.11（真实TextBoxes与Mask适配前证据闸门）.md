## 背景
Koharu 的图像链路不是“整页 OCR 后不断裁切补丁”，而是 artifact DAG：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> FontPredictions
  -> Translations
  -> Inpainted
  -> RenderedSprites
  -> FinalRender
```

Koharu 源码中 `Artifact` 明确把 `TextBoxes`、`SegmentMask`、`BubbleMask` 作为 pipeline 的依赖货币；默认配置使用 `pp-doclayout-v3`、`comic-text-detector-seg`、`speech-bubble-segmentation` 等 engine。`TextRegion` 输出包含 `x/y/width/height`、`confidence`、`line_polygons`、`source_direction`、`rotation_deg`、`detected_font_size_px`、`detector` 等字段。

AITRANS 当前已有很多轻量近似层：

- whole-page + bubble-first 融合主流程。
- BubbleMask 实例 ID 近似和 mask-safe layout 诊断。
- TextBox / SegmentMask 轻量证据层。
- pre-crop TextBox plan、crop experiment、plan failure attribution。
- line-level TextBox / deskew shadow 验证。

但这些仍是从 Vision OCR / 气泡几何 / glyph proxy 反推出来的近似产物，不是独立 detector / segmenter 的真实输出。v1.11 的目标不是直接把外部模型接入主流程，而是建立一个可审计的适配层和 readiness gate：如果本地没有可用 detector / mask 产物，就明确报告缺失和阻塞；如果存在本地离线输出或手工导出的 detector 结果，则只作为 shadow artifact 解析、校验、对照，不写回主流程。

## 目标
实现一个 ground-truth-free、shadow-only 的 Koharu artifact 适配前证据闸门。建议命名为：

- `externalArtifactReadinessReport`
- `koharuArtifactReadinessReport`
- 或 `detectorArtifactReadinessReport`

至少覆盖三类 artifact：

1. `TextBoxes`：真实或外部导出的文本框检测结果。
2. `BubbleMask`：真实或外部导出的气泡实例 mask / instance bbox / instance ID 结果。
3. `SegmentMask`：真实或外部导出的文字像素 mask / glyph mask 结果。

本轮必须回答：

- 当前仓库和 App 沙盒里有没有可用的本地 detector / mask artifact 输入。
- 如果没有，缺的是模型、可执行文件、manifest、输出文件、格式转换，还是 iOS 本地部署约束。
- 如果有，能否解析成 AITRANS 内部统一数据模型。
- 这些外部 artifact 与现有 fused blocks / bubbleMaskReport / segmentMaskReport 的几何关系如何。
- 是否存在足够证据进入下一轮真实 detector shadow OCR；如果证据不足，应给出停止原因，不得假装已接入。

## 风险和禁止项
- 最大风险是把 readiness gate 写成 detector 接入完成。本轮只验证输入和适配条件。
- 第二风险是引入网络下载或大模型权重。禁止。
- 第三风险是把 reference/koharu-main 的源码存在误判为 AITRANS iOS 可直接调用。必须区分参考源码、可执行文件、模型权重、可解析输出和 App 内可部署能力。
- 第四风险是让外部 artifact 对齐使用 ground truth。禁止。
- 第五风险是绕过 v20 结论继续调 crop / line / deskew。禁止。
- 第六风险是把 detector/mask 几何 readiness 写成 OCR 或翻译质量提升。报告要分开记录。

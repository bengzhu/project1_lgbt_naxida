# AITRANS Agent B / Koharu 提示词：v1.3（BubbleMask 子区域与 TextRegion clamp 优化）

## 版本号
v1.3（漫画探针 / BubbleMask 子区域诊断与 TextRegion crop clamp 优化）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入，v1.1 已做 post-fusion 重复碎片清理和气泡分割审计，v1.2 已接入 TextRegion crop OCR 候选层。

v1.2 的关键结果不是 crop 失败，而是证据更清楚：当前 13 个主块都有结构化 TextRegion 诊断，10 个 crop OCR 有结果，但 `adoptedCount = 0`，全部被护栏回退。主要拒绝原因集中在 `rawWordsLost`、`emptyCropText`、`wordCountRegression`、`introducedLikelyOCRError` 和 `insufficientQualityGain`。这说明下一步不应继续放宽 crop 采用规则，也不应换模型或把纠错切主流程，而应沿 Koharu 的 `BubbleMask / SegmentMask / TextBoxes` 思路，先让过大的 bubble 内部出现可审计的子区域和 mask 约束，再用它们收紧 TextRegion crop 的边界。

本轮是 v1.3：对 `bubbleID 4/6/7` 等 oversized bubble 做轻量 BubbleMask 子区域诊断，并在强护栏下让 TextRegion crop 优先 clamp 到 block-local subregion，而不是粗暴 clamp 到整个大 bubble bbox。

- `bubbleID 6`：bbox `[0,883,231,262]`，`fusedBlockIndexes = [8, 9]`，覆盖长建议气泡与 `What are you talking about?`，`bubbleSplitCandidate = true`。
- `bubbleID 7`：bbox `[213,900,190,199]`，`fusedBlockIndexes = [10, 12]`，覆盖 `-O2 AT LEAST...` 与装饰标题附近，`bubbleSplitCandidate = true`。

v1.2 的 crop 失败案例证明大 bubble bbox 不是足够好的 OCR crop 边界：

- `block 5` 的 crop 在 `bubbleID 7` 内混入 `LET'S BATTLER` 附近内容，`rawWordsLost`。
- `block 6` 的 crop 在 `bubbleID 4` 内混入 `What are...`，`rawWordsLost`。

- `block 11` 的 crop 在 `bubbleID 4` 内变成 `cono / DuST / ONLINE:`，`emptyCropText`。

所以 v1.3 的问题定义是：TextRegion crop 已经有了，但它缺少 Koharu 式 bubble instance mask / local safe region 证据；先补轻量子区域和 mask 诊断，再决定 crop 能否更窄、更干净。

## 目标
实现一个可审计、可回退、ground-truth-free 的轻量 BubbleMask 子区域诊断层，并把它接入 TextRegion crop clamp：

1. 为每个已有 bubble 生成轻量 `bubbleSubRegions` / `bubbleMaskApproximation` 报告，至少记录 subregion id、parent bubbleID、bbox、seed block indexes、source、area、coverage、risk flags 和 notes。
2. 对 `bubbleSplitCandidate = true` 的 oversized bubble，优先根据 fused block seed bbox、OCR text region bbox、白底连通域边界和几何间隙生成 block-local subregion。
3. TextRegion crop OCR 先尝试使用 block-local subregion bbox 作为 clamp 边界；没有可信 subregion 时回退 v1.2 的 bubble bbox / content rect clamp。
4. 在 `textRegionCropReport.diagnostics[]` 中新增或扩展字段，记录本块使用的 clamp 来源：
   - `clampSource = subRegion | bubbleBBox | contentRect`
   - `subRegionID`
   - `subRegionBBox`
   - `subRegionCoverageRatio`
   - `subRegionRejectedReason`
   - `cropBBoxBeforeSubRegionClamp`
   - `cropBBoxAfterSubRegionClamp`
5. 允许在强护栏下采用 subregion clamp 后的 crop OCR 文本，但不得放宽 v1.2 的候选采用规则；如果 crop 仍更差，必须回退 fused 文本并写明原因。
6. 报告必须能回答：本轮是否减少了 crop 串扰、哪些块因 subregion clamp 改善、哪些块仍失败、哪些 bubble 只适合诊断不适合拆分。
7. 保持 v1.1 / v1.2 主成果不回归：13 块、三条保护文本、post-fusion cleanup、失败块绘制、报告明细和输出清理规则都必须保留。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于 subregion 生成、crop clamp、候选采用、排序、拒绝或回退。
- 不要放宽 TextRegion crop 采用规则来制造 `adoptedCount`。
- 不要把 deterministic correction 纳入 `finalTextUsedForTranslation` 主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要为了降低块数或提高相似度跨气泡合并。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 mask / subregion 的渲染收益说成 OCR 质量已经提升；必须用报告数字区分。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严。

## 实现步骤
### 1. 先做基线核查
实现前从当前 `output/probe_report.json` 和 `output/1_ocr_probe_text.txt` 列出：

- 13 个块的 `index`、`bubbleID`、`bbox`、`finalTextUsedForTranslation`、`textRegionCropText`、`textRegionRejectionReasons`。
- `bubbleAudits` 中 `bubbleSplitCandidate = true` 的 bubble。
- `textRegionCropReport.mainRejectionReasons`。
- v1.2 中 crop 明显被相邻块污染的案例。

把观察写进最终回复。不要只看覆盖图猜。

### 2. 新增 Bubble subregion 报告模型
在 `TranscriptModels.swift` 或 `MangaOverlayProbeService.swift` 附近新增轻量 Codable 结构。命名可自行调整，但报告必须表达这些字段：

```swift
struct MangaOverlayBubbleSubRegionDiagnostic: Equatable, Codable, Sendable {
    var id: Int
    var parentBubbleID: Int
    var bbox: [Double]
    var seedBlockIndexes: [Int]
    var seedTextRegionIndexes: [Int]
    var source: String
    var area: Double
    var parentCoverageRatio: Double
    var seedCoverageRatio: Double
    var confidence: Double
    var clampEligible: Bool
    var rejectionReasons: [String]
    var notes: [String]
}

struct MangaOverlayBubbleSubRegionReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var totalSubRegions: Int
    var clampEligibleCount: Int
    var oversizedBubbleIDs: [Int]
    var diagnostics: [MangaOverlayBubbleSubRegionDiagnostic]
    var notes: [String]
}
```

可以挂在 `bubbleGeometry` 下，也可以作为顶层 `bubbleSubRegionReport`。优先选择最小侵入方案，但 `probe_report.json` 必须能看见。

### 3. 生成轻量 subregion
新增一个纯函数式步骤，建议放在 `MangaOverlayProbeService`：

```text
bubbleGeometry + post-clean fused blocks + image/content rect
  -> oversized bubble audit
  -> fused block seed bbox / text region bbox
  -> optional near-white component bounds
  -> block-local expanded bbox
  -> clamp to parent bubble bbox and content rect
  -> subregion diagnostics
```

规则建议：

- 只对有 `bubbleID` 的块生成 parent-bubble subregion；`bubbleID = nil` 块继续使用 v1.2 content rect fallback。
- 对普通 bubble，可生成与现有 bubble bbox 接近的 subregion，但 `clampEligible` 可以为 false，避免无意义重写。
- 对 oversized bubble，使用每个 fused block 的 seed bbox 向外扩张，再 clamp 到 parent bubble bbox。
- 扩张大小参考 block bbox 尺寸、文字方向和当前 v1.2 padding；不要把整个 parent bubble 当成 crop。
- 若两个 subregion 高重叠，记录 `overlapsSiblingSubRegion`，不要强行拆分到错位。
- 若 subregion 太小、覆盖 seed 不足、宽高异常、面积低于阈值、或会切掉大部分 seed bbox，则 `clampEligible = false`。
- 不要用真值相似度、groundTruthMatch、bestGroundTruthText 或人工真值文本参与任何判断。

### 4. 接入 TextRegion crop clamp
扩展 `recognizeTextRegionCrop(...)` 或其调用参数，使其能接收可选 `subRegionBBox`。

推荐顺序：

```text
seed bbox
  -> 计算 v1.2 原始 region/crop bbox
  -> 如果有可信 subregion，crop clamp 到 subregion bbox
  -> 否则有 bubbleID 时 clamp 到 bubble bbox
  -> 否则 clamp 到 content rect
  -> Vision OCR
  -> v1.2 evaluateTextRegionCropSelection
```

必须记录：

- 原始 crop bbox。
- subregion clamp 后 crop bbox。
- 是否实际使用 subregion clamp。
- 未使用原因。
- crop OCR 与 fused 文本的选择结果和拒绝原因。

### 5. 不放宽采用规则
`evaluateTextRegionCropSelection(...)` 的核心护栏保持不变：

- 空文本拒绝。
- 词数退化拒绝。
- raw words 丢失拒绝。
- 低拉丁比例或符号过重拒绝。
- 与原 fused 文本相同或收益不足拒绝。
- 引入明显 OCR 错误拒绝。

如果 subregion clamp 让 crop 文本变好，但仍未达到护栏要求，应继续回退 fused 文本。不要为了让 `adoptedCount > 0` 放宽规则。

### 6. 更新输出文本和图像证据
同步更新：

- `probe_report.json`：新增 subregion / clamp 诊断。
- `1_ocr_probe_text.txt`：每块显示 `subRegionID`、`subRegionBBox`、`clampSource`、`cropBBoxBeforeSubRegionClamp`、`cropBBoxAfterSubRegionClamp`、`subRegionRejectedReason`。
- 如实现成本低，可在 `1_bubble_debug.png` 或 contact sheet 上画 subregion bbox，使用不同颜色区分 parent bubble 和 subregion；本轮不强制，但如果实现了必须确保 PNG 非空且不影响原图输出。

### 7. 强保护 v1.2 成果
本轮不能回归：

- `configuration.currentBlockSource` 默认仍保持 `fusedWholePageBubble`；只有 crop 被实际采用时才可改成更明确的 `fusedWholePageBubbleTextRegionCrop`，并同步文档解释。
- `fusionComparison.postFusionCleanup.applied = true` 仍要存在。
- `fusionComparison.postFusionCleanup.blockCountBeforeCleanup = 16`、`blockCountAfterCleanup = 13`、`rejectedBlockCount = 3` 的语义不能被破坏。
- 三条保护文本不能丢：
  - `Let's Battle!`
  - `What are you even talking about?`
  - `We need to get results at this tournament to save the gaming club from being disbanded.`
- `frameworkComparison.consistencyPassed` 和 `fusionComparison.consistencyPassed` 必须继续可解释。
- 失败块仍必须保留在 `blocks` 明细，并在覆盖图显示 `翻译失败 + OCR 原文`。

## 风险和禁止项
- 轻量 subregion 不是 Koharu 真正的实例 `BubbleMask`，只能作为 iOS 传统图像算法近似；不要在文档中夸大。
- 过窄 subregion 可能切掉字，必须记录 seed coverage 和回退原因。
- 过宽 subregion 仍会串扰，必须记录 sibling overlap 或 oversized 风险。
- OCR 分数不提升也可以接受，只要报告更能解释下一步该拆 bubble、改 mask，还是继续保留 fallback。
- 不要把渲染安全区、glyph mask、背景填充和 OCR 准确率混为一谈。

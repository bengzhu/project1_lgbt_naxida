v1.18-v1.21 已形成四层结构诊断：

- `internalStructureBottleneckReport`：聚合 OCR、bubble、crop、翻译、render 证据并给每块路由。
- `routingDrivenTranslationComparisonReport` / `ocrCharacterDamageAuditReport`：专项翻译和 OCR 损坏审计。
- `readingOrderStructureAuditReport`：阅读顺序、气泡归属、多块气泡、重复/碎片和结构动作建议。
- `structureActionCandidateReport`：把结构建议转成 shadow-only 候选矩阵，做轻量可执行评估。

下一步不要继续新增同类“每块风险摘要”。Koharu 的关键结构不是单个风险列表，而是 `SourceImage -> TextBoxes -> SegmentMask -> BubbleMask -> OcrText -> Translations -> Inpainted/Rendered -> FinalRender` 的 artifact DAG。AITRANS 现在虽然有很多诊断报告，但缺少一张统一的“阶段账本”：每个阶段产生了哪些真实 / proxy / missing artifact，哪些下游消费了它，在哪个 gate 首次失败，是否影响 OCR 准确率、气泡归属 / 分割、翻译失败分类或覆盖渲染。

本轮要把这些既有报告组织成 Koharu 式 artifact pipeline trace，为后续真实 TextBoxes / BubbleMask / SegmentMask 接入和主流程升级提供可审计底座。

## 本轮目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.22-koharu-artifact-dag-stage-ledger
```

新增一个 Koharu 式 Artifact DAG 阶段账本报告：

```text
koharuArtifactDAGReport
```

报告目标：

1. 用稳定 schema 描述 AITRANS 当前探针中等价于 Koharu artifact 的阶段产物。
2. 按 block 追踪 `SourceImage / ContentCrop / BubbleCandidates / BubbleMask / TextBoxes / SegmentMask / OcrText / Translation / Render` 的 ready / proxy / missing / blocked 状态。
3. 找出每个 block 的 `firstBlockingStage` 和 `downstreamImpact`。
4. 把 v1.21 `structureActionCandidateReport` 的候选结论纳入阶段 gate，但不替换 v1.21 报告。
5. 给出下一步最小可执行建议：继续等待真实 artifact、停止某类 crop / line / deskew 试参、保留渲染优化候选、或进入人工 review。

本轮仍是 report-only / diagnostic-only，不改变主 OCR、翻译输入、覆盖图、`blockPassed`、失败分类、post-fusion cleanup、候选选择或 `configuration.currentBlockSource`。

- `sourceReport`
- `sourceIDs`
- `confidence`
- `gateChecks`
- `blockers`
- `downstreamImpact`
- `diagnosticOnly`
- `wouldChangeMainFlow = false`

`firstBlockingStage` 应从当前真实证据推导，建议优先级：

1. `externalArtifactGate`：真实 active artifact 缺失时，只对需要真实 TextBoxes / BubbleMask / SegmentMask 的候选标阻塞，不要把所有块都标成全局失败。
2. `textBoxes` / `segmentMask`：v1.21 candidate 或 v1.20 evidence 标记 weak / missing 时。
3. `bubbleMask`：mask conflict、bubble assignment risk、split risk 或 low crop mask coverage。
4. `ocrText` / `ocrCropShadow`：低 OCR 相似度、`ocrInputSuspect`、crop / line promotion 被 `rawWordsLost`、`introducedLikelyOCRError`、`emptyLocalOCR` 阻塞。
5. `translation`：`cleanTextDiagnostic` 低、`failureCategory = modelOutputFailure` 或 `translationLanguageQualityFailure`，且 OCR 不是主要嫌疑时。
6. `renderLayout`：render overflow、truncation、mask collision 或只有渲染候选。
7. `finalOverlay`：只有最终绘制产物缺失 / 空图时才阻塞。

`downstreamImpacts` 稳定字符串建议：

- `ocrAccuracy`
- `bubbleAssignment`
- `bubbleSegmentation`
- `translationFailureClassification`
- `renderLayout`
- `artifactReadiness`
- `manualReview`
- `none`

## 目标 4：与既有报告的映射规则
`koharuArtifactDAGReport` 必须复用既有证据，不新增昂贵 OCR / LLM 调用。建议映射：

- `sourceImage` / `contentCrop`：来自当前 probe configuration 和 source image。
- `visionOCRCandidates` / `ocrText`：来自最终 `blocks`、`frameworkComparison`、`fusionComparison`。
- `bubbleCandidates` / `bubbleMask`：来自 `bubbleMaskReport`、`bubbleAssignmentCorrectionReport`、`bubbleSplitCandidateReport`、block `bubbleID`。
- `textBoxes`：来自 `textBoxCandidateReport`、`preCropTextBoxPlanReport`、`textBoxPlanFailureReport`、`externalArtifactReadinessReport`。
- `segmentMask`：来自 `segmentMaskReport`、glyph mask、external readiness。
- `ocrCropShadow`：来自 `textRegionCropReport`、`cropExperimentReport`、`textBoxPlanFailureReport`。
- `lineTextBoxShadow`：来自 `lineTextBoxPlanReport`、`lineCropExperimentReport`。
- `externalArtifactGate` / `externalTextBoxShadowOCR`：来自 external readiness / shadow OCR reports。
- `fusionAndCleanup`：来自 `fusionComparison` 和 `postFusionCleanup`。
- `translation` / `cleanTextDiagnostic`：来自 block failure category、translation decision trace、`clean_text_diagnostic.json` embedded report。
- `renderLayout` / `finalOverlay`：来自 safe layout、glyph mask、background fill、render collision and retained output files。
- `structureActionCandidates`：来自 v1.21 `structureActionCandidateReport`。

允许把 `groundTruthMatch`、`bestGroundTruthType`、`ocrGroundTruthSimilarity` 写入 `ocrSimilarityForEvaluation`，但只能用于评估和说明，不能参与 stage gate 的 pass/fail 决策、候选生成、排序、promotion、cleanup 或覆盖绘制。

## 风险和禁止项
- 最大风险是把内部 proxy 包装成“真实 Koharu artifact”。禁止。
- 第二风险是新增报告过度复杂导致 `probe_report.json` 巨大但不可读。字段要稳定、枚举要短、TXT 要能快速读懂。
- 第三风险是把 ground truth evaluation 误用为 gate decision。所有 gate check 必须写 `groundTruthUsedForDecision = false`。
- `ci-fast` 跳过 full-only shadow 诊断时不能崩溃；缺失 report 要写 `skippedFastMode` / `notApplicable`。
- 不要为追求阶段完整而新增 OCR / LLM 调用，避免拖慢云端。
- 不要合并到 `main`。
- push、PR、merge、删除远端分支前确认目标不是 `main`。

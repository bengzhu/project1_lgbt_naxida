## 版本号
v1.7（漫画探针 / TextRegion crop 实验矩阵与候选晋级门槛）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入。v1.1 完成 post-fusion cleanup 和气泡分割审计。v1.2 接入 TextRegion crop OCR 候选层。v1.3-v1.5 继续补上 BubbleMask 子区域、实例 ID、mask-safe layout、归属修正和保守 split candidate。v1.6 已新增 TextBox / SegmentMask 轻量证据层和 crop failure attribution，并修正语义：TextBox/SegmentMask 当前是 TextRegion crop 之后派生的诊断层，`usedForTextRegionCrop = false`、`usedForCropBlocks = []`，不能暗示已经参与上游选择。

v1.6 的结果说明，当前问题不是缺少更多字段，而是缺少一组可复现、可比较、ground-truth-free 的局部 OCR 候选实验。现在 `textRegionCropReport = 13 regions / 10 succeeded / 0 adopted / 13 rejected`，主要拒绝原因和归因已经清楚：

- `mainRejectionReasons = { emptyCropText: 3, insufficientQualityGain: 2, introducedLikelyOCRError: 2, rawWordsLost: 5, sameAsFusedText: 2, wordCountRegression: 2 }`
- `failureAttributionBreakdown = { localVisionRegression: 6, rawWordsLost: 5, bubbleMaskConflict: 3, emptyLocalOCR: 3, segmentMaskWeak: 3, textBoxTooWide: 2, introducedLikelyOCRError: 2, wordCountRegression: 2, sameAsFusedText: 2, insufficientQualityGain: 2 }`
- `textBoxCandidateReport.candidateCount = 13`
- `textBoxCandidateReport.cropEligibleCount = 6`
- `textBoxCandidateReport.usedForCropBlocks = []`
- `textBoxCandidateReport.rejectedBlocks = [2, 4, 5, 7, 9, 11, 12]`
- `segmentMaskReport.usableForCropEvidenceBlocks = [0, 1, 2, 3, 6, 7, 8, 9, 10, 11]`
- `segmentMaskReport.weakSegmentBlocks = [4, 5, 12]`

因此 v1.7 不应继续放宽 crop 采用护栏，也不应声称 TextBox/SegmentMask 已经改善 OCR。下一步应做 Koharu 风格的候选层验证：把现有 fused block、TextBox、SegmentMask、BubbleMask、subRegion、split candidate 和 corrected bubble clamp 组织成一个 shadow-only 实验矩阵，逐块比较哪些 crop 几何和预处理组合在无真值信号下更可靠；只有通过明确晋级门槛的候选，才允许后续版本讨论上游化。

## 问题定义
当前 TextRegion crop 链路有五个未解决问题：

1. 每块只有一个主要 crop 尝试，失败后很难判断是 crop bbox 错、预处理错、Vision 局部 OCR 退化，还是 SegmentMask/BubbleMask 证据本身不可靠。
2. TextBox 候选现在是 crop 之后派生，无法评估“如果 TextBox 先于 crop 生成，是否能改善局部 OCR 输入”。
3. `emptyCropText`、`rawWordsLost`、`wordCountRegression` 等拒绝原因说明结果差，但还不能给出下一步应该缩小、扩大、换 clamp source、还是停止该块 crop 尝试。
4. SegmentMask 可用块和 TextBox eligible 块有交集，但还没有被系统化地用于构造受控 OCR 候选。
5. 报告缺少 per-block 的候选排名、胜负原因和晋级门槛，因此后续 Agent 容易继续盲目堆诊断字段。

## 目标
实现一个 shadow-only、可复现、可审计、ground-truth-free 的 `TextRegionCropExperimentReport` 或等价报告：

1. 对每个最终 fused block 生成有限数量的 OCR crop 实验候选，至少包含当前 v16 TextRegion crop 作为 control。
2. 候选来源必须来自现有结构信号：fused seed bbox、TextBox candidate bbox、glyph/SegmentMask expanded bbox、maskSafeRect/subRegion、split candidate、corrected bubble clamp、bubble bbox 或 content rect。
3. 每个候选都记录 `candidateID`、`blockIndex`、`variantName`、`sourceStack`、`bboxBeforeClamp`、`bboxAfterClamp`、`preprocessingProfile`、`ocrText`、`ocrSucceeded`、`wordPreservationRatio`、`lineCountDelta`、`qualityScore`、`riskFlags`、`rejectionReasons`。
4. 每块最多运行一个小型候选集，避免指数级矩阵。建议每块 control + 最多 3 个额外候选；超过时按 ground-truth-free 证据先排序再截断。
5. 新增 per-block 的 `bestShadowCandidate` 和 `promotionVerdict`，但本轮不得改变 `finalTextUsedForTranslation`，不得改变覆盖图主译文输入。
6. 新增全局汇总：各 variant 的尝试数、OCR 成功数、优于 control 数、明显退化数、空输出数、raw words lost 数、可晋级块列表、应停止 crop 尝试块列表。
7. 在 `1_ocr_probe_text.txt` 中输出每块实验矩阵摘要，能直接看到 control 与 best shadow candidate 的差异和不采用原因。
8. 如果某块连续出现 `emptyLocalOCR` 或 `localVisionRegression`，报告要给出 stop reason，例如 `localVisionCropNotPromising`，避免后续继续在该块上盲目调参。
9. 保持当前主流程、失败块绘制、质量判定、clean text diagnostic 和 tagged batch 诊断不变。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于候选生成、候选排序、晋级判断、crop 采用或回退。
- 不要放宽 TextRegion crop 采用规则来制造 `adoptedCount > 0`。
- 不要在本轮把 TextBox/SegmentMask 候选上游化为主输入。
- 不要把 `bestShadowCandidate` 写入 `finalTextUsedForTranslation`。
- 不要改变 `fusedWholePageBubble` 主流程、post-fusion cleanup 或失败块覆盖绘制。
- 不要把 deterministic correction、tagged batch translation 或 clean text diagnostic 替换主流程。
- 不要为了提高相似度跨气泡合并。
- 不要把实验矩阵的诊断收益说成 OCR 准确率提升，除非完整探针数字证明。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严。

### 3. 设计候选集，控制规模
每块必须有 control：

- `currentTextRegionCrop`：v16 当前 TextRegion crop bbox 和预处理。

额外候选最多 3 个，按证据选择：

- `textBoxTight`：TextBox candidate bbox 或 fused seed bbox 的轻量收紧版本。
- `glyphMaskExpanded`：glyph rect 扩张后 clamp 到 bubble/mask safe 区，只在 `segmentMask.usableForCropEvidence = true` 时生成。
- `maskSafeRectConstrained`：以 `maskSafeRect` / `safeLayoutRect` 为边界，避免 crop 扩到相邻气泡。
- `splitCandidateClamp`：仅用于已有 split candidate 且非 decorative/短保护文本的块。
- `correctedBubbleClamp`：仅用于 v1.5 推荐归属修正且不触发保护规则的块。
- `subRegionClamp`：仅用于 oversized bubble 或已有 subRegion 证据的块。

候选选择规则：

- 不使用 ground truth。
- 不为 `decorative` 或 unassigned 短保护文本生成激进候选。
- `segmentMaskWeak` 块默认只允许 control + 保守 bbox 对照，不允许 glyph-driven 候选。
- 每块候选数必须在报告中可见，防止运行成本失控。

### 4. 定义 ground-truth-free 评分和晋级门槛
复用或抽取现有 TextRegion crop 质量判断，不要发明与主流程冲突的口径。每个候选至少检查：

- OCR 是否为空。
- 是否保留 fused 文本中的主要 raw words。
- 词数是否严重回退。
- 字母/符号比例是否异常。
- 是否引入明显 OCR 错误。
- 是否与原 fused 文本完全相同。
- bbox 是否越出 bubble / mask safe 区。
- SegmentMask 是否支持该 bbox。

建议晋级门槛：

- `ocrSucceeded = true`
- `wordPreservationRatio >= 0.80`，或对短文本使用更严格的 exact/near-exact 保留规则。
- `qualityDelta > 0.08` 或至少优于 control 且不触发 `rawWordsLost` / `introducedLikelyOCRError`。
- 不含 `bubbleMaskConflict`、`segmentOutsideBubbleRisk`、`decorativeTitleDiagnosticOnly`、`protectedShortTextDiagnosticOnly`。
- 对 `sameAsFusedText` 的候选不晋级，只记录为无收益。

本轮的 `promotionVerdict` 只能表示“shadow 候选值得后续研究”，不能表示已经采用到主流程。建议枚举：

- `promotableShadowCandidate`
- `controlStillBest`
- `noLocalOCRBenefit`
- `localVisionCropNotPromising`
- `segmentEvidenceTooWeak`
- `bubbleMaskConflict`
- `protectedDiagnosticOnly`

### 5. 接入调度，但保持主输入不变
建议在 `applyTextRegionCropCandidates(...)` 完成后、`makeTextBoxCandidateReport(...)` / `makeSegmentMaskReport(...)` 可用后，新增一个 shadow 实验函数，例如：

```text

  + textRegionCropReport

  + bubbleMaskReport
  + bubbleAssignmentCorrectionReport
```

规则：

- 实验报告可以调用 `recognizeTextRegionCrop(...)` 或抽出共享 OCR crop helper。
- 不要把实验候选写回 `blocks[].finalTextUsedForTranslation`。
- 不要改变 `textRegionCropReport.adoptedCount` 的既有语义。
- 如果为了复用 helper 需要小重构，必须保持改动局部，避免重写漫画探针主流程。

### 6. 输出 JSON 和 TXT
`probe_report.json` 顶层新增：

## 风险和禁止项
- 最大风险是把 shadow 实验误接入主输入。必须用字段名、notes 和最终回复反复说明：本轮只做候选实验，不改变生产选择。
- 第二风险是候选矩阵过大导致探针耗时失控。每块候选数必须受限。
- 第三风险是用 ground truth 优化候选排序。所有 promotion verdict 必须只用 bbox、mask、OCR 文本质量、raw word preservation 和现有质量门。
- 第四风险是把 local Vision crop 失败误解成“规则太严”。如果 `emptyLocalOCR`、`rawWordsLost`、`localVisionRegression` 仍占主导，结论应是该 crop 方向暂不 promising。
- 第五风险是报告语义再度误导。`bestShadowCandidate` 不等于 adopted，`promotableShadowCandidate` 只表示下一轮可研究，不表示当前主流程采用。

本轮交付应让下一位 Agent 能回答：哪些 TextRegion crop 候选值得继续上游化，哪些块应该停止局部 crop 方向，哪些失败更可能需要真正 TextBoxes/BubbleMask/SegmentMask 模型或更强 OCR，而不是继续调参。

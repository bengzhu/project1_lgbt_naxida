# AITRANS Agent B / Koharu 提示词：v1.1（重复碎片压缩与气泡分割审计）

## 版本号
v1.1（漫画探针 / fusedWholePageBubble 重复碎片压缩与气泡分割审计）

## 版本分配依据
v1.0 已完成 whole-page + bubble-first 融合主流程，并把当前主翻译输入切到 `fusedWholePageBubble`。融合解决了 v8 的二选一问题：没有丢 `Let's Battle!`，也纳入了 bubble-first 独有的 `What are you even talking about?` 和 `We need to get results at this tournament to save the gaming club from being disbanded.`。

但 v10 当前输出仍有重复、碎片和低信息块进入主流程。结合 `md/koharu研究/v6～9work.md` 的路线，本轮不继续换模型、不引入新 OCR 引擎、不把纠错切主流程，而是沿 Koharu 的 `TextBoxes / BubbleMask` 思路，先把融合后的候选层压干净：减少重复块、拒绝碎片块，并补充气泡分割审计字段，为后续真正的 text region crop 和 mask safe area 做准备。

## 背景
当前真实基线以最新 `output/probe_report.json`、`output/clean_text_diagnostic.json` 和 `metrics/version_history.csv` v10 行为准：

- `configuration.currentBlockSource = fusedWholePageBubble`
- `totalBlocksDetected = 16`
- `groundTruthMatchedBlocks = 13`
- `groundTruthUnmatchedBlocks = 3`
- `averageCoreDialogueOCRSimilarity = 0.7106`
- `averageDecorativeOCRSimilarity = 0.8000`
- `wholePageAccuracyVsGroundTruth = 0.5972`
- `bubbleFirstAccuracyVsGroundTruth = 0.7300`
- `frameworkComparison.consistencyPassed = true`
- `fusionComparison.consistencyPassed = true`
- `fusion.fused.accuracyVsGroundTruth = 0.7384`
- `cleanTextDiagnostic.passRate = 0.4545`
- `passedBlocks = 1`
- `failedBlocks = 15`
- `translationFailureBreakdown = { modelOutputFailure: 2, ocrInputSuspect: 10, translationLanguageQualityFailure: 3 }`
- `likelyRuleFalseFailureBlocks = []`

当前融合结果的问题不是“覆盖绘制失败”或“规则太严”，而是候选层仍保留了一些明显的重复/碎片：

- `#8` 已有较完整的 `THE SUGGESTION WAS OVERRULED...`，但 `#9` 又保留了同区域的 `THE SUGSESTION WAS OVERPULED, AND IT WAS DECIDED` 碎片。
- `#5` 已有 `I SAID IT'S JUST SPECIAL TRAINING... PLAY ONLINE...`，但 `#11 PLAY ONLING...` 和 `#12 JUST` 仍作为低信息 source-only 块进入主流程。
- `#13` 和 `#14` 都指向 `-02 AT LEAST... SENPAI'S LOGIC` 附近，其中 `#14` 是重复残片。
- `#10 What are you talking about?` 已比 v9 改善，但仍需要确保不会被重复/碎片规则误删。

v6-v9 Koharu 对齐报告的下一步路线是：先做 bubble-first + whole-page 融合，再改进气泡候选分割，再把 OCR 主输入推向 text region crop。v1.0 已完成第一步，所以 v1.1 应收敛第二步的最小可交付：融合后候选去重/碎片拒绝 + 气泡候选分割审计，不做大规模架构替换。

## 目标
实现一个 ground-truth-free 的融合后清理和气泡分割审计层：

1. 在 `fuseMangaProbeBlocks(...)` 之后或其中新增二次清理，拒绝明显重复、被包含、低信息、低面积且被其他候选覆盖的碎片块。
2. 清理逻辑只使用 bbox、bubbleID、source、文本相似度、文本长度、词数、OCR 质量启发、候选来源和候选间覆盖关系，不得使用 `test/1.ground_truth.json` 做选择。
3. 保留 v1.0 已证明必须保留的真实内容：
   - `Let's Battle!`
   - `What are you even talking about?`
   - `We need to get results at this tournament to save the gaming club from being disbanded.`
4. 优先压掉当前重复/碎片块，重点观察：
   - `THE SUGSESTION WAS OVERPULED, AND IT WAS DECIDED`
   - `PLAY ONLING...`
   - `JUST`
   - `-02 AT LEAST... 2EN-` 残片
5. 在 `fusionResults` 或新增报告字段中记录每个被拒绝块的理由，例如 `containedByHigherQualityBlock`、`lowInformationSourceOnly`、`duplicateWithinBubble`、`overlapsSelectedLongerText`、`fragmentOfSelectedCandidate`。
6. 对气泡候选分割补充审计，不要求本轮强行改出复杂 watershed，但至少要能在报告里解释大气泡/相邻气泡的问题：
   - 每个 bubble 的 bbox、source、area、confidence。
   - bubble 内 selected/fused block 数。
   - 多块同 bubble 的分区情况。
   - 是否存在同 bubble 内高度重叠或文本重复候选。
   - 是否存在明显过大 bubble 覆盖多个语义块的风险。
7. 如果实现了保守的气泡候选拆分，只允许在有强回归保护时启用；否则先作为诊断字段，不替换主流程。
8. 更新报告和文档，让 Agent C 能直接判断本轮是“候选清理/分割审计收益”，而不是 OCR 或翻译模型收益。

## 非目标
本轮不要做这些事：

- 不要更换内置 Gemma 270M，不要下载、提交或默认切换新模型。
- 不要接入 PaddleOCR、Core ML OCR、Koharu Rust/Candle、外部检测模型或新网络依赖。
- 不要把 deterministic correction 纳入 `finalTextUsedForTranslation` 主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要用 ground truth 做生产候选选择、排序、去重、拒绝或气泡拆分。
- 不要为了降块数跨气泡强行合并。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严。
- 不要只因为 `totalBlocksDetected` 降低就宣布成功；必须证明真实内容没有丢。

## 实现步骤
### 1. 先做代码级诊断，不急着改规则
先从当前 `output/probe_report.json` 和 `fusionResults` 手工列出：

- selected source-only 候选。
- 与其他 selected 候选 bbox 高重叠的 source-only 候选。
- 同 bubbleID 内文本相似或被包含的候选。
- 文本词数少于 2、字符数很短、或只是一段长句中的单词/残片的候选。

把这些观察写进实现过程或最终回复。不要只看覆盖图猜。

### 2. 新增融合后清理函数
建议在 `TranslationSessionStore` 中新增一个纯函数式步骤，命名可自行调整：

```text
fused blocks + fusionResults
  -> inspect candidate overlap / containment / text inclusion
  -> reject duplicate or fragment selected blocks
  -> reindex remaining blocks
  -> rewrite fusionResults with rejection reasons
```

清理规则建议：

- 如果一个 source-only 候选 bbox 大部分落在另一个已选候选 bbox 内，且文本词集合大部分被另一个候选覆盖，拒绝较短者。
- 如果两个候选同 `bubbleID`，bbox IoU 或 overlap ratio 高，且一个文本明显是另一个文本的前缀、后缀、子串、词子集或 OCR 轻微变体，拒绝信息量更低者。
- 如果候选词数 `< 2` 或字符数 `< 8`，且不是已知真实短句模式，默认拒绝；短句保留必须有明确理由，例如 bbox 独立、没有被其他块覆盖、文本有足够拉丁字母和标点结构。
- 对未归属 `bubbleID = nil` 的短句要保守：`LET'S / BATTLER!` 这类 whole-page 独有真实内容必须保留，不能用“未归属”一刀切删除。
- 不要把 `groundTruthMatch`、`bestGroundTruthIndex`、`ocrGroundTruthSimilarity` 放进拒绝条件。

### 3. 扩展报告字段
优先复用 `MangaOverlayFusionResult.rejectedCandidates` 和 `MangaOverlayFusionCandidate.rejectionReason`。如果现有结构不够，新增轻量 Codable 字段，例如：

- `postFusionCleanupApplied`
- `postFusionRejectedBlockCount`
- `postFusionRejectedBlocks`
- `postFusionCleanupWarnings`
- `duplicateSuppressionReason`
- `containedByFusedBlockIndex`
- `fragmentOfFusedBlockIndex`

报告必须回答：

- 清理前有多少 fused blocks。
- 清理后有多少 fused blocks。
- 每个被移除块原 index、source、bubbleID、text、bbox、原因。
- 是否保留了 v1.0 的三条关键真实内容。
- 是否存在因规则不确定而保留的可疑块。

### 4. 补充气泡分割审计
在 `MangaOverlayBubbleGeometryDiagnostics` 或新增字段中补充审计信息，目标是解释“为什么某些相邻气泡会混在一起”，而不是本轮必须彻底解决：

- 每个 bubble 的 fused block indexes。
- 每个 bubble 的 selected block count。
- 每个 bubble 内候选 bbox overlap / containment 风险。
- 过大 bubble 风险：area、宽高、是否覆盖多个 selected blocks、是否同时含长句和短问句。
- `bubbleSplitCandidate` 诊断：只写报告，不默认改变主流程。

如果你实现保守拆分，必须满足：

- 只基于 OCR seed 分布、白色连通域局部切缝、bbox 投票或候选间几何，不使用真值。
- 默认 feature flag 或局部函数可回退。
- 重新验证不会丢 `Let's Battle!`、`What are you even talking about?`、`We need...`。
- 如果块数或未匹配数明显变差，回退拆分实现，只保留诊断。

### 5. 不破坏 v1.0 融合收益
本轮成功标准不是“块越少越好”，而是减少噪声同时保持真实覆盖。清理后应继续：

- `configuration.currentBlockSource = fusedWholePageBubble`，或明确写成 `fusedWholePageBubblePostCleaned` 并在文档同步解释。
- 保留 `frameworkComparison` 原始 whole-page/bubble-first 对照。
- 保留 `fusionComparison` 并保证 `consistencyPassed = true`，除非有更严格的新一致性字段且解释清楚。
- 保留失败块绘制和明细，不能静默隐藏翻译失败块。

- 融合结果不能丢 `What are you even talking about?`。

## 风险和禁止项
- 清理碎片的最大风险是误删短真实文本。短句删除必须极保守，尤其是未归属的 `Let's Battle!`。
- 同 bubble 内重复不等于一定噪声；漫画同一气泡可能有多行真实文本。拒绝时要用 bbox 覆盖关系和文本包含关系一起判断。
- 气泡分割实验 v7 已有负面记录：粗暴 seed 分裂和小框优先会拆碎正常块。若本轮重试，必须有回退开关和回归证据。
- OCR/翻译质量仍受 Gemma 270M 限制。即使候选清理成功，`passedBlocks` 可能仍低；不要把模型失败算作本轮候选清理失败。
- 任何评估数字都以本轮重新导出的 `output/` 和 `metrics/version_history.csv` 为准，不使用 README 旧数字验收。

## 本轮目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.20-reading-order-structure-audit
```

本轮做一个小步、可验证、可回退的算法结构优化：新增 Koharu 式 `TextBoxes -> BubbleMask -> OcrText -> Translation` 之间的阅读顺序、气泡归属和结构计划审计报告。该报告只使用现有 AITRANS 探针内部产物，不依赖真实 `test/koharu_artifacts/`，不替换主流程 OCR、翻译、覆盖图或通过判定。

建议新增 report 名称：

```text
readingOrderStructureAuditReport
```

它的核心问题是：

```text
当前 fused blocks 的顺序、bubbleID、bbox、safe layout、TextBox / SegmentMask proxy、post-fusion cleanup 证据，
是否已经足以构成一个稳定的 Koharu 式页面结构计划？
如果不足，瓶颈是阅读顺序、气泡归属、气泡内多块分割、重复/碎片风险，还是 decorative / dialogue 类型边界？
```

## 风险和禁止项
- 风险：阅读顺序启发式容易把漫画视觉顺序误当自然语言阅读顺序。本轮只做审计，不改主流程。
- 风险：同 bubble 多块不等于过分割，可能是同一气泡内多个句子或相邻气泡 mask 粗糙导致。不要自动合并。
- 风险：`groundTruthType` 对固定测试图有用，但不能迁移到真实产品图。任何依赖真值的判断都必须保留在 diagnostic-only。
- 风险：`ci-fast` 跳过部分 full 诊断，report builder 必须能在缺少 full-only report 时优雅降级，用 `missing` / `weak` / note 表示，而不是崩溃。
- 禁止合并到 `main`。
- 禁止提交 GGUF 或大模型文件。
- 禁止伪造测试结果或把旧 artifact 当新结果。
- 禁止为了让指标好看删除失败块或隐藏失败块。
- 禁止让失败块从覆盖图消失；失败块仍必须显示 `翻译失败 + OCR 原文` 并保留失败原因。

## 当前判断
v1.28 `koharuArtifactConvergenceReport` 已把 Koharu canonical artifact 差距收敛到几个未闭合工作项：

- `WI-translation-model-floor-comparison`
- `WI-render-regression-lock`
- `WI-external-artifact-optional-handoff`

v1.29 已执行 `WI-translation-model-floor-comparison`，把 clean text baseline、strict prompt 变体、noisy block 翻译失败和 Koharu convergence 关联起来。本轮优先执行第二个可在 AITRANS 自有探针内完成的工作项：

```text
WI-render-regression-lock
```

原因：

- Koharu 的后半链路不是只画一个 bbox，而是 `BubbleMask -> BubbleIndex -> RenderedSprites -> FinalRender`：用气泡实例 mask / safe layout / sprite 非透明像素碰撞检查锁住最终覆盖效果。
- AITRANS 已有 `safeLayoutRect`、`maskSafeRect`、`renderCollisionChecked`、`renderMaskCollisionChecked`、`glyphMaskFillRects`、`backgroundFillApplied`、失败块覆盖和 PNG 输出，但这些证据分散在 block、diagnostics、BubbleMask / SegmentMask scoreboard 和 convergence report 中。
- v1.28 convergence 当前只把 `WI-render-regression-lock` 标为 open，没有专门的 report 把 RenderedSprites / FinalRender 阶段的回归不变量、逐块状态、PNG 可用性、失败块覆盖契约和 Koharu 对齐差距收束起来。
- `WI-external-artifact-optional-handoff` 仍受真实 `test/koharu_artifacts/` 缺失阻塞，本轮不应伪造 external artifact。

本轮仍是 report-only / diagnostic-only。不得改变 overlay renderer、safe rect 算法、glyph mask、背景填充、主 OCR、主翻译、`blockPassed` 或 PNG 绘制行为。

## 本轮目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.30-render-regression-lock
```

新增一个 AITRANS 自有探针驱动的 Koharu 渲染阶段回归锁报告：

```text
koharuRenderRegressionLockReport
```

报告目标：

1. 聚合现有 final blocks、render diagnostics、safe layout、BubbleMask scoreboard、SegmentMask scoreboard、structure action candidate、Koharu convergence、输出 PNG 文件状态，形成 RenderedSprites / FinalRender 阶段的回归锁。
2. 明确哪些渲染能力已经稳定：失败块仍绘制、无未解决 overflow、无截断、mask collision resolved、safeLayoutRect 存在、核心 PNG 非空、glyph 清字边界没有越权改主流程。
3. 明确哪些仍是 Koharu 差距：没有真实 BubbleMask distance transform、没有真实 RenderedSprites artifact、没有字体 / 方向 / 颜色预测、没有真实 inpainting，只是 AITRANS native/proxy 渲染保护。
4. 把 `WI-render-regression-lock` 从 v1.28 的 open work item 推进为 `closedReportOnly` 或 `openRenderIssueDetected`，并联动 `koharuArtifactConvergenceReport`。
5. 继续用 AITRANS 自己的 probe 输出分析 OCR 准确率、气泡归属 / 分割、翻译失败分类、覆盖渲染和结构瓶颈，但不要把渲染锁伪装成 OCR 质量提升。

- `renderStatus` / `recommendedNextAction` 不得使用 ground truth 相似度决定；OCR 相似度只能进入 `evaluationSignals`。
- 若某块没有 glyph mask 但背景复杂或未归属，应输出 `glyphMaskMissingButAllowed` 或等价状态，不得把它当成 SegmentMask 真 artifact。
- 如果存在 `renderMaskOverflowPixelCount > 0`、`renderTextTruncated = true` 或 `renderCollisionResolved = false`，该块必须进入 `renderIssueBlocks` 和 gate affected blocks。

## 风险和注意事项
- 当前根 `output/` 是旧快照，不含 v1.28 / v1.29 / v1.30 新字段；不要用它判断新报告缺失。v1.30 的可信验收看本 PR 的云端 artifact。
- render lock 的价值是保护覆盖渲染稳定性和 Koharu FinalRender 阶段契约，不代表 OCR 准确率、气泡分割或翻译质量提升。
- 如果发现 render issue，本轮只报告和联动 convergence，不自动修 renderer；修 renderer 应另开后续任务。
- 失败块覆盖是硬规则：任何 `blockPassed = false` 的块都不能从覆盖图或 JSON 明细中静默消失。
- `ci-fast` 不产出 contact sheet 是正常情况，不要把缺 contact sheet 当失败；full 模式才检查完整诊断 PNG。
- 输出文件检查不要依赖开发机仓库根 `output/`，App 只认沙盒输出和 retained file 信息，Agent C 再核对 Actions artifact 实际文件。

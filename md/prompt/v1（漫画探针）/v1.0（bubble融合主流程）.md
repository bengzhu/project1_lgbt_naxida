# AITRANS Agent B 提示词：v1.0（bubble融合主流程）

## 版本号
v1.0（漫画探针 / bubble-first + whole-page 融合主流程）

## 版本分配依据
这是 v6-v9 Koharu 对齐后的第一个实现任务。v6 已固定诊断解码，v7 已排除底部问题主要靠 crop 放宽解决，v8 已证明 bubble-first 不能直接独占主流程，v9 已证明 Vision `customWords` 和确定性纠错不能直接救主流程。因此本轮进入新的漫画探针阶段 v1.0：做可回退的 bubble-first + whole-page 融合候选源。

## 背景
当前真实基线以最新 `output/probe_report.json`、`output/clean_text_diagnostic.json` 和 `metrics/version_history.csv` v9 行为准：

- `totalBlocksDetected = 14`
- `groundTruthMatchedBlocks = 10`
- `groundTruthUnmatchedBlocks = 4`
- `averageCoreDialogueOCRSimilarity = 0.6131`
- `averageDecorativeOCRSimilarity = 0.8000`
- `frameworkComparison.wholePage.accuracyVsGroundTruth = 0.6131`
- `frameworkComparison.bubbleFirst.accuracyVsGroundTruth = 0.7397`
- `frameworkComparison.blocksFoundByBoth = 8`
- `frameworkComparison.blocksOnlyInWholePage = ["Let's Battle!"]`
- `frameworkComparison.blocksOnlyInBubbleFirst = ["What are you even talking about?", "We need to get results at this tournament to save the gaming club from being disbanded."]`
- `frameworkComparison.matchedGroundTruthUnionCount = 11`
- `frameworkComparison.consistencyPassed = true`
- `cleanTextDiagnostic.passRate = 0.4545`
- `passedBlocks = 1`
- `failedBlocks = 13`
- `translationFailureBreakdown = { ocrInputSuspect: 10, translationLanguageQualityFailure: 3 }`
- `likelyRuleFalseFailureBlocks = []`

当前结论是：bubble-first 找到了整页路径漏掉或识别更差的真实内容，但整页路径独有的 `Let's Battle!` 也是真实对话，所以不能把 bubble-first 直接替换成唯一主源。下一步应做融合，而不是继续词表、确定性纠错或规则放宽。

## 目标
实现一个可审计、可回退、不用 ground truth 参与生产选择的融合候选源：

1. 保留 whole-page 主路径已有块。
2. 引入 bubble-first 结果作为额外候选。
3. 用 ground-truth-free 信号做去重和选择：bbox IoU、文本相似度、bubbleID、source、OCR 置信度、文本长度、疑似 OCR 损坏特征、是否跨气泡、是否为空或低信息文本。
4. 对 whole-page 和 bubble-first 都覆盖的同一文本区域，只保留一个主翻译输入，并在报告记录另一路候选。
5. 对 bubble-first 独有且质量可信的块纳入融合结果，重点验证当前两条独有真实内容。
6. 对 whole-page 独有且质量可信的块保留，重点不能丢 `Let's Battle!`。
7. 报告中同时保留 whole-page、bubble-first、fused 三套指标和差集，便于 Agent C 验收。
8. 失败块仍必须翻译失败可见、写入明细、绘制到覆盖图。

## 非目标
本轮不要做这些事：

- 不要引入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle 运行时或外部依赖。
- 不要更换内置 Gemma 270M 或下载/提交模型文件。
- 不要把 `test/1.ground_truth.json` 用于生产候选选择、去重、排序或主流程替换；它只能用于报告评估。
- 不要把 deterministic correction 纳入主流程。
- 不要把 Vision `customWords` 当成主要修复路径。
- 不要把 tagged batch translation 替换逐块翻译；当前 batch 格式崩坏，只保留诊断。
- 不要为了提高分数跨气泡强行合并。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit 或语音链路。

## 实现步骤
### 1. 增加融合候选模型
在 `TranscriptModels.swift` 或 `MangaOverlayProbeService.swift` 附近新增轻量 Codable 结构，命名可自行调整，但报告需要表达这些信息：

- fused block index
- selected source：`wholePageOCR` / `bubbleFirst` / `wholePagePreferred` / `bubblePreferred`
- selected text
- selected bbox
- selected bubbleID
- competing candidates
- dedupe reason
- replacement reason
- rejected candidates and reason
- source block index 或 bubble result index

如果已有结构能复用，优先复用，不做大面积类型迁移。

### 2. 实现融合算法
新增一个纯函数式融合步骤，优先放在 `TranslationSessionStore` 或 `MangaOverlayProbeService` 内部，不要把逻辑散到 UI：

```text
wholePage probeBlocks + bubbleComparison.bubbleResults
  -> normalize candidates
  -> ground-truth-free dedupe
  -> choose selected candidate per cluster
  -> append credible source-only candidates
  -> fused probe blocks
  -> fused diagnostics
```

建议规则：

- 两候选 bbox IoU 高，或中心点距离近且文本相似，视为同一候选簇。
- 同一 `bubbleID` 内的候选更容易合并；不同 bubbleID 默认不合并。
- bubble-first 的 `groundTruthMatch`、`bestGroundTruthIndex`、`bestSimilarity` 不能参与选择，只能原样保留作评估字段。
- 优先选择更长、更少明显 OCR 错误、更少乱码、更完整英文词的文本。
- 如果 whole-page 候选短但可信，且 bubble-first 候选明显包含更多完整词，可选 bubble-first。
- 如果 bubble-first 没覆盖 whole-page 真实短句，必须保留 whole-page source-only 候选。
- 对非常短、空、符号化、低信息 bubble-first 文本要拒绝，不要制造噪声块。
- 所有选择和拒绝都写 reason，便于后续查错。

### 3. 不破坏可回退性
保留 whole-page 原路径指标和明细。融合可以成为本轮新的探针主翻译输入，但必须能在报告里看出：

- 原 whole-page blocks 是什么。
- bubble-first candidates 是什么。
- fused blocks 是什么。
- 哪些块从 whole-page 替换为 bubble-first。
- 哪些 bubble-first 独有块被加入。
- 哪些 whole-page 独有块被保留。
- 哪些候选被拒绝。

如果实现中发现融合会让 `Let's Battle!` 丢失，必须停止把融合设为主翻译输入，只保留融合诊断，并在 README/update_log 记录原因。

### 4. 更新报告字段
在 `probe_report.json` 中新增融合相关字段。建议顶层字段名：

- `fusionComparison`
- `fusionResults`
- `configuration.currentBlockSource = "fusedWholePageBubble"` 或类似值

`fusionComparison` 至少包含：

- `wholePage`
- `bubbleFirst`
- `fused`
- `blocksFoundByAll`
- `blocksOnlyInWholePage`
- `blocksOnlyInBubbleFirst`
- `blocksOnlyInFused`
- `fusedFromWholePageCount`
- `fusedFromBubbleFirstCount`
- `fusedAddedBubbleOnlyCount`
- `fusedRetainedWholePageOnlyCount`
- `fusedRejectedCandidateCount`
- `consistencyPassed`
- `consistencyWarnings`

真值匹配只用于这些评估字段，不得反向影响融合选择。

### 5. 更新覆盖和文本输出
确保融合后的实际 `probeBlocks` 继续进入：

- 逐块 deterministic 翻译。
- `translationDecisionTrace`。
- `translationFailureDetail`。
- `applySafeLayoutAndRenderingDiagnostics`。
- overlay 绘制。
- `1_ocr_probe_text.txt`。
- contact sheet。

失败块仍必须显示 `翻译失败 + OCR 原文`，不能静默隐藏。

## 验收标准
必须全部满足：

- build 通过。
- `probe_report.json` 可解析。
- `clean_text_diagnostic.json` 可解析。
- 输出目录仍每轮清理，不能混旧 PNG/JSON。
- 失败块仍保留在 `blocks` 明细和覆盖图中。
- `frameworkComparison.consistencyPassed = true` 继续成立，或若字段被扩展，旧 framework 对比仍能解释。
- 新增 `fusionComparison.consistencyPassed = true`。
- 融合结果不能丢 `Let's Battle!`。
- 融合结果应纳入或清楚解释为什么拒绝这两条 bubble-first 独有真实内容：
  - `What are you even talking about?`
  - `We need to get results at this tournament to save the gaming club from being disbanded.`
- `totalBlocksDetected` 不能无解释暴涨；如超过 16，必须在报告和最终回复说明原因并证明不是噪声。
- `groundTruthMatchedBlocks` 不应低于当前 10；若低于 10，默认视为回归，除非有强证据说明报告口径改变且更正确。
- `averageCoreDialogueOCRSimilarity` 不应低于当前 0.6131；若下降，必须说明具体块和原因。
- `likelyRuleFalseFailureBlocks` 不能被当作放宽规则理由；若仍为 `[]`，最终回复不得声称规则太严格。

目标性收益：

- 理想结果：可信匹配 union 中的 11 条能在 fused 指标中体现，且核心 OCR 相似度高于 whole-page 当前 0.6131。
- 可接受结果：融合诊断完整，但因 ground-truth-free 选择规则过保守而未切主流程；必须明确列出阻塞原因和下一步需要的信号。
- 不接受结果：直接使用 ground truth 选候选、直接 bubble-first 替换、丢掉 whole-page 独有真实内容、或隐藏失败块。

## 风险和禁止项
- 最大风险是为了追求 v9 已知差集，暗中用 ground truth 做选择。不要这么做。
- 第二风险是 bubble-first source-only 候选引入噪声，导致块数暴涨或 overlay 混乱。必须有拒绝阈值和 rejected reason。
- 第三风险是把融合、翻译模型质量和规则误伤混为一谈。报告和最终回复要分别说明 OCR/fusion 指标、clean text 模型指标、translation failure breakdown。
- 不要回滚用户或其他 Agent 的改动。
- 不要伪造探针运行、导出或 JSON 数字。

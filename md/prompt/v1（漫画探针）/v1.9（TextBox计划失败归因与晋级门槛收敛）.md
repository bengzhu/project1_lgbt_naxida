v1.8 的关键结论不是“plan 已可采用”，而是：

- 上游 plan 规模可控，已经做到每块最多 3 个 shadow OCR plan。
- 13 个 block 中有 13 个 shadow candidate 的简单质量分高于 control，但没有任何 `promotableShadowCandidate`。
- `adoptedCount` 仍为 0，说明不能放宽 TextRegion crop 护栏。
- 当前报告能看到 plan、shadow OCR 和 stop reason，但还不能系统回答“到底是几何计划弱、BubbleMask/SegmentMask 证据弱、局部 Vision OCR 退化，还是晋级门槛正确拒绝”。

因此 v1.9 不继续盲目枚举新 crop 变体，也不把 plan 写回主流程；本轮目标是把 v1.8 生成的 plan 和 shadow OCR 结果做成更清晰的失败归因、晋级门槛解释和下一步决策依据。

## 背景
`md/koharu研究/v6～9work.md` 和 `md/koharu研究/koharu图像识别链路研究.md` 的共同结论是：Koharu 的优势来自结构化中间产物链路，而不是整页 OCR 后不断补丁：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> Translations
  -> Inpainted / RenderedSprites / FinalRender
```

AITRANS 当前已经逐步接近这个方向：

- v1.0：whole-page + bubble-first 融合主流程。
- v1.1：post-fusion cleanup。
- v1.2-v1.7：TextRegion crop、BubbleMask、TextBox / SegmentMask 证据层、crop shadow 实验矩阵。
- v1.8：TextRegion crop 之前生成上游 TextBox plan，并进入 shadow-only 验证。

但当前 TextBox plan 仍缺少 Koharu 式 artifact 的一个重要属性：失败解释必须稳定、可组合、可复用。Agent B 本轮应把 plan 级、candidate 级、block 级的失败原因收敛成明确分类，避免下一轮继续在已证明无收益的 crop 上循环试参。

## 目标
实现一个 ground-truth-free 的 TextBox plan 失败归因和晋级门槛审计层。命名可按现有风格调整，但语义必须清楚，例如：

- `preCropTextBoxPlanFailureReport`
- `textBoxPlanFailureAttributionReport`
- 或扩展 `preCropTextBoxPlanReport` / `cropExperimentReport`，但字段必须能直接表达失败归因。

至少满足：

1. 对每个 pre-crop plan 记录 plan 级失败归因：几何证据、BubbleMask、SegmentMask/glyph、safe rect、保护文本、重复/过宽/过窄、与 sibling block 冲突等。
2. 对每个 shadow OCR candidate 记录 OCR 级失败归因：empty local OCR、raw words lost、word count regression、introduced likely OCR error、same as fused text、local Vision regression、quality gain insufficient。
3. 对每个 block 输出 block 级结论：`promotable`、`controlStillBest`、`localVisionCropNotPromising`、`geometryEvidenceTooWeak`、`segmentEvidenceTooWeak`、`bubbleMaskConflict`、`protectedDiagnosticOnly` 等。
4. 把 `cropExperimentReport.promotedShadowBlocks = []` 解释清楚：每个“看似 betterThanControl”的 candidate 为什么仍不能晋级。
5. 输出全局 breakdown，统计每类失败归因涉及的 block 和 candidate 数量。
6. 在 `1_ocr_probe_text.txt` 中每块新增“为什么没晋级 / 下一步应停止还是继续”的可读摘要。
7. 不改变 `finalTextUsedForTranslation`、主翻译输入、主覆盖图文本、`textRegionCropReport.adoptedCount`。
8. 不使用 `test/1.ground_truth.json` 参与 plan 生成、排序、失败归因、晋级或回退；真值只能用于事后评估。

## 非目标
本轮不要做这些事：

- 不新增 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不更换、下载、提交或默认切换翻译模型。
- 不放宽 TextRegion crop 采用规则，不制造 `adoptedCount > 0`。
- 不把 `bestShadowCandidate`、pre-crop plan OCR 或局部 OCR 结果写入 `finalTextUsedForTranslation`。
- 不改变 `fusedWholePageBubble` 主流程、post-fusion cleanup、失败块绘制或翻译质量判定。
- 不把 deterministic correction、tagged batch translation 或 clean text diagnostic 替换主流程。
- 不为了提高数字跨气泡合并。
- 不把渲染/清字改善描述成 OCR 准确率提升。
- 如果 `likelyRuleFalseFailureBlocks = []`，不要声称规则太严格。

## 实现步骤
### 1. 先做 v18 基线核查
实现前从当前输出提取并写入最终回复：

- 顶层数字：13 blocks、13 matched、0 unmatched、core/decorative OCR similarity。
- TextRegion crop：13 / 10 / 0 adopted / 13 rejected。
- pre-crop plan：37 plans、29 eligible、selected blocks、stopped blocks。
- crop experiment：48 candidates、13 controls、36 OCR succeeded、13 betterThanControl、0 promoted。
- `variantBreakdown` 中各 preCrop variant 的 attempted / succeeded / better / empty / rawWordsLost。
- 每个 stopped block 的 `promotionVerdict` 和 `stopReasons`。
- 三条保护内容是否仍在明细中：`Let's Battle!`、`What are you even talking about?`、`We need to get results...`。

### 2. 新增或扩展失败归因模型
推荐新增 Codable / Sendable 模型。字段名可按现有风格调整，但必须表达以下语义：

```swift
struct MangaOverlayTextBoxPlanFailureDiagnostic: Equatable, Codable, Sendable {
    var planID: Int
    var blockIndex: Int
    var variantName: String
    var planFailureCategory: String
    var geometryReasons: [String]
    var bubbleMaskReasons: [String]
    var segmentMaskReasons: [String]
    var safetyReasons: [String]
    var protectionReasons: [String]
    var candidateID: Int?
    var ocrFailureCategory: String?
    var ocrReasons: [String]
    var promotionBlockers: [String]
    var recommendedNextAction: String
    var notes: [String]
}

struct MangaOverlayTextBoxPlanFailureBlockSummary: Equatable, Codable, Sendable {
    var blockIndex: Int
    var verdict: String
    var primaryFailureCategory: String
    var planIDs: [Int]
    var candidateIDs: [Int]
    var promotionBlockers: [String]
    var recommendedNextAction: String
    var notes: [String]
}

struct MangaOverlayTextBoxPlanFailureReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var evaluatedBlockCount: Int
    var evaluatedPlanCount: Int
    var evaluatedCandidateCount: Int
    var planFailureBreakdown: [String: Int]
    var ocrFailureBreakdown: [String: Int]
    var promotionBlockerBreakdown: [String: Int]
    var stopRecommendedBlocks: [Int]
    var continueGeometryResearchBlocks: [Int]
    var candidatePromotionBlockedBlocks: [Int]
    var blockSummaries: [MangaOverlayTextBoxPlanFailureBlockSummary]
    var diagnostics: [MangaOverlayTextBoxPlanFailureDiagnostic]
    var notes: [String]
}
```

如果选择直接扩展现有 report，也必须保留等价信息，并写入 `probe_report.json` 顶层或清楚嵌套位置。

### 3. 建立失败归因分类
分类必须不使用 ground truth。建议最少覆盖：

plan 级：

- `protectedDiagnosticOnly`
- `geometryEvidenceTooWeak`
- `bubbleMaskConflict`
- `lowBubbleCoverage`
- `missingSafeRectCoverage`
- `segmentEvidenceTooWeak`
- `textBoxTooWide`
- `textBoxTooTight`
- `siblingOverlapRisk`
- `diagnosticOnlyNoShadowOCR`
- `eligibleButNeedsShadowOCR`

candidate / OCR 级：

- `emptyLocalOCR`
- `rawWordsLost`
- `wordCountRegression`
- `sameAsFusedText`
- `introducedLikelyOCRError`
- `localVisionRegression`
- `qualityGainInsufficient`
- `betterButUnsafe`
- `controlStillBest`
- `shadowOnlyNotAdopted`

block 级 recommended action：

- `stopProtectedBlock`
- `stopLocalVisionCrop`
- `stopUntilSegmentMaskImproves`
- `stopUntilBubbleMaskImproves`
- `continueGeometryPlanning`
- `candidateNeedsPromotionGateReview`
- `candidateGoodButModelTranslationStillWeak`
- `noActionControlBest`

注意：`betterThanControl = true` 不等于可晋级。必须显式说明为什么被 blocker 拦下，例如 raw words lost、word count regression、segment evidence weak、bubble mask conflict、quality gain 小于门槛。

### 4. 把 plan 和 crop candidate 串起来
当前 `cropExperimentReport.candidates[].sourceStack` 包含 `planID:N`。本轮需要利用该关系，把每个 plan 与其 shadow OCR candidate 对齐：

- plan 未进入 shadow OCR：归因为 plan 级过滤或保护。
- plan 进入 shadow OCR 且 candidate empty：归因为 local Vision OCR 失败。
- candidate 有文本但丢 raw words：归因为局部 OCR 退化。
- candidate 分数高于 control 但不晋级：列出所有 blocker。
- control 仍最好：说明没有必要继续同类 crop。

若发现当前 `sourceStack` 的 `planID` 解析不稳定，可以新增显式 `sourcePlanID: Int?` 字段到 `MangaOverlayCropExperimentCandidate`，但必须保持旧字段兼容。

### 5. 收敛晋级门槛说明
不要放宽门槛。要把当前门槛变成可审计文本和 JSON：

- `wordPreservationRatio >= 0.80`
- `qualityDelta > 0.08`
- `rawWordsLost` 不存在
- `introducedLikelyOCRError` 不存在
- `sameAsFusedText` 不存在
- `bubbleMaskConflict` 不存在
- `segmentOutsideBubbleRisk` 不存在
- protected / decorative block 不允许晋级

对每个 best shadow candidate 输出 `passedPromotionChecks` / `failedPromotionChecks` 或等价字段。

### 6. 更新 TXT 输出
更新 `output/1_ocr_probe_text.txt` 生成逻辑，使每块都能读到：

- plan failure verdict。
- best shadow 为什么没有晋级。
- primary failure category。
- promotion blockers。
- recommended next action。
- 是否应该继续 Koharu 式几何优化，还是停止此块 crop 尝试。

示例语义：

```text
textBoxPlanFailure: primary=localVisionCropNotPromising blockers=rawWordsLost|wordCountRegression action=stopLocalVisionCrop
promotionChecks: passed=ocrSucceeded|qualityDelta failed=rawWordsLost|wordPreservationBelowThreshold
```

### 7. 更新文档和指标
如果本轮只新增失败归因字段，仍属于漫画探针报告模型修改，必须同步：

- `README.md`：近期优化记录追加 v19 / v1.9 关键数字和结论。
- `update_log.md`：追加版本记录、关键结论、遗留问题。
- `md/flow/flow.md`：把 TextBox plan failure attribution 放在 crop experiment 之后、主翻译之前或报告汇总处。
- `md/flow/flowchart.md`：同步流程图。
- `md/test/test.md`：若新增字段成为基线，更新 Stage Regression 数字。
- `metrics/version_history.csv`：用脚本 append-only 追加 v19 行，不覆盖历史。

如果实现中发现字段语义需要调整 v1.8 文档中的表述，也要同步修正。

## 验收标准
通过条件：

1. `probe_report.json` 能直接看到 TextBox plan 失败归因报告，或在现有 report 中看到等价结构。
2. 失败归因能从 plan/candidate 明细实时汇总，不是手写结论。
3. plan 和 candidate 能通过 `planID` 或显式字段稳定关联。
4. 每个 best shadow candidate 都能解释为什么晋级或未晋级。
5. `promotedShadowBlocks = []` 时，报告必须列出具体 blocker，而不是只写无晋级。
6. `finalTextUsedForTranslation`、主译文、覆盖图主输入、`textRegionCropReport.adoptedCount` 不因本轮改变。
7. 候选排序、失败归因、promotion checks 均不使用 ground truth。
8. 三条保护文本仍保留：`Let's Battle!`、`What are you even talking about?`、`We need to get results...`。
9. `frameworkComparison.consistencyPassed = true`、`fusionComparison.consistencyPassed = true` 仍成立。
10. `1_ocr_probe_text.txt` 能直接读出每块 failure category、promotion blockers 和 next action。
11. README、update_log、flow、flowchart、test、version_history 与最新输出同步。

## 风险和禁止项
- 最大风险是把“失败归因报告”写成主流程采用逻辑。本轮只解释，不采用。
- 第二风险是为了出现 promoted block 而放宽门槛。禁止这么做。
- 第三风险是从真值或 OCR 相似度反推失败分类。真值只能用于事后统计。
- 第四风险是分类过碎导致不可读。必须有 block 级 primary category 和全局 breakdown。
- 第五风险是把翻译失败归因错给 OCR。clean text 仍只有 `0.4545`，Gemma 270M 不是翻译质量基准。

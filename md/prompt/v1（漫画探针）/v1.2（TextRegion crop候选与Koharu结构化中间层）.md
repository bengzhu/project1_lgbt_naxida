# AITRANS Agent B / Koharu 提示词：v1.2（TextRegion crop 候选与结构化中间层）

## 版本号
v1.2（漫画探针 / TextRegion crop 候选与 Koharu 结构化中间层）

## 版本分配依据
v1.0 已完成 whole-page + bubble-first 融合主流程，v1.1 已完成 post-fusion 重复碎片压缩和气泡分割审计。当前主流程能保留 `Let's Battle!`、`What are you even talking about?`、`We need to get results at this tournament to save the gaming club from being disbanded.`，并把融合块从 16 压到 13。

但 v11 当前瓶颈仍是 OCR 文本质量和 Gemma 270M 翻译能力，不是覆盖绘制、候选去重或规则过严。结合 `md/koharu研究/v6～9work.md` 和 `md/koharu研究/koharu图像识别链路研究.md`，下一步不应继续调翻译规则或换模型，而应向 Koharu 的 `TextBoxes -> OCR crop -> OcrText` 思路靠近：先把当前融合块表达成可审计的 TextRegion 中间层，对每个 region 做更受气泡约束的 crop OCR 候选，对比 whole-page / bubble-first / adaptive crop 的文本质量，再在强护栏下允许局部采用更好的 crop OCR 文本。

本轮是 v1.2：补 TextRegion crop 候选层。它不是引入新 OCR 模型，也不是把确定性纠错切主流程。

## 目标
实现一个可审计、可回退、ground-truth-free 的 TextRegion crop OCR 候选层：

1. 为融合后的 13 个主块生成 `TextRegion` 级报告字段，记录 region bbox、bubbleID、source、seed block、region crop bbox、padding、clamp、方向、候选文本和采用决策。
2. 让 crop OCR 更像 Koharu 的 TextBoxes crop：OCR 只在每个 TextRegion 的局部 crop 上做候选识别，而不是继续只依赖整页 observations。
3. crop 边界必须受所属 bubble 限制；没有 bubbleID 的块保守回退到 block bbox 扩张，不能跨进浏览器 UI、广告或底部导航。
4. 对每块记录多路文本候选：
   - `wholePageText`
   - `bubbleFirstText` 或融合来源文本
   - `adaptiveCropText`
   - 新增 `textRegionCropText`
   - `selectedTextForTranslation`
   - `selectionReason`
   - `rejectionReasons`
5. 允许在强护栏下采用 `textRegionCropText` 作为 `finalTextUsedForTranslation`，但选择只能用 ground-truth-free 信号：raw words 保留率、词数、拉丁字符比例、乱码/数字异常、bbox/crop 是否被 bubble clamp、与原主文本的相似度、是否明显空/短/符号化。
6. 如果 crop 候选更差，必须保留原 `fusedWholePageBubble` 文本并写明回退原因。
7. 报告必须能回答：本轮 crop OCR 改善了哪些块、恶化了哪些块、采用了哪些块、拒绝了哪些块、有没有丢 v1.1 的三条保护文本。
8. 保持失败块显示、报告明细和覆盖图绘制规则不变。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle 或网络依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于生产候选选择、排序、替换、回退或 crop 采用决策。
- 不要把 deterministic correction 纳入主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要继续调翻译通过规则来掩盖 OCR 错误。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严格。
- 不要把本轮称为 mask/inpainting 实现；这轮只做 TextRegion crop 候选和报告。

## 实现步骤
### 1. 先做基线核查
实现前从当前 `output/probe_report.json` 手工或脚本列出：

- 13 个块的 `index`、`bubbleID`、`groundTruthMatch`、`ocrGroundTruthSimilarity`、`failureCategory`、`finalTextUsedForTranslation`。
- `fusionComparison.postFusionCleanup.rejectedBlocks`。
- `bubbleGeometry.bubbleAudits` 中 `bubbleSplitCandidate = true` 的 bubble。
- `output/1_ocr_probe_text.txt` 中 adaptive/fixed crop 与 final 文本差异。

把观察写入最终回复。不要只看覆盖图猜。

### 2. 新增 TextRegion crop 报告模型
在 `TranscriptModels.swift` 中新增轻量 Codable 结构，命名可自行调整，例如：

```swift
struct MangaOverlayTextRegionCropDiagnostic: Equatable, Codable, Sendable {
    var blockIndex: Int
    var bubbleID: Int?
    var source: String
    var seedBBox: [Double]
    var regionBBox: [Double]
    var cropBBox: [Double]
    var cropClampedByBubble: Bool
    var paddingX: Double
    var paddingY: Double
    var orientationHint: String
    var wholePageText: String
    var fusedTextBeforeCrop: String
    var textRegionCropText: String?
    var selectedText: String
    var adopted: Bool
    var selectionReason: String
    var rejectionReasons: [String]
    var rawWordPreservationRatio: Double
    var candidateQualityScore: Double
}
```

可放在顶层报告，也可挂在每个 `MangaOverlayProbeBlock` 上。优先选择最小侵入方案，但 `probe_report.json` 和 `1_ocr_probe_text.txt` 必须能看见。

### 3. 实现 TextRegion crop OCR 候选
建议在 `MangaOverlayProbeService` 增加一个新方法，或者复用并扩展 `recognizePreprocessedText(...)`：

```text
fused block + bubble geometry + source image
  -> build TextRegion bbox
  -> compute region-aware padding
  -> clamp crop to assigned bubble bbox or content rect
  -> run Vision OCR on crop
  -> map text candidate back to block diagnostic
```

规则建议：

- TextRegion seed bbox 默认来自 post-fusion block bbox。
- 有 bubbleID 时，crop 不能超出 bubble bbox；如果 bubble audit 标为过大，只做 clamp，不在本轮拆分。
- 无 bubbleID 时，crop 只能在内容区内扩张，且扩张比例更保守。
- 横排文本 y padding 大于 x padding；窄高文本再考虑竖排 hint，但当前图主要英文横排，不要过度旋转。
- crop OCR 结果为空、词数过少、符号过多、数字异常、拉丁字符过少时直接拒绝。
- 若 crop 文本丢失原主文本的大部分有效词，拒绝并回退原 fused 文本。
- 若 crop 文本补足明显 OCR 错字但没有引入新乱码，可采用。

### 4. 选择逻辑必须 ground-truth-free
新增候选选择函数，输入原 fused 文本和 crop 文本，输出采用/拒绝和原因。禁止使用：

- `groundTruthMatch`
- `bestGroundTruthIndex`
- `bestGroundTruthText`
- `ocrGroundTruthSimilarity`
- `ocrLegacySimilarity`
- `wordOrderPreserved`
- `test/1.ground_truth.json` 任意内容

可用信号：

- 词数变化。
- raw words preservation ratio。
- 字母/数字/标点比例。
- OCR 错误启发，例如 `TOUPNAMENT`、`PEW DAYS`、`DONS`、`TRAININS` 这类疑似坏词只能作为质量扣分，不要硬编码真值替换。
- 与原 fused 文本的 normalized similarity。
- crop 是否被 bubble clamp。
- 是否从空/短文本变成长文本。
- 是否从长文本退化成短碎片。

### 5. 强保护 v1.1 成果
本轮不能回归 v1.1：

- `configuration.currentBlockSource` 可以保持 `fusedWholePageBubble`，也可以改为 `fusedWholePageBubbleTextRegionCrop`，但必须同步文档解释。
- `fusionComparison.postFusionCleanup.applied = true` 仍要存在。
- `fusionComparison.postFusionCleanup.blockCountBeforeCleanup = 16` 和 `blockCountAfterCleanup = 13` 的语义不能被无意破坏；如因新逻辑改变，必须解释清楚。
- 三条保护文本不能丢：

- `frameworkComparison.consistencyPassed` 和 `fusionComparison.consistencyPassed` 必须继续可解释。
- 失败块仍必须保留在 `blocks`，并在覆盖图显示 `翻译失败 + OCR 原文`。

## 验收标准
必须全部满足：

- build 通过。
- `probe_report.json` 可解析。
- `clean_text_diagnostic.json` 可解析。
- 输出目录仍每轮清理，不能混旧 PNG/JSON。
- `fusionComparison.postFusionCleanup.applied = true`。
- `fusionComparison.consistencyPassed = true`。
- `frameworkComparison.consistencyPassed = true`。
- `totalBlocksDetected` 不应低于 13；若低于 13，必须证明没有丢真实内容。
- `groundTruthMatchedBlocks` 不应低于 13；若口径改变，必须说明具体原因。
- `groundTruthUnmatchedBlocks` 不应高于 0；若高于 0，默认视为回归。
- `averageCoreDialogueOCRSimilarity` 不应低于 0.7106；若下降，必须列出下降块和原因。
- `fusion.fused.accuracyVsGroundTruth` 不应低于 0.7384；若下降，必须解释。
- 三条 v1.1 保护文本必须保留，`missingKeyTexts = []`。
- 新增 TextRegion crop 诊断必须记录 adopted/rejected 数量和每块理由。
- 采用 crop 文本的块必须有 ground-truth-free 理由；不能只因为真值相似度更高而采用。
- 如果没有任何 crop 候选被采用，也可以验收，但必须说明“诊断收益”是什么，以及下一步为什么不应强行替换。
- `likelyRuleFalseFailureBlocks = []` 时，最终回复不得声称规则太严格。

## 风险和禁止项
- 最大风险是 crop OCR 看似更干净但漏词，导致翻译输入更短。必须用 raw words preservation 和词数护栏防止。
- 第二风险是 bubbleID 4/6/7 过大，crop clamp 到大 bubble 仍可能串扰。本轮只记录风险，不默认拆分。
- 第三风险是为了提高指标误用 ground truth。任何生产选择逻辑中出现真值字段都算失败。
- 第四风险是把 TextRegion crop 与 deterministic correction 混在一起。本轮只比较 OCR crop，不把纠错候选切主流程。

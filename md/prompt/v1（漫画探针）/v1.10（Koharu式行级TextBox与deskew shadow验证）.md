## 背景
`md/koharu研究/koharu图像识别链路研究.md` 说明 Koharu 的 OCR 不是直接扫整页，而是：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
```

其中和本轮最相关的能力是：

- OCR 只在 TextBox crop 上跑。
- TextBox 可以结合 line polygon、方向、字号做动态 padding。
- 对倾斜或局部文字行可以做 line-level crop / warp / deskew，而不是只用整块 bbox。
- SegmentMask 和 BubbleMask 用于约束 TextBox，避免吃到相邻气泡、背景线条或 sibling block。

AITRANS v1.8/v1.9 已经有 `preCropTextBoxPlanReport`、`cropExperimentReport` 和 `textBoxPlanFailureReport`，但 plan 仍以 block 级 bbox 为主。v19 输出显示：

- block 1：best shadow 比 control 略好，但 `qualityDelta = 0.051`，只差晋级门槛；失败 blocker 只有 `qualityDeltaBelowOrEqual0.08`。
- block 6：best shadow 比 control 略好，但仍有 `qualityDeltaBelowOrEqual0.08` 和 `wordPreservationRatioBelow0.80`，局部 OCR 混入或漏掉词。
- block 10：best shadow 比 control 略好，但仍有 `qualityDeltaBelowOrEqual0.08` 和 `wordPreservationRatioBelow0.80`，容易吃到 sibling 文本。

这三个块不是“可以直接采用”，而是“值得用更细粒度 TextBox 证据再验证一次”。本轮要让报告回答：行级切分、局部 deskew、方向化 padding 是否能让 `[1, 6, 10]` 的 shadow OCR 候选通过现有 promotion gate；如果不能，也要给出停止依据。

## 目标
实现一个 shadow-only 的 Koharu 式行级 TextBox / deskew 实验层，建议命名为：

- `lineTextBoxPlanReport`
- `lineCropExperimentReport`
- 或扩展现有 `preCropTextBoxPlanReport` / `cropExperimentReport`，但字段语义必须清楚，不能把 line-level 诊断伪装成主流程采用。

至少满足：

1. 仅对 `textBoxPlanFailureReport.continueGeometryResearchBlocks = [1, 6, 10]` 或等价动态集合生成 line-level shadow plans。
2. 每个目标 block 生成不超过 4 个 line-level plan，控制实验规模。
3. line-level plan 使用 ground-truth-free 信号：现有 OCR 行、bbox、bubbleID、BubbleMask coverage、glyph/SegmentMask proxy、safe rect、sibling overlap、文本行数和方向估计。
4. 增加至少三类候选：
   - `lineTightTextBox`：按 OCR 文本行和 seed bbox 高度切分的紧框。
   - `lineBandTextBox`：横向/纵向带状候选，用于避免吃到 sibling block。
   - `deskewProbeTextBox`：轻量旋转/deskew 诊断候选，角度范围必须保守，例如 `[-3, 0, 3]` 或只在 report 中记录可用角度，不做昂贵全局搜索。
5. 所有 line-level candidate 只进入 shadow OCR 与报告，不写回 `finalTextUsedForTranslation`。
6. 不改变 `textRegionCropReport.adoptedCount`、主覆盖图文本、主翻译输入、post-fusion cleanup 或 `blockPassed` 判定。
7. 如果产生 better-than-control candidate，仍必须通过 v1.9 既有 promotion checks，不能放宽 `qualityDelta > 0.08`、`wordPreservationRatio >= 0.80` 等门槛。
8. 在 `1_ocr_probe_text.txt` 中为 block 1/6/10 输出 line-level 计划、best line candidate、promotion checks、失败 blocker 和下一步建议。
9. 顶层报告必须汇总 `lineLevelTargetBlocks`、`linePlanCount`、`lineCandidateCount`、`ocrSucceededCount`、`betterThanControlCount`、`promotedLineShadowBlocks`、`stoppedAfterLineResearchBlocks`。

## 非目标
本轮不要做这些事：

- 不新增 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不更换、下载、提交或默认切换翻译模型。
- 不把 line-level shadow OCR 写回 `finalTextUsedForTranslation`。
- 不放宽 TextRegion crop、TextBox plan 或 shadow candidate 的晋级门槛。
- 不把 `promotedShadowBlocks` 或 `adoptedCount` 人为做成非空。
- 不对全部 13 个 block 再开大矩阵；只聚焦 v1.9 证明仍值得继续的块。
- 不用 `test/1.ground_truth.json` 生成、排序、筛选、晋级或回退候选。
- 不为了提升数字跨气泡合并。
- 不把 deterministic correction、tagged batch translation 或 clean text diagnostic 替换主流程。
- 不声称规则过严；当前 `likelyRuleFalseFailureBlocks = []`。

### 2. 新增行级计划模型
推荐新增 Codable / Sendable 模型，字段名可按现有风格调整：

```swift

}

struct MangaOverlayLineTextBoxPlanBlockSummary: Equatable, Codable, Sendable {

```

如果直接扩展现有 `preCropTextBoxPlanReport`，必须能明确区分 block-level plan 和 line-level plan，避免 v1.8/v1.9 的统计语义被污染。

### 3. 生成目标 block 的 line-level plan
目标 block 来自 v1.9 failure report：

```text
textBoxPlanFailureReport.continueGeometryResearchBlocks
```

如果该字段不存在或为空，fallback 只能使用 `recommendedNextAction == candidateNeedsPromotionGateReview` 的 block。不要硬编码 ground truth 或 OCR 相似度。

计划生成规则：

- 每个 block 最多 4 个 plan。
- 以 v1.9 best shadow / selected pre-crop plan 为 parent。
- `lineTightTextBox`：根据 seed bbox 和 OCR 行数等分或按已有 line layout 估计子框。
- `lineBandTextBox`：保留整行方向的带状区域，但 clamp 到 bubble/safe rect，避免 sibling overlap。
- `deskewProbeTextBox`：只在目标 block 的紧框上做保守角度探针；如果实现成本高，可先只生成角度计划和报告，不做真实旋转 OCR，但必须如实标记 `ocrExecuted = false` 或等价字段。
- plan 的 `eligibleForShadowOCR` 必须要求：
  - 非 protected short text。
  - 非 decorative title。
  - `bubbleMaskConflict` 不存在。
  - `siblingOverlapRatio` 低于阈值，例如 `<= 0.20`。
  - `evidenceScore >= 0.46`。

### 4. 接入 shadow OCR 实验
推荐新增 `lineCropExperimentReport`，不要混淆 v1.8/v1.9 的 `cropExperimentReport`：

```swift
    var targetBlocks: [Int]

```

实现可复用 `MangaOverlayCropExperimentCandidate`、`cropExperimentCandidate(...)`、`cropExperimentVerdict(...)` 和 v1.9 promotion checks，但候选 `variantName` 必须以 `lineTextBoxPlan.` 开头，例如：

- `lineTextBoxPlan.lineTightTextBox`
- `lineTextBoxPlan.lineBandTextBox`
- `lineTextBoxPlan.deskewProbeTextBox`

候选必须记录 `sourcePlanID` 或等价字段，能从 report 反查 line plan。

### 5. 维持现有晋级门槛
不要为 v1.10 新开更宽松门槛。line candidate 必须继续满足：

- `ocrSucceeded = true`
- `wordPreservationRatio >= 0.80`
- `qualityDelta > 0.08`
- 不含 `rawWordsLost`
- 不含 `introducedLikelyOCRError`
- 不含 `sameAsFusedText`
- 不含 `bubbleMaskConflict`
- 不含 `segmentOutsideBubbleRisk`
- protected / decorative block 不允许晋级

即使 line candidate 过门，也先只写入 `promotedLineShadowBlocks` 或等价 shadow 字段，不写回主流程。真正采用需要下一轮 Agent C 或人工明确批准。

## 验收标准
通过条件：

1. `probe_report.json` 能看到 line-level TextBox / deskew shadow report，或现有 report 中有等价结构。
2. 目标 block 动态来自 v1.9 failure report，不使用 ground truth，也不硬编码为“真值低分块”。
3. 实验规模受控：每个目标 block 最多 4 个 line-level plan。
4. plan/candidate 能通过 `sourcePlanID` 或等价字段稳定关联。
5. block 1/6/10 均能在 TXT 中读到 line-level 计划、best candidate、promotion checks 和 next action。
6. 非目标 block 不生成大矩阵，避免把 v1.9 已停止的块重新拉回试参循环。
7. 候选排序、失败归因和 promotion checks 均不使用 ground truth。
8. `finalTextUsedForTranslation`、主译文、覆盖图主输入、`textRegionCropReport.adoptedCount` 不因本轮改变。
9. `frameworkComparison.consistencyPassed = true`、`fusionComparison.consistencyPassed = true` 仍成立。
10. 三条保护文本仍保留：`Let's Battle!`、`What are you even talking about?`、`We need to get results...`。
11. 若没有任何 line candidate 通过门槛，报告必须清楚写出停止原因，不能把 better-than-control 误写成可采用。
12. README、update_log、flow、flowchart、test、version_history 与最新输出同步。

## 风险和禁止项
- 最大风险是把 line-level shadow 验证写成主流程采用逻辑。本轮只验证，不采用。
- 第二风险是为了出现 promoted block 而放宽门槛。禁止这么做。
- 第三风险是把 block 1/6/10 写死为唯一真理。实现应优先读取 `continueGeometryResearchBlocks`，当前数字只是 v19 基线。
- 第四风险是 deskew 搜索膨胀成本。角度必须少，目标 block 必须少，输出必须说明 `ocrExecuted` 或等价执行状态。
- 第五风险是用 ground truth 或 OCR 相似度指导候选生成。真值只能用于事后评估。

## 给 Agent B 的最终提醒
这轮目标不是“把 OCR 数字做上去”，而是验证 Koharu 式更细粒度 TextBox 是否还能在 v1.9 后提供边际收益。若 block 1/6/10 仍不能通过不放宽的 promotion gate，正确结论就是停止这一支 crop/line/deskew 试参，把下一轮重点转向更强 OCR 模型、真实 TextBoxes detector、真实 BubbleMask / SegmentMask 或翻译模型质量。

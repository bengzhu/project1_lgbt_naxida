## 当前判断
v1.30 已把 RenderedSprites / FinalRender 做成回归锁，证明当前覆盖图、失败块 fallback、核心输出文件和 render collision 不能被后续诊断层破坏。v1.35-v1.37 进一步把 Koharu 的 BubbleIndex、DistanceField safe area 和 BubbleMask adjacency / seam partition 复刻为 report-only 账本。

但 Koharu renderer 的关键不只是“有 safe rect”，还包括：

- 在 bubble safe map 内搜索可放置的译文 sprite；
- 根据布局框和文字长度选择字号、换行和最小可读边界；
- 对同一气泡多个文字块做分区，避免 sibling 互相覆盖；
- 失败块 fallback 文本也必须受同一套 render budget 约束；
- sprite 非透明像素必须留在 BubbleMask ID 内。

AITRANS 当前已有 `safeLayoutRect`、`renderFontSize`、`renderNonTransparentBounds`、`renderCollisionResolved`、`renderTextTruncated`、`failureOverlayRequired`、DistanceField safe rect、BubbleIndex sibling ledger 和 v1.37 seam ledger，但缺少一个 Koharu 式 `RenderedSprites fit planner`：把这些现有证据聚合成逐块排版预算、字体 / 换行适配风险、同气泡 sibling 互斥风险和 failure overlay 渲染风险账本。

v1.38 应新增 report-only 的 `Koharu RenderSprite Fit Planner Report`。它只复用 AITRANS 现有探针输出和报告字段，不重新渲染 PNG，不改 overlay renderer，不改 safeLayoutRect，不新增 OCR / LLM。目标是回答：当前译文或失败 fallback 如果按 Koharu renderer 的思路进入 RenderedSprites 阶段，哪些块只是 render-locked，哪些块有字体预算 / sibling overlap / seam-safe-area / failure fallback 风险，哪些风险必须等待真实 BubbleMask / renderer artifact。

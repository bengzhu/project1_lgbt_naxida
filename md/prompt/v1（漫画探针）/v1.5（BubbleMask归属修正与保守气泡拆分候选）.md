# AITRANS Agent B / Koharu 提示词：v1.5（BubbleMask 归属修正与保守气泡拆分候选）

## 版本号
v1.5（漫画探针 / BubbleMask 归属修正与保守气泡拆分候选）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入，v1.1 已完成 post-fusion 重复/碎片清理与气泡分割审计，v1.2 已接入 TextRegion crop OCR 候选层，v1.3 已新增 `bubbleSubRegionReport` 和 subregion clamp，v1.4 已新增轻量 `bubbleMaskReport`、mask-safe layout、crop mask coverage 和渲染 mask collision 诊断。

v1.4 的关键结论是：BubbleMask 近似层已经能暴露新的结构性问题，但它仍未用于修正主流程几何归属，也没有真正拆分 oversized bubble。当前 `bubbleMaskReport.inconsistentBubbleAssignmentBlocks = [4, 5, 11, 12]`，`cropMaskCoverage` 低的块是 `[4, 5, 9, 12]`，`bubbleID 4/6/7` 仍是 oversized / split candidate。下一步应做 Koharu 路线里的“实例 mask -> seed 归属 -> 保守拆分候选 -> 受保护主流程采用”闭环，而不是继续放宽 TextRegion crop 护栏、换翻译模型或把确定性纠错切主流程。

本轮是 v1.5：基于 v1.4 的 BubbleMask 证据，做可审计、可回退、ground-truth-free 的 bubble 归属修正诊断和保守气泡拆分候选。默认先以诊断为主；只有满足强护栏时，才允许把局部归属修正或拆分结果用于 TextRegion crop clamp / safe layout，不允许为了指标强行改主文本。

## 问题定义
当前几何层还有三个具体缺口：

1. `bubbleID` 归属和 `BubbleMask` dominant ID 已经出现冲突，但报告只记录冲突，没有给出“是否可修正”的可审计结论。
2. `bubbleID 4/6/7` 的 oversized 风险仍停留在 audit，没有形成保守 split candidate，也没有把 split candidate 作为 TextRegion crop 的更窄 clamp 依据。
3. TextRegion crop 的低 coverage 块已经很清楚，但缺少 `maskDominantBubbleID`、subregion、split candidate 和 crop rejection 之间的统一决策轨迹。

Koharu 的关键不是“用真值选更好文本”，而是让 TextBoxes、BubbleMask、SegmentMask 这类结构中间层驱动 OCR crop、清字和渲染。AITRANS 本轮不接入新模型，但应把 v1.4 的 mask 诊断推进到更明确的几何候选层：哪些块可安全修正归属，哪些 oversized bubble 可生成拆分候选，哪些候选只能保留诊断。

## 目标
实现一个可审计、可回退、ground-truth-free 的 BubbleMask 归属修正与保守气泡拆分候选层：

1. 新增 `bubbleAssignmentCorrectionReport` 或等价结构，逐块记录当前 `bubbleID`、mask dominant ID、coverage、冲突原因、是否建议修正、修正后的候选 bubbleID、采用状态、拒绝原因和影响范围。
2. 对 `bubbleID 4/6/7` 生成保守 split candidate 诊断，至少记录 parent bubble、候选子 bubble bbox/mask/safeRect、seed blocks、coverage、overlap、风险 flags、是否可用于 crop clamp。
3. 建立强护栏：只有 mask dominant coverage 足够高、seed 下非 0 mask 足够多、候选不会抢占 sibling block、不会导致保护文本丢失、不会让 total block 暴涨时，才允许把归属修正用于诊断性 clamp / safe layout。
4. TextRegion crop 仍保持 v1.2/v1.3 护栏，但本轮可优先尝试更精确的 `correctedBubbleID` 或 `splitCandidateBBox` 作为 clamp；如果 crop 更差，必须回退 fused 文本并写明原因。
5. 报告必须能回答：哪些 `inconsistentBubbleAssignmentBlocks` 被确认可修正、哪些被拒绝、哪些 oversized bubble 有 split candidate、哪些 split candidate 实际用于 crop clamp、是否减少低 mask coverage、是否仍保持 13 块和三条保护文本。
6. `1_ocr_probe_text.txt` 必须输出每块的 bubble 修正决策、split candidate、crop clamp 来源、mask coverage 和拒绝原因。
7. 如果实现成本可控，在 `1_bubble_debug.png` 或 contact sheet 中用不同颜色标出 parent bubble bbox、mask-safe rect、split candidate bbox 和 corrected assignment；若不画图，最终回复必须说明本轮只输出 JSON/TXT 证据。
8. 保持失败块报告和覆盖绘制规则不变：失败块必须在 `blocks` 明细中，覆盖图必须显示 `翻译失败 + OCR 原文`。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于 bubble 修正、split candidate、crop clamp、候选采用、排序或回退。
- 不要放宽 TextRegion crop 采用规则来制造 `adoptedCount > 0`。
- 不要把 deterministic correction 纳入 `finalTextUsedForTranslation` 主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要为了提高 OCR 相似度跨气泡合并。
- 不要把 `bubbleMaskReport` 当作真实分割模型结果；必须继续标注它是近似。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 mask/split 的布局收益说成 OCR 质量提升。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严。

## 实现步骤
### 1. 先做基线核查
实现前从当前 `output/probe_report.json` 和 `output/1_ocr_probe_text.txt` 列出：

- 13 个块的 `index`、`bubbleID`、`bbox`、`maskDominantBubbleID`、`maskDominantCoverageRatio`、`cropMaskCoverageRatio`、`safeLayoutSource`、`finalTextUsedForTranslation`、`failureCategory`。
- `bubbleMaskReport.inconsistentBubbleAssignmentBlocks`、`renderMaskOverflowBlocks`、`bboxFallbackBlocks`。
- `bubbleSubRegionReport.totalSubRegions`、`clampEligibleCount`、`oversizedBubbleIDs`。
- `textRegionCropReport.mainRejectionReasons`、各块 `clampSource`、`cropMaskCoverageRatio`、`cropMaskRejectedReason`。
- `bubbleAudits` 中 `bubbleSplitCandidate = true` 的 bubble。

把观察写进最终回复。不要只看覆盖图猜原因。

### 4. 归属修正决策必须保守
新增纯函数式决策步骤，建议基于 v1.4 `bubbleMaskReport.blockDiagnostics` 运行：

```text
block + current bubbleID + mask dominant ID + mask IDs under seed + bubbleGeometry + split candidates
  -> classify assignment conflict
  -> decide diagnostic-only / recommended / applied-to-crop-clamp / rejected
```

推荐护栏：

- `maskDominantBubbleID == nil`：不得修正。
- 当前 `bubbleID == maskDominantBubbleID`：记录 consistent，不修正。
- 当前 `bubbleID == nil` 且 mask coverage 高，但 block 是装饰标题或保护短文本时，默认只推荐不应用；除非不会改变 block 数、不会污染 crop、不会改变 final text。
- 当前 `bubbleID != nil` 且 mask dominant coverage >= 0.70，可推荐修正；若 coverage >= 0.85、seed 下非 0 mask 像素充足、sibling overlap 低，才允许用于 crop clamp。
- `block 5` 这类 coverage 高但当前归属明显冲突的块，可以优先作为 applied-to-crop-clamp 候选，但必须保留原 `finalTextUsedForTranslation` 回退。
- `block 9` 这类 coverage 低/边界混合块，不应直接改归属；应优先进入 split candidate 诊断。
- `block 12` 是 decorative 标题，不能为了 mask dominant 把它强行并入对话气泡；默认只诊断。
- 任何修正不得使用 `groundTruthMatch`、`ocrGroundTruthSimilarity`、`bestGroundTruthText` 或人工真值文本。

### 5. 生成保守 split candidate
基于 `bubbleAudits`、v1.3 subregion、v1.4 mask runtime 和 fused blocks 生成候选：

```text
oversized parent bubble 4/6/7
  -> collect seed blocks in parent / mask-dominant-conflicted blocks near parent
  -> build block-local bbox expanded by orientation-aware padding
  -> clamp to parent mask safe bbox / parent bbox / content rect
  -> estimate mask coverage and sibling overlap
  -> decide clampEligible
```

规则建议：

- 只对 `bubbleSplitCandidate = true` 的 parent bubble 做候选；普通 bubble 可记录 skipped。
- 候选 bbox 必须覆盖 seed block bbox 的大部分区域，不能切掉 seed。
- 候选 bbox 不能与 sibling candidate 高重叠；若高重叠，只保留诊断，`clampEligible = false`。
- 如果候选面积接近整个 parent bubble，说明没有真实拆分收益，`clampEligible = false`。
- 如果候选 mask coverage 太低或 parent mask 本身不可信，`clampEligible = false`。
- 候选只允许影响 TextRegion crop clamp / safe layout 诊断，不直接新建或删除 `probeBlocks`。
- 不允许为了让 `totalBlocksDetected` 改变而拆块；本轮默认保持 13 个主块。

### 6. 接入 TextRegion crop clamp，但不放宽采用
扩展 `applyTextRegionCropCandidates(...)` 或其调用前置数据，让 clamp 顺序变为：

```text
seed bbox
  -> v1.2/v1.3 原始 region/crop bbox
  -> 若有可信 split candidate，优先 clamp 到 split candidate bbox/safeRect
  -> 否则若有可信 correctedBubbleID，clamp 到 corrected bubble mask/safeRect/bbox
  -> 否则若有可信 subregion，clamp 到 subregion
  -> 否则按 bubble bbox / content rect 回退
  -> Vision OCR
  -> evaluateTextRegionCropSelection 原护栏
```

必须记录：

- `clampSource = splitCandidate | correctedBubbleMask | subRegion | bubbleBBox | contentRect`
- `correctedBubbleID`
- `splitCandidateID`
- `cropBBoxBeforeAssignmentCorrection`
- `cropBBoxAfterAssignmentCorrection`
- `cropMaskCoverageBefore`
- `cropMaskCoverageAfter`
- `assignmentCorrectionRejectedReason`
- `splitCandidateRejectedReason`

`evaluateTextRegionCropSelection(...)` 的核心护栏保持不变。空文本、词数退化、raw words 丢失、明显 OCR 错误、收益不足仍必须拒绝。

### 7. 接入 safe layout 只做保守升级
如果 correctedBubbleID 或 split candidate 可信，可让 safe layout 诊断优先使用更精确的 mask-safe rect，但必须满足：

- 不让多个块抢同一整气泡 safe rect。
- 渲染 mask collision 仍要检查，越界必须回退或缩字号。
- `renderMaskOverflowBlocks` 不应新增；若新增，必须解释具体块和回退结果。
- safe layout 改善不能写成 OCR 提升。

### 8. 更新输出文本和图像证据
同步更新：

- `probe_report.json`：新增 `bubbleAssignmentCorrectionReport` 和 `bubbleSplitCandidateReport` 或等价结构。
- `1_ocr_probe_text.txt`：每块显示 current/dominant/corrected bubble ID、correction decision、split candidate、clamp source、crop mask coverage before/after、rejection reasons。
- `1_bubble_debug.png` 或 `1_probe_contact_sheet.png`：如实现成本可控，叠加 split candidate bbox / corrected assignment marker；若不画图，最终回复说明原因。

### 9. 强保护 v1.4 成果
本轮不能回归：

- `configuration.currentBlockSource` 默认仍保持 `fusedWholePageBubble`；只有 crop 文本实际采用时才可改成更明确的来源，并同步文档解释。
- `fusionComparison.postFusionCleanup.applied = true` 仍要存在。
- `postFusionCleanup.blockCountBeforeCleanup = 16`、`blockCountAfterCleanup = 13`、`rejectedBlockCount = 3` 的语义不能被破坏。
- 三条保护文本不能丢：
  - `Let's Battle!`
  - `What are you even talking about?`
  - `We need to get results at this tournament to save the gaming club from being disbanded.`

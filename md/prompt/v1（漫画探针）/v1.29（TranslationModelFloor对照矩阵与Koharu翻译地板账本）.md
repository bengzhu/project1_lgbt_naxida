## 当前判断
v1.28 已新增 `koharuArtifactConvergenceReport`，把 v1.25 / v1.26 / v1.27 三个 native/proxy 结构 work item 收束到 Koharu canonical artifact 矩阵，并把未闭合项集中到：

- `WI-render-regression-lock`
- `WI-external-artifact-optional-handoff`

本轮优先执行第一个未闭合项：`WI-translation-model-floor-comparison`。

原因：

- 当前旧基线 `cleanTextDiagnostic.passRate = 0.4545`，说明即使跳过 OCR、直接把人工 dialogue 真值送入当前 Local GGUF 翻译链路，仍只有 5/11 通过。
- 主探针 `failedBlocks = 12`，`translationFailureBreakdown = { modelOutputFailure: 2, ocrInputSuspect: 7, translationLanguageQualityFailure: 3 }`，不能继续把所有端到端失败都归因到 OCR / TextBoxes / BubbleMask / SegmentMask。
- v1.19 已有 `routingDrivenTranslationComparisonReport`，但它只针对最多 5 个 noisy final blocks 跑 strict prompt；还没有把 clean text 基线和 strict prompt 变体放进统一的 translation floor 矩阵。
- Koharu 的 LLM 阶段是 tagged / structured translation；AITRANS 当前 Gemma 270M 的 batch tag 对照崩坏，必须先把“当前模型 + 当前 prompt / strict prompt 的地板”诊断清楚，再决定后续是否引入更强小模型对比或 batch translation 复测。

本轮仍是 report-only / diagnostic-only。允许新增确定性 LLM 诊断调用，但禁止改主翻译 prompt、默认模型、质量判定、逐块主译文、覆盖图或 `blockPassed`。

## 目标 2：Clean Text strict prompt 对照


执行时机建议：

1. 先运行现有 `runCleanTextDiagnostic(groundTruth:)`，写出 `clean_text_diagnostic.json`。
2. 再对同一批 `groundTruth.dialogue` entries 运行 strict prompt 变体。
3. 再生成 `translationModelFloorComparisonReport`。

## 风险和注意事项
- 当前根 `output/` 是旧快照，不含 v1.28 / v1.29 新字段；不要用它判断新报告缺失。v1.29 的可信验收看本 PR 的云端 artifact。
- strict prompt 变体可能变好、变差或无变化，三种结果都可以接受；本轮目的是分类模型地板，不是保证质量提升。
- clean text ground truth 用于模型地板诊断是允许的，但只能进入 `cleanCases` 和 evaluation-only signals，不能影响 noisy OCR 候选选择或产品路径。
- 如果 strict prompt 明显改善，也只能给下一轮“prompt promotion shadow gate”提供证据，不能在本轮替换主 prompt。
- 如果 strict prompt 无改善，结论应是当前 Gemma 270M 模型地板更强，而不是继续盲目调 OCR。
- batch tagged 仍可能格式崩坏；它只能证明当前模型的结构化输出能力不足，不能替换逐块翻译。
- 额外 deterministic LLM 调用会增加云端探针耗时；保持 max tokens 保守，记录进度，失败时结果包必须保留 `manga-probe.log`、`app-console.log` 和 `manga_probe_progress.json`。

## 背景判断
Koharu 的关键能力来自结构化 artifact DAG：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> FontPredictions
  -> Translations
  -> Inpainted
  -> RenderedSprites
  -> FinalRender
```

AITRANS 目前已经有 fused whole-page / bubble-first、BubbleMask 近似、SegmentMask proxy、pre-crop plan、line-level deskew shadow 和 readiness gate，但这些都不是独立 detector / segmenter 输出。继续调 Vision crop、line deskew、deterministic correction 或 prompt 不会补齐 Koharu 三件套。

下一步必须先解决契约问题：真实外部输出应长什么样，如何放入仓库或 App bundle，如何在不运行 iOS 探针的情况下提前发现 schema、坐标、bbox、coverage、source image 或路径错误。

## 目标
实现一个不会污染主探针输入的 Koharu external artifact contract pack，并为下一轮真实 external TextBoxes shadow OCR 做准备。

本轮至少完成：

1. 明确 `test/koharu_artifacts/` 是活动输入目录，只能放真实 artifact，不放示例或伪造 detector 输出。
2. 新增非活动 fixture / schema 示例目录，例如：

```text
md/koharu研究/artifact_contract/
  README.md
  examples/
    valid/
      1.manifest.json
      1.textboxes.json
      1.bubbles.json
      1.segment_mask.json
    invalid/
      coordinate_mismatch.manifest.json
      invalid_bbox.textboxes.json
      missing_textboxes.manifest.json
```

3. 新增离线校验脚本，建议：

```text
scripts/validate-koharu-artifacts.py
```

4. 校验脚本能验证 active artifact 目录或 examples 目录，但默认不把 examples 复制到 `test/koharu_artifacts/`。
5. 校验规则必须与 Swift `MangaOverlayExternalArtifact*` 模型一致，并覆盖 manifest、TextBoxes、BubbleMask、SegmentMask、坐标系、bbox、confidence、sourceImage、相对路径解析。
6. 如果 Swift parser 当前缺字段、缺错误类型或与契约不一致，只做小范围补齐。
7. 如且仅如 `test/koharu_artifacts/` 存在真实 artifact 且 readiness 为 `readyForShadowOCR`，才允许准备 external TextBoxes shadow OCR 入口；没有真实 artifact 时继续阻塞，不运行 shadow OCR。

## 非目标

- 不联网下载模型，不访问 Hugging Face，不引入 package registry 依赖。
- 不提交 detector 权重、Core ML、ONNX、safetensors、GGUF 或大二进制文件。
- 不把 example fixture 放进 `test/koharu_artifacts/` 让 App 误以为真实 detector 输出已存在。
- 不用 Vision OCR blocks、pre-crop plan、line plan、bubble proxy 生成 active external artifacts。
- 不改变 `configuration.currentBlockSource`。
- 不改变 `finalTextUsedForTranslation`、主覆盖图文本、`blockPassed`、`textRegionCropReport.adoptedCount`。
- 不用 `test/1.ground_truth.json` 生成、筛选、排序、晋级或回退 external artifact。
- 不继续在 v20 已判停的 block-level / line-level crop / deskew 路线试参。
- 不放宽 v1.9 / v1.10 promotion gate。
- 不把“schema 示例通过”写成“真实 detector 接入完成”。

## 实现要求
### 1. 文档化外部 artifact contract
新增 `md/koharu研究/artifact_contract/README.md`，至少写清：

- active 输入目录：`test/koharu_artifacts/`
- example 目录：`md/koharu研究/artifact_contract/examples/`
- active 目录只接受真实 detector / segmenter 输出。
- 坐标系固定为原图左上角像素坐标：`originalImageTopLeftPixels`。
- `sourceImage` 必须是 `test/1.png`，或 manifest 中明确可映射到当前 probe 图。
- bbox 格式是 `[x, y, width, height]`，宽高必须为正，不得越界。
- confidence 如果存在必须在 `[0, 1]`。
- TextBoxes 支持 `bbox` 或 `x/y/width/height` 两种输入，但输出报告统一 bbox。
- BubbleMask 当前契约可先接收 instance summary：`id`、`bbox`、`maskValue`、`pixelCount`，不要求提交真实 mask PNG。
- SegmentMask 当前契约可先接收 summary：`width`、`height`、`glyphPixelCount`、`connectedComponentCount`，不要求提交真实 mask PNG。
- line polygons、source direction、rotation、font size 字段是可选项；有则校验结构，不作为 readiness 必填。

### 2. 提供非活动示例 fixture
在 `md/koharu研究/artifact_contract/examples/valid/` 提供最小可解析示例。

要求：

- 示例必须在文件内或 README 中明确标注 `contractExampleOnly=true` 或等价说明。
- 示例不能被 App 探针自动读取。
- 示例坐标可以是少量手写 bbox，但不得声称来自真实 detector。
- 示例只用于 schema / parser smoke，不用于 OCR 指标、版本指标或主流程。

在 `examples/invalid/` 至少提供：

- 坐标系错误 manifest。
- bbox 越界或宽高非法 TextBoxes。
- manifest 指向缺失文件。

### 3. 新增离线校验脚本
建议脚本：

```sh
python3 scripts/validate-koharu-artifacts.py --root md/koharu研究/artifact_contract/examples/valid
python3 scripts/validate-koharu-artifacts.py --root md/koharu研究/artifact_contract/examples/invalid/coordinate_mismatch --expect-fail
python3 scripts/validate-koharu-artifacts.py --root test/koharu_artifacts --allow-missing
```

脚本必须：

- 只用 Python 标准库。
- 解析 manifest 指定路径和 fallback 文件名。
- 支持 TextBoxes array 或 `{ "textBoxes": [...] }` / `{ "items": [...] }`。
- 支持 Bubble instances array 或 `{ "bubbleInstances": [...] }` / `{ "bubbles": [...] }` / `{ "instances": [...] }` / `{ "items": [...] }`。
- 校验 image size，建议从 `test/1.png` 读取 PNG header 得到宽高；不要依赖 Pillow。
- 输出 JSON 摘要到 stdout，包含 `verdict`、`missingArtifacts`、`parseErrors`、`coordinateErrors`、`textBoxCount`、`bubbleInstanceCount`、`segmentMaskSizeMatches`。
- `--expect-fail` 时，只有确实失败才返回 0。
- `--allow-missing` 时，active 目录不存在可返回 0，但摘要必须是 `manifestMissing` 或 `artifactFilesMissing`。

### 4. 同步 Swift readiness 语义
核对 Swift 代码里的这些字段和脚本一致：

- `MangaOverlayExternalArtifactManifest`
- `MangaOverlayExternalTextBox`
- `MangaOverlayExternalBubbleInstance`
- `MangaOverlayExternalSegmentMaskSummary`
- `MangaOverlayExternalArtifactCoordinateValidation`
- `MangaOverlayExternalArtifactReadinessReport`

允许小范围补齐：

- 更清晰的 parse error label。
- `contractExampleOnly` / `generatedBy` / `notes` 的透传。
- readiness note 中明确 active vs example 目录。
- `coordinateSpaceMissing` 和 `coordinateSpaceMismatch` 区分。

禁止借机重构 `TranslationSessionStore` 大段逻辑。

### 5. Shadow OCR 入口只做门控
本轮可以新增一个明确的门控字段或 note，例如：

```text
externalTextBoxesShadowOCRAllowed = readinessVerdict == "readyForShadowOCR" && activeArtifactsDirectory == true
```

没有真实 active artifact 时：

- 不运行 external TextBoxes OCR。
- 不新增 `externalArtifact.*` OCR candidate。
- 不改变 `cropExperimentReport`、`lineCropExperimentReport`。
- 报告仍为 `manifestMissing` / `stopUntilArtifactsProvided`。

如果人工已经提供真实 `test/koharu_artifacts/`：

- 最多允许每个 block 准备 1 个 external TextBox shadow candidate。
- 变体名必须以 `externalArtifact.` 开头。

- 仍复用既有 promotion gate，不放宽。
- 最终回复必须说明 artifact 来源、文件名、数量、是否真实 detector 输出。

## 验收标准
通过条件：

1. `test/koharu_artifacts/` 不存在时，App 探针仍稳定报告 `manifestMissing / stopUntilArtifactsProvided`。
2. 示例 fixture 不会被 App 探针当作 active artifact 读取。
3. validator 对 valid example 返回成功，并输出可解析 JSON 摘要。
4. validator 对 invalid coordinate / invalid bbox / missing file 样例按预期失败。
5. validator 的 verdict 和 Swift readiness verdict 语义一致。
6. active 目录缺失时，validator 在 `--allow-missing` 下返回成功但摘要明确阻塞。
7. 不改变 `finalTextUsedForTranslation`、主覆盖图、`blockPassed`、`textRegionCropReport.adoptedCount`。
8. 不改变 `configuration.currentBlockSource = fusedWholePageBubble`。
9. `frameworkComparison.consistencyPassed = true`、`fusionComparison.consistencyPassed = true` 仍成立。
10. 三条保护文本仍在报告明细或 OCR 文本快照中。
11. 文档明确区分 contract / fixture / validator / real detector artifact。
12. 若未跑完整探针，不追加 `metrics/version_history.csv` 漫画指标行。

## 已知风险
- 最大风险：把示例 fixture 放进 active 目录，导致报告假装真实 detector artifact ready。
- 第二风险：validator 和 Swift parser 语义漂移，云端或 App 端发现的问题无法提前在本地脚本暴露。
- 第三风险：把 contract 工作误记成 OCR 质量版本。
- 第四风险：继续围绕 Vision crop / deskew 调参，偏离 v1.11 已明确的 artifact 阻塞。
- 第五风险：使用 ground truth 修正 external artifact。禁止。

## 给 Agent B 的最终提醒
这轮的正确进展是“让真实 Koharu artifact 可以被人类按契约提供，并能在进入 App 探针前被离线校验”。没有真实 `test/koharu_artifacts/` 时，继续阻塞是正确结果。不要制造假 artifact，不要把 fixture 当 detector 输出，不要改主 OCR / 翻译 / 覆盖路径。

## 背景判断
Koharu 的强项不是“继续调 OCR 后处理字符串”，而是通过结构化 artifact DAG 驱动整条链路：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> FontPredictions
  -> Translations
  -> Inpainted
  -> RenderedSprites
  -> FinalRender
```

AITRANS 目前已经完成：

- whole-page + bubble-first 融合主流程。
- post-fusion cleanup。
- BubbleMask 近似、SegmentMask proxy、TextBox plan、crop experiment、line-level deskew shadow。
- external artifact contract。
- active artifact validator。
- external TextBoxes shadow OCR report。
- CI manifest 中的 Koharu gate 摘要。

但这些都没有替代真实 Koharu detector / segmenter 输出。v20 已判停继续在 block-level / line-level crop / deskew 试参线上消耗；v1.11-v1.14 已建立“缺真实 artifact 就阻塞”的正确边界。v1.15 的任务应当第一次验证真实 active artifact 的进入路径，而不是继续围绕 missing path 打补丁。

## 实现要求
### 1. 先判断是否真的有 active artifact
实现前必须运行：

```sh
find test -maxdepth 3 -path 'test/koharu_artifacts*' -print
python3 scripts/validate-koharu-artifacts.py --root test/koharu_artifacts --allow-missing
```

判断规则：

- 目录不存在或 `verdict = manifestMissing`：走路径 B。

- 有目录但 parse / coordinate / bbox / source image 失败：修 artifact 转换或退回 Koharu，不要在 App 内偷偷改坐标。
- 只有 `readyForShadowOCR = true` 且 `externalTextBoxesShadowOCRAllowed = true`：走路径 A。

### 2. 路径 A 的 active artifact 最低质量门槛
真实 active artifact 至少应满足：

- `1.manifest.json` 存在。
- `1.textboxes.json` 至少包含能覆盖当前 13 个 fused blocks 附近的 TextBoxes。
- `1.bubbles.json` 至少包含当前图主要气泡实例 summary。
- `1.segment_mask.json` 至少包含 `width = 576`、`height = 1280`，并建议包含 `glyphPixelCount`、`connectedComponentCount`。
- 所有 bbox 使用原图左上角像素坐标 `[x, y, width, height]`。
- bbox 不越界，宽高为正。
- confidence 如果存在，必须在 `[0, 1]`。
- manifest `contractExampleOnly = false`。
- manifest `generatedBy` 必须说明真实 detector / Koharu 输出来源。

如果真实 detector 输出的坐标来自裁切图、缩放图或其他坐标空间，必须先在外部转换为 `originalImageTopLeftPixels`，并在 notes 记录转换来源。不要让 App 探针在读取时猜测坐标换算。

## 背景判断
v20 已证明 block `[1, 6, 10]` 的 line-level / deskew shadow 候选不能通过既有 promotion gate，应停止继续在这条路线试参。

v21 / v1.11 建立了真实 `TextBoxes` / `BubbleMask` / `SegmentMask` 适配前证据闸门。

v1.12 建立了 artifact contract 和离线 validator，解决“外部 artifact 应长什么样、如何提前验证 schema / bbox / 坐标 / 示例误用”的问题。

因此 v1.13 的正确优化方向是：当外部真实 TextBoxes 被人工或 Koharu 侧按契约提供后，AITRANS 能以 shadow-only 方式跑 OCR 对照并归因收益；当 artifact 缺失、是示例、坐标错或覆盖不足时，继续明确阻塞。

## 目标
实现 external TextBoxes shadow OCR 候选接入层。它必须完全由 `externalArtifactReadinessReport.externalTextBoxesShadowOCRAllowed` 门控。

本轮至少完成：

1. 新增 external TextBoxes shadow OCR report，建议命名：
   - `externalTextBoxShadowOCRReport`
   - 或 `externalArtifactShadowOCRReport`
2. 当且仅当以下条件同时满足时运行：
   - `readinessVerdict == "readyForShadowOCR"`
   - `activeArtifactsDirectory == true`
   - `contractExampleOnly == false`
   - `externalTextBoxesShadowOCRAllowed == true`
3. 每个当前 fused block 最多选择 1 个 external TextBox shadow candidate。
4. candidate 选择只能使用无真值信号：
   - external TextBox 与当前 block bbox 的 IoU。
   - block center 是否落入 TextBox。
   - TextBox confidence。
   - bubble instance alignment。
   - bbox 合法性和面积比例。
   - 可选 line polygons / rotation / sourceDirection 只作为记录和轻量 crop padding 依据。
5. 对 external TextBox crop 跑本地 Vision OCR 对照，记录 OCR 文本、质量分、raw word preservation、candidate 与 control 的差异。
6. 报告所有 skipped / blocked 原因：artifact 缺失、示例、坐标错误、无匹配 TextBox、crop 空、Vision OCR 空、质量未提升、promotion blockers。
7. 不替换 `finalTextUsedForTranslation`、主覆盖图、`blockPassed`、`textRegionCropReport.adoptedCount`、`cropExperimentReport.promotedShadowBlocks`。
8. `1_ocr_probe_text.txt` 每块增加 external TextBoxes shadow OCR 摘要。

## 实现要求
### 1. 新增报告模型
在 `TranscriptModels.swift` 中按现有风格新增 Codable / Sendable 报告模型。建议字段：

```swift
struct MangaOverlayExternalTextBoxShadowOCRReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var executed: Bool
    var gateVerdict: String
    var activeArtifactsDirectory: Bool
    var contractExampleOnly: Bool
    var candidateCount: Int
    var ocrExecutedCount: Int
    var ocrSucceededCount: Int
    var betterThanControlCount: Int
    var promotedExternalShadowBlocks: [Int]
    var skippedBlocks: [Int]
    var blockSummaries: [MangaOverlayExternalTextBoxShadowOCRBlockSummary]
    var candidates: [MangaOverlayExternalTextBoxShadowOCRCandidate]
    var notes: [String]
}
```

命名可调整，但语义必须覆盖：

- 门控是否允许。
- 是否实际运行。
- 每块是否有 candidate。
- candidate 来源 TextBox ID。
- crop bbox。
- OCR 是否执行和是否成功。
- control 文本、external OCR 文本、质量差异。
- promotion verdict 和 blockers。
- 明确 `shadowOnly=true`、`groundTruthNotUsed=true`、`doesNotChangeFinalTextUsedForTranslation=true`。

`promotedExternalShadowBlocks` 本轮应保持 `[]`，除非只是沿用既有 promotion gate 的“shadow promotion for report only”语义，并且文档中明确不写回主流程。更保守的做法是新增 `wouldPromoteByExistingGateBlocks`，但 `promotedExternalShadowBlocks = []`。

### 2. 候选选择规则
每个 block 从 external TextBoxes 中最多选 1 个 candidate。

推荐排序：

1. center contained 优先。
2. IoU 高优先。
3. confidence 高优先。
4. bbox 面积与 block 面积比例在合理区间优先。
5. bubble alignment 一致优先。

硬拒绝：

- bbox 非法或越界。
- crop 面积过小。
- TextBox 与 block 无重叠且中心不包含。
- TextBox 面积相对 block 过大，可能跨多个气泡。
- external artifact readiness 未通过。
- `contractExampleOnly = true`。

候选 variant 名统一以 `externalArtifact.` 开头，例如：

```text
externalArtifact.textBoxCrop
externalArtifact.linePolygonEnvelope
```

如本轮暂不实现 line polygon crop，只记录 `linePolygonsPresent=true`，不要谎称执行了 polygon warp / deskew。

### 3. Shadow OCR 执行
复用现有 Vision OCR crop 辅助能力，保持 deterministic 报告语义。

要求：

- 对 external TextBox bbox 做必要 padding，但必须 clamp 到原图范围。
- 如果 TextBox 有 `rotationDegrees` / `sourceDirection`，可以先只记录，不必实现旋转矫正。
- 如果未实现 deskew，字段必须写 `deskewExecuted=false`。
- OCR 文本只写入 external report 和 `1_ocr_probe_text.txt`。
- 不能写入 `finalTextUsedForTranslation`。
- 不能触发逐块翻译或 clean text 变化。

### 4. 质量评估与归因
质量评估使用现有无真值信号：

- OCR 非空。
- raw word preservation。
- candidate quality score。
- 是否引入明显符号噪声。
- 是否丢失现有 block 关键词。
- 相比 control 是否更短但保留更多词。

可以在完整报告中保留事后 ground truth 对照字段用于统计，但必须明确：

- `groundTruthUsedForSelection = false`
- `groundTruthUsedForPromotion = false`
- candidate 选择和 gate 不读取真值。

### 5. 缺失 artifact 时的行为
当前仓库默认没有 active `test/koharu_artifacts/`。因此在默认状态下：

- `externalArtifactReadinessReport.readinessVerdict = manifestMissing`
- `externalTextBoxesShadowOCRAllowed = false`
- 新 report 应存在或可为空，但必须清楚写：
  - `enabled = true`
  - `executed = false`
  - `gateVerdict = manifestMissing`
  - `candidateCount = 0`
  - `ocrExecutedCount = 0`
  - `skippedBlocks = [0...12]` 或等价汇总
- 不新增 `externalArtifact.*` OCR candidate。

如果有人误把 `examples/valid` 放进 active 目录且 `contractExampleOnly=true`：

- readiness 必须是 `contractExampleOnly`。
- shadow OCR 不运行。
- report 必须写 `blockedBecauseContractExampleOnly`。

### 6. 报告输出
同步以下输出：

- `probe_report.json` 顶层新增 external shadow OCR report。
- `1_ocr_probe_text.txt` 每块新增一段 external shadow OCR 摘要：

报告必须保留现有字段，不破坏 Agent C 既有验收脚本读取。

## 已知风险
- 最大风险：把 contract example 当真实 detector 输出，导致假 ready。
- 第二风险：external OCR candidate 被误写回 `finalTextUsedForTranslation`，污染主流程。
- 第三风险：candidate 选择偷偷使用 ground truth，造成指标虚高。
- 第四风险：把 “shadow better than control” 误解成可替换主流程。
- 第五风险：继续在线级 deskew / crop 试参上消耗，偏离 Koharu artifact DAG 的主方向。
- 第六风险：Swift report 字段新增后未同步文档和 `1_ocr_probe_text.txt`，导致 Agent C 无法验收。

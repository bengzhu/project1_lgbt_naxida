## 本轮目标
从最新 `smalldata_test` 开分支：

```text
codeb/v1.19-routing-driven-translation-ocr-audit
```

本轮做一个小步、可验证、可回退的算法结构优化：把 v1.18 的 `internalStructureBottleneckReport` 从“路由说明”推进到“路由驱动的可量化对照”。仍然只做探针诊断，不替换主流程文本、翻译、覆盖图或通过判定。

目标分两层。

### 目标 1：新增路由驱动翻译 Prompt 对照报告
新增一个 report-only 对照层，建议命名为：

```text
routingDrivenTranslationComparisonReport
```

它只针对 v1.18 路由为 `modelTranslationQuality` 的块，最多选 5 个块运行 deterministic 对照，避免 ci-fast 耗时失控。选择依据必须来自 `internalStructureBottleneckReport.blockSummaries` 和当前 block 明细，不得用 ground truth 选择样本。

对每个目标块，用现有主流程逐块翻译作为 control，再额外跑一个更强约束的诊断 prompt variant。建议 variant 先使用单一稳定 ID：

```text
strictChineseOnlyV1
```

建议 prompt 方向：

```text
把以下英文漫画台词翻译成简体中文。
只输出中文译文，不要解释，不要列点，不要重复英文原文。
如果出现 Senpai、Ren、City Battler、Tournament 等专有名词，请用自然中文或音译处理，不要原样保留英文短语。
原文：
...
```

实现要求：

- Local 模式必须使用 deterministic 解码；Mock 模式可用 mock 但要在报告中标明。
- 不改变普通用户翻译 prompt。
- 不改变漫画主流程 prompt。
- 不改变 `block.translationCandidate`、`blockPassed`、`failureCategory`、`translationDecisionTrace` 或覆盖图。
- 不放宽质量判定规则。
- 不把含中文字符作为唯一成功标准。
- 报告中必须复用现有 `extractMangaProbeTranslationCandidate`、`classifyMangaProbeRawOutput`、`classifyMangaProbeCandidate`、`mangaProbeChecks`、`mangaProbeFailureReasons` 和 `mangaProbeTranslationLanguageQualityIssue`，避免另起一套判定。

每个 case 至少输出：

- `blockIndex`
- `routingPrimaryBottleneck`
- `routingRecommendedAction`
- `sourceText`
- `controlCandidate`
- `controlPassed`
- `controlFailureCategory`
- `controlFailureReasons`
- `variantID`
- `variantPrompt`
- `variantRawOutput`
- `variantCandidate`
- `variantRawOutputClassification`
- `variantCandidateClassification`
- `variantPassed`
- `variantFailureReasons`
- `improvementCategory`
- `latinLeakReduced`
- `emptyOutputFixed`
- `placeholderFixed`
- `shortChineseFixed`
- `diagnosticOnly = true`
- `mustNotPromoteReasons`

建议 `improvementCategory` 使用稳定字符串：

- `fixedEmptyOutput`
- `fixedPlaceholder`
- `fixedLatinLeak`
- `fixedShortChinese`
- `passedButControlFailed`
- `stillModelOutputFailure`
- `stillTranslationLanguageQualityFailure`
- `worseThanControl`
- `noChange`

报告级至少输出：

- `enabled`
- `decodingMode`
- `decodingSeed`
- `variantID`
- `candidateSelectionRule`
- `evaluatedCaseCount`
- `targetBlockIndexes`

- `passedButControlFailedBlocks`
- `worseThanControlBlocks`
- `emptyOutputFixedBlocks`
- `placeholderFixedBlocks`
- `latinLeakReducedBlocks`
- `improvementBreakdown`
- `notes`

验收重点：

- 如果 strict prompt 能让某些 `modelTranslationQuality` 块从空输出、占位、短中文或英文残留变成通过，只能写进 report，不能自动替换主流程译文。
- 如果 strict prompt 仍失败，也必须写明失败类型，帮助下一轮判断是 prompt 无效还是 Gemma 270M 能力瓶颈。
- `ci-fast` 必须产出该 report；不能只在 full 模式产出。

### 目标 2：新增 OCR 字符损坏审计报告
新增一个 report-only OCR 损坏分析层，建议命名为：

```text
ocrCharacterDamageAuditReport
```

它只针对 v1.18 路由为 `ocrCharacterDamage`、或 `failureCategory = ocrInputSuspect`、或 `ocrGroundTruthSimilarity < 0.72` 的块做审计。这里允许使用 `test/1.ground_truth.json` 做探针评估，因为这是诊断报告；但不得用它做生产候选选择、排序、清理或翻译输入替换。

每个 case 至少输出：

- `blockIndex`
- `groundTruthMatch`
- `groundTruthType`
- `ocrGroundTruthSimilarity`
- `wordOrderPreserved`
- `finalTextUsedForTranslation`
- `bestGroundTruthText`
- `damagedTokens`
- `missingGroundTruthTokens`
- `extraOcrTokens`
- `suspectedSubstitutions`
- `repeatedKeywordDamage`
- `lineBreakRisk`
- `bubbleID`
- `textBoxEvidenceSummary`
- `segmentMaskEvidenceSummary`
- `cropBlockers`
- `recommendedNextAction`
- `diagnosticOnly = true`
- `mustNotPromoteReasons`

建议 token 审计用现有词级 Levenshtein / token 化思路，保持可解释，不要引入外部库。`suspectedSubstitutions` 可以输出类似：

```text
HATTLER -> BATTLER
TOUPNAMENT -> TOURNAMENT
PEW -> FEW
ANP -> AND
TRAININS -> TRAINING
THS -> THIS
SAMNG -> GAMING
CLUR -> CLUB
RENG -> BEING
LOSIC -> LOGIC
```

报告级至少输出：

- `enabled`
- `evaluatedBlockCount`
- `targetBlockIndexes`
- `damageTokenFrequency`
- `missingTokenFrequency`
- `substitutionFrequency`
- `repeatedKeywordDamage`
- `lineBreakRiskBlocks`
- `cropBlockedBlocks`
- `textBoxOrSegmentEvidenceBlocks`
- `recommendedActionBreakdown`
- `notes`

建议 `recommendedNextAction` 使用稳定字符串：

- `needsBetterTextBoxOrSegmentEvidence`
- `needsOCRModelOrEngineComparison`
- `needsBubbleSplitOrAssignmentReview`
- `doNotTuneCropFurther`
- `promptComparisonOnly`
- `manualReview`

验收重点：

- 报告能解释 `ocrCharacterDamage` 桶里到底是字符替换、漏词、额外词、词序问题、line break 风险，还是 crop 候选被护栏挡住。
- 对 v20 已停止的 line-level / deskew 参数线，遇到同类 blocker 时应输出 `doNotTuneCropFurther`，不要建议继续调同一条参数线。
- `1_ocr_probe_text.txt` 每个相关块必须追加 OCR 损坏审计摘要，便于不用 `jq` 排查。

## 实现提示
建议按这个顺序实现：

1. 在 `AITRANS/Models/TranscriptModels.swift` 新增 `MangaRoutingDrivenTranslationComparisonReport`、case 模型、`MangaOCRCharacterDamageAuditReport`、case 模型。字段使用 string enum，保持 Codable 向后兼容。
2. 在 `MangaOverlayProbeReport` 中新增两个 optional 字段：
   - `routingDrivenTranslationComparisonReport`
   - `ocrCharacterDamageAuditReport`
3. 在 `TranslationSessionStore.runMangaOverlayProbe` 中，先生成 v1.18 `internalStructureBottleneckReport`，再基于它生成两个新报告。
4. `routingDrivenTranslationComparisonReport` 需要异步跑 Local raw probe；只选择 `modelTranslationQuality` 目标块，最多 5 个，且必须记录选择规则和 skipped 原因。
5. `ocrCharacterDamageAuditReport` 应是纯本地计算，不增加模型调用。它可以读取 block 的 `bestGroundTruthText`、`ocrGroundTruthSimilarity`、`wordOrderPreserved`、TextRegion crop / TextBox plan / SegmentMask / BubbleMask 证据，做诊断归因。
6. 在 `MangaOverlayProbeService` 的 TXT 生成逻辑里追加：
   - 每个 model-translation 目标块的 strict prompt 对照摘要。
   - 每个 OCR-damage 目标块的 token 损坏摘要。
   - 文件末尾两个报告级 summary。
7. 更新 `README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`，只写当前真实行为和验收口径，不把本轮 report-only 结果写成主流程提升。

- OCR 损坏审计允许用 ground truth 做诊断，但所有生产选择和候选排序仍必须 ground-truth-free。
- 不要因为某个 prompt variant 在当前图变好，就直接把它改成普通翻译或漫画主流程默认 prompt。

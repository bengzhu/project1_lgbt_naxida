新增报告：

```text
koharuNativeTextBoxDetectorLiteShadowOCRReport
```

报告目标：

1. 在漫画探针中新增一个 shadow-only OCR 执行阶段，只消费 v1.39 `koharuNativeTextBoxDetectorLiteReport.candidates` 中 `shadowOCREligible = true` 的候选。
2. 候选选择只使用 v1.39 detector-lite 的 ground-truth-free 信号：candidate score、candidate verdict、bubble coverage、glyph overlap、block overlap、direction hint、candidate / block ledger。不得用 `test/1.ground_truth.json` 选择候选、排序、决定是否执行 OCR 或决定 next action。
3. `ci-fast` 默认执行低成本闭环：每个最终 block 最多 1 个 detector-lite candidate OCR，总量建议不超过 `totalBlocksDetected`；`full` 可以每块最多 2 个候选，但仍必须有硬上限和报告字段。
4. OCR 输入必须来自 detector-lite candidate crop，不得退回 pre-crop plan、line plan、TextRegion crop bbox、Vision OCR bbox 或 ground truth 框。可以基于 `directionHint` 对 crop 做保守 padding、0/90° 方向变体或内容放大，但必须记录在 candidate ledger。
5. 输出 OCR raw text、normalized text、empty / non-empty、word preservation、quality score、与当前 `finalTextUsedForTranslation` 的对照、与 ground truth 的 evaluation-only 相似度、better / worse / same / empty 分类、失败原因和 stop / next action。
6. 不替换主 OCR 输入，不改变 `finalTextUsedForTranslation`、主覆盖图、`blockPassed`、`failureCategory`、`translationDecisionTrace`、translation prompt、模型、`configuration.currentBlockSource` 或 `textRegionCropReport.adoptedCount`。
7. 不新增 LLM 调用。v1.40 只做 TextBoxes -> OCR 的结构复刻评估，不做翻译模型实验。
8. `koharuArtifactConvergenceReport.referenceReports`、`workItemLedger` 和 `gateLedger` 中联动 v1.40。
9. `1_ocr_probe_text.txt` 必须新增 shadow OCR report summary、candidate OCR ledger、逐块 detector-lite shadow OCR 对照和 convergence v1.40 work item 摘要。

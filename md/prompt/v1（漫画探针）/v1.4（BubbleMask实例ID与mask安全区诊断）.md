# AITRANS Agent B / Koharu 提示词：v1.4（BubbleMask 实例 ID 与 mask 安全区诊断）

## 版本号
v1.4（漫画探针 / BubbleMask 实例 ID 近似与 mask 安全区诊断）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入，v1.1 已完成 post-fusion 重复碎片清理和气泡分割审计，v1.2 已接入 TextRegion crop OCR 候选层，v1.3 已新增轻量 `bubbleSubRegionReport` 并让 TextRegion crop 能优先使用 block-local subregion clamp。

v1.3 的关键结论是：subregion 诊断让 oversized bubble 的局部证据更清楚，但它仍主要是 bbox 近似，不是真正的 Koharu 式 `BubbleMask`。当前 `textRegionCropReport.adoptedCount = 0`，说明继续放宽 crop 采用规则没有依据。下一步应补 Koharu 更核心的结构层：为每个 bubble 生成可审计的实例 ID mask 近似，用 mask 计算 seed 归属、safe area、mask-safe layout rect、crop 是否越界和渲染碰撞，而不是继续只依赖 bubble bbox / subregion bbox。

本轮是 v1.4：实现 ground-truth-free 的轻量 BubbleMask 实例 ID 近似和 mask 安全区诊断。它优先改善几何约束、覆盖布局和后续 crop 判断证据；不要把它说成 OCR 已经提升。

## 问题定义
当前 bubble 表达仍偏弱：

- `bubbleID + bbox` 不能表达气泡尾巴、凹陷、相邻气泡接触和内部安全像素。
- subregion bbox 能缩小 crop，但不能判断文本 seed 下到底属于哪个 bubble ID 像素占多数。
- safe layout 只能检查矩形，不能检查译文 sprite 是否仍在真实气泡区域内。
- glyph mask 和背景填充已有，但缺少实例 bubble mask 作为更硬的边界。

Koharu 的关键做法是 `BubbleMask`：每个气泡一个实例 ID，后续 seed 归属、安全区、清字扩张、渲染碰撞都基于这个 ID mask。AITRANS 本轮不接入分割模型，但可以用现有近白连通域、bubble bbox、content crop 和 OCR seed 生成轻量近似 ID mask，并把它作为诊断和安全区来源。

## 目标
实现一个可审计、可回退、ground-truth-free 的 BubbleMask 实例 ID 近似诊断层：

1. 为现有 bubble candidates 生成轻量 `bubbleMaskReport`，报告每个 bubble 的 instance ID、bbox、mask pixel count、coverage、source、confidence、risk flags 和 notes。
2. 在内容图坐标系中生成 bubble ID mask 近似：背景为 0，每个 bubble 为稳定 ID；重叠区域要有确定规则，例如小 bubble / 高置信 bubble 优先。
3. 用 mask 重新审计 block seed 归属：统计 block bbox 或 seed bbox 下各 bubble ID 像素数，记录 `maskDominantBubbleID`、`maskDominantCoverageRatio`、是否与当前 `bubbleID` 一致。
4. 为每个 bubble 计算 mask-safe layout 诊断：安全像素数量、safe bbox、最大近似安全矩形、fallback reason。
5. 将 overlay safe layout 从纯 bbox inset 增强为“有可信 mask-safe rect 时优先使用 mask-safe rect，否则回退现有 bbox inset / block fallback”。
6. 对渲染碰撞新增 mask 检查：离屏译文 sprite 的非透明像素是否落在所属 bubble ID mask 内；失败时继续沿用现有字号回退，不能静默越界。
7. TextRegion crop 不放宽采用规则，但要记录 crop bbox 与 mask 的关系：是否越出 parent bubble mask、mask 内覆盖比例、是否因 mask coverage 低而只能回退 bbox clamp。
8. 输出 JSON / TXT / PNG 证据，让 Agent C 能回答：mask 是否可信、哪些块 mask 归属不一致、哪些块 safe rect 来源升级、是否出现渲染越界、是否影响 13 块和保护文本。

## 非目标
本轮不要做这些事：

- 不要接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不要更换、下载、提交或默认切换翻译模型。
- 不要把 `test/1.ground_truth.json` 用于 mask 生成、bubble 归属、safe rect、crop clamp、候选采用、排序或回退。
- 不要放宽 TextRegion crop 采用规则来制造 `adoptedCount`。
- 不要把 deterministic correction 纳入 `finalTextUsedForTranslation` 主流程。
- 不要把 tagged batch translation 替换逐块翻译。
- 不要为了提高 OCR 相似度跨气泡合并。
- 不要重构普通图片 OCR、文本翻译、历史、Pro、StoreKit、语音或模型下载链路。
- 不要把 mask-safe layout 的渲染收益说成 OCR 识别质量提升。
- 不要把 `likelyRuleFalseFailureBlocks = []` 解释成规则太严格。

## 实现步骤
### 1. 先做基线核查
实现前从当前 `output/probe_report.json` 和 `output/1_ocr_probe_text.txt` 列出：

- 13 个块的 `index`、`bubbleID`、`bbox`、`safeLayoutSource`、`safeLayoutRect`、`glyphMaskPixelCount`、`backgroundFillApplied`、`finalTextUsedForTranslation`、`failureCategory`。
- `bubbleSubRegionReport` 的 `totalSubRegions`、`clampEligibleCount`、`oversizedBubbleIDs`。
- `textRegionCropReport` 的 `adoptedCount`、`rejectedCount`、`mainRejectionReasons`、各块 `clampSource`。
- 当前 `bubbleAudits` 中 `bubbleSplitCandidate = true` 的 bubble。

把观察写进最终回复。不要只看覆盖图猜原因。

### 2. 新增 BubbleMask 报告模型
在 `TranscriptModels.swift` 中新增轻量 Codable 结构。命名可调整，但报告必须表达这些字段：

```swift
struct MangaOverlayBubbleMaskInstanceDiagnostic: Equatable, Codable, Sendable {
    var bubbleID: Int
    var bbox: [Double]
    var maskPixelCount: Int
    var bboxPixelCount: Int
    var maskCoverageRatio: Double
    var source: String
    var confidence: Double
    var safePixelCount: Int
    var safeBBox: [Double]?
    var safeRect: [Double]?
    var safeRectCoverageRatio: Double
    var riskFlags: [String]
    var notes: [String]
}

struct MangaOverlayBubbleMaskBlockDiagnostic: Equatable, Codable, Sendable {
    var blockIndex: Int
    var currentBubbleID: Int?
    var maskDominantBubbleID: Int?
    var maskDominantCoverageRatio: Double
    var maskIDsUnderSeed: [String: Int]
    var bubbleIDConsistent: Bool
    var safeLayoutSourceBeforeMask: String?
    var safeLayoutSourceAfterMask: String?
    var maskSafeRect: [Double]?
    var renderMaskCollisionChecked: Bool
    var renderMaskCollisionResolved: Bool
    var renderMaskOverflowPixelCount: Int
    var cropMaskCoverageRatio: Double?
    var cropMaskRejectedReason: String?
}

struct MangaOverlayBubbleMaskReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var imageWidth: Int
    var imageHeight: Int
    var instanceCount: Int
    var instances: [MangaOverlayBubbleMaskInstanceDiagnostic]
    var blockDiagnostics: [MangaOverlayBubbleMaskBlockDiagnostic]
    var maskSafeLayoutBlocks: Int
    var bboxFallbackBlocks: Int
    var inconsistentBubbleAssignmentBlocks: [Int]
    var renderMaskOverflowBlocks: [Int]
    var notes: [String]
}
```

可以挂在顶层 `probe_report.json` 的 `bubbleMaskReport`，也可以挂在 `bubbleGeometry` 下。优先选择最小侵入方案，但 JSON 和 `1_ocr_probe_text.txt` 必须能看见。

### 3. 生成轻量 BubbleMask 实例 ID 近似
新增纯函数式步骤，建议放在 `MangaOverlayProbeService` 或 `TranslationSessionStore` 的探针私有区：

```text
content image + bubble candidates + fused blocks + bubbleSubRegionReport
  -> rasterize bubble instance ID mask
  -> refine with near-white content / OCR seed if available
  -> resolve overlaps
  -> compute per-instance stats
  -> compute per-block dominant bubble ID
```

规则建议：

- mask 坐标必须与现有 bbox 坐标系一致，仍按原图左上角为原点。
- 初版可用 bubble bbox 内的近白像素 / 连通域像素作为 mask；如果实现复杂，可先 rasterize ellipse/rounded-rect approximation，但必须在 notes 里写清楚来源和局限。
- 背景 ID 为 0；bubble ID 要与现有 `bubbleID` 对齐，避免下游字段难以追踪。
- 重叠区域使用稳定规则：更小 bbox、高置信、seed 覆盖更多者优先；规则要写入 report notes。
- 对 `bubbleID 4/6/7` 这种 oversized bubble，记录 `riskFlags`，但不要本轮强行重分配文本块。
- 无法生成可信 mask 的 bubble 必须保留 bbox fallback，并写 `riskFlags` / `notes`。
- 不得使用真值文本、相似度或人工标注参与任何 mask 生成和排序。

### 4. 计算 mask-safe rect
为每个 bubble instance 计算安全区。可以先做轻量版，不要求完整 Koharu distance transform，但需要可审计：

- 从 instance mask 中排除边缘 padding。
- 若能实现距离场，记录最大安全点和近似最大安全矩形。
- 若不实现距离场，至少用 mask 内像素 bbox + inset 生成 `safeRect`，并标注 `source = maskInsetApproximation`。
- 如果 safe 像素太少、safe rect 过小、mask coverage 太低，回退现有 `bubbleInsetSingle` / `bubbleInsetSegment` / `blockFallbackNoBubble`。
- 多块同 bubble 仍要保留现有分区策略，不能让多个译文抢同一整气泡 safe rect。

### 5. 接入 safe layout 和渲染碰撞
扩展现有 safe layout / render diagnostic：

```text
block seed bbox
  -> mask dominant bubble ID
  -> mask safe rect candidate
  -> existing multi-block partition rule
  -> render sprite
  -> check non-transparent pixels against safe rect and bubble ID mask
  -> font fallback / truncation rule
```

必须记录：

- `safeLayoutSourceBeforeMask`
- `safeLayoutSourceAfterMask`
- `maskSafeRect`
- `renderMaskCollisionChecked`
- `renderMaskOverflowPixelCount`
- `renderMaskCollisionResolved`

如果 mask 检查失败，不能破坏当前覆盖图生成；必须回退现有 bbox safe rect，并在 report 里写明。

### 6. 接入 TextRegion crop 诊断，但不放宽采用
TextRegion crop 仍保持 v1.2 / v1.3 护栏。新增的 mask 只能作为诊断和 clamp 可信度信号：

- 记录 crop bbox 与 parent bubble mask 的覆盖比例。
- 如果 crop 大量越出 mask，记录 `cropMaskRejectedReason = lowMaskCoverage`，但不要直接用真值判定好坏。
- subregion clamp 已存在时，可比较 `subRegionBBox` 与 `maskSafeRect` 的关系，写入 notes。
- 不得为了让 `adoptedCount > 0` 放宽 `rawWordsLost`、`wordCountRegression`、`introducedLikelyOCRError` 等拒绝规则。

### 7. 更新输出文本和图像证据
同步更新：

- `probe_report.json`：新增 `bubbleMaskReport` 或等价结构。
- `1_ocr_probe_text.txt`：每块显示 mask dominant ID、coverage、safe rect、render mask collision、crop mask coverage。
- `1_bubble_debug.png` 或 `1_probe_contact_sheet.png`：如果实现成本可控，叠加 mask-safe rect 或 mask outline。颜色要区别 parent bubble bbox、subregion bbox 和 mask-safe rect。若不画图，必须在最终回复说明本轮只输出 JSON/TXT mask 证据。

### 8. 强保护 v1.3 成果
本轮不能回归：

- `configuration.currentBlockSource` 默认仍保持 `fusedWholePageBubble`，除非 TextRegion crop 真的通过原护栏被采用。
- `fusionComparison.postFusionCleanup.applied = true` 仍要存在。
- `fusionComparison.postFusionCleanup.blockCountBeforeCleanup = 16`、`blockCountAfterCleanup = 13`、`rejectedBlockCount = 3` 的语义不能被破坏。
- 三条保护文本不能丢：
  - `Let's Battle!`
  - `What are you even talking about?`
  - `We need to get results at this tournament to save the gaming club from being disbanded.`
- `bubbleSubRegionReport.totalSubRegions = 11`、`clampEligibleCount = 2` 的语义不能被无意改坏；如因 mask 接入需要变化，必须解释。
- `textRegionCropReport` 仍要完整记录 13 个 region 和拒绝原因。
- `frameworkComparison.consistencyPassed` 和 `fusionComparison.consistencyPassed` 必须继续可解释。
- 失败块仍必须保留在 `blocks` 明细，并在覆盖图显示 `翻译失败 + OCR 原文`。
- 输出目录每轮必须清理，不能混入旧 PNG / JSON。

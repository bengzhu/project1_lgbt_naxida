# AITRANS Agent B / Koharu 提示词：v1.8（Koharu 式上游 TextBoxes 候选规划与 shadow 验证）

## 版本号
v1.8（漫画探针 / Koharu 式上游 TextBoxes 候选规划与 shadow 验证）

## 版本分配依据
v1.0 已把 whole-page 与 bubble-first 融合成 `fusedWholePageBubble` 主输入。v1.1-v1.6 依次补上 post-fusion cleanup、TextRegion crop、BubbleMask 子区域、BubbleMask 实例 ID、归属修正、split candidate、TextBox / SegmentMask 轻量证据层。v1.7 已实现 `cropExperimentReport`，把现有 TextRegion crop control 与最多 3 个 shadow 候选放进实验矩阵。

v1.7 的结果说明：继续只枚举 crop 变体还不够，必须把 Koharu 的核心顺序前移，即先形成 OCR 前的结构化 `TextBoxes / BubbleMask / SegmentMask` 候选，再让局部 OCR 验证它们，而不是从 TextRegion crop 结果反推 TextBox。

- 下一步不是放宽 `adoptedCount`，而是建立 OCR 前候选规划层，区分“几何候选本身是否可靠”和“Vision 局部 OCR 是否退化”。

## 背景
Koharu 的核心链路不是整页 OCR 后再修补，而是：

```text
SourceImage
  -> TextBoxes
  -> SegmentMask
  -> BubbleMask
  -> OcrText
  -> Translations
  -> Inpainted / RenderedSprites / FinalRender
```

AITRANS 当前已有近似 `BubbleMaskReport`、`TextBoxCandidateReport`、`SegmentMaskReport`、`TextRegionCropReport` 和 `cropExperimentReport`，但它们的执行顺序仍偏后置诊断：

- `TextBoxCandidateReport` 目前派生自 TextRegion crop 后的 bbox，`derivedFromTextRegionCrop = true`。
- `SegmentMaskReport` 聚合现有 glyph mask 和近似 BubbleMask 覆盖率，但还不是 OCR 前的 TextBox refinement 输入。
- `cropExperimentReport` 说明某些 shadow 候选可能优于 control，但没有把候选规划变成可复用的上游 artifact。

v1.8 的任务是建立一层“上游 TextBoxes 候选规划”，以 Koharu 的 artifact 思路组织现有信号，但仍保持 shadow-only，不改变主翻译输入。

## 目标
实现一个可审计、ground-truth-free、OCR 前生成的上游候选规划层。命名可调整，但语义必须清楚，例如：

- `preCropTextBoxPlanReport`
- `textBoxPlanningReport`
- `koharuArtifactPlanningReport`

至少满足：

1. 在 TextRegion crop OCR 之前，为每个 fused block 生成 `TextBoxPlan` 候选，而不是从 crop 结果反推 TextBox。
2. 每个候选只使用生产可用结构信号：fused seed bbox、bubbleID、bubble geometry、BubbleMask majority ID、subRegion、split candidate、assignment correction、glyph/SegmentMask evidence、safeLayoutRect/maskSafeRect、OCR observation bbox。
3. 报告每个候选的 `planID`、`blockIndex`、`variantName`、`sourceSignals`、`bbox`、`bubbleID`、`dominantBubbleID`、`bubbleCoverageRatio`、`glyphCoverageRatio`、`safeRectCoverageRatio`、`estimatedOrientation`、`riskFlags`、`rejectionReasons`、`eligibleForShadowOCR`。
4. 每块最多保留 3 个上游 TextBox plan；排序和截断必须 ground-truth-free。
5. 将符合条件的 plan 接入一个新的 shadow OCR 对照，或扩展 v1.7 `cropExperimentReport`，明确标记来源为 `preCropTextBoxPlan`。
6. 本轮不得把任何 plan 的 OCR 结果写入 `finalTextUsedForTranslation`，不得改变 `textRegionCropReport.adoptedCount` 的含义。
7. 报告要能回答：哪些块是几何候选不足，哪些块是局部 Vision OCR 退化，哪些块因 BubbleMask/SegmentMask 证据弱应停止继续 crop。
8. `1_ocr_probe_text.txt` 必须输出每块的上游 TextBox plan 摘要、shadow OCR 结果、拒绝/停止原因。
9. 若发现 v17 的 `cropExperimentReport` 语义或字段命名会误导为“已上游采用”，必须修正命名或 notes。

## 非目标
本轮不要做这些事：

- 不接入新 OCR 模型、Core ML 模型、PaddleOCR、Koharu Rust/Candle、网络服务或外部依赖。
- 不更换、下载、提交或默认切换翻译模型。
- 不用 `test/1.ground_truth.json` 参与候选生成、排序、晋级、采用或回退。
- 不放宽 TextRegion crop 采用规则，不为了制造 `adoptedCount > 0` 修改护栏。
- 不把 `bestShadowCandidate`、`preCropTextBoxPlan` 或局部 OCR 结果写入 `finalTextUsedForTranslation`。
- 不改变 `fusedWholePageBubble` 主流程、post-fusion cleanup、失败块绘制或翻译质量判定。
- 不把 deterministic correction、tagged batch translation 或 clean text diagnostic 替换主流程。
- 不为了提高相似度跨气泡合并。
- 不把几何诊断收益描述成 OCR 准确率提升，除非完整探针数字证明。
- 如果 `likelyRuleFalseFailureBlocks = []`，不要声称规则太严格。

## 实现步骤
### 1. 先做 v17 基线核查
实现前从当前输出提取并写入最终回复：

- 顶层数字：13 blocks、13 matched、0 unmatched、core/decorative OCR similarity、TextRegion crop 13/10/0/13、cropExperiment 52/13/43/15/0。
- `cropExperimentReport.variantBreakdown`，特别是 `glyphMaskExpanded`、`maskSafeRectConstrained`、`textBoxTight` 的 attempted / succeeded / better / rawWordsLost。
- `cropExperimentReport.blockSummaries` 中每块的 `promotionVerdict` 和 `stopReasons`。
- `textRegionCropReport.diagnostics` 中 `emptyCropText`、`rawWordsLost`、`localVisionRegression`、`bubbleMaskConflict`、`segmentMaskWeak` 的块。
- 三条保护内容是否仍在明细中：`Let's Battle!`、`What are you even talking about?`、`We need to get results...`。

### 2. 新增上游候选规划模型
在 `TranscriptModels.swift` 新增 Codable / Sendable 报告模型。字段名可按现有风格调整，但必须表达以下语义：

```swift
struct MangaOverlayPreCropTextBoxPlan: Equatable, Codable, Sendable {
    var planID: Int
    var blockIndex: Int
    var variantName: String
    var sourceSignals: [String]
    var bbox: [Double]
    var seedBBox: [Double]
    var bubbleID: Int?
    var dominantBubbleID: Int?
    var bubbleCoverageRatio: Double?
    var glyphCoverageRatio: Double?
    var safeRectCoverageRatio: Double?
    var estimatedOrientation: String
    var evidenceScore: Double
    var eligibleForShadowOCR: Bool
    var riskFlags: [String]
    var rejectionReasons: [String]
    var notes: [String]
}

struct MangaOverlayPreCropTextBoxPlanBlockSummary: Equatable, Codable, Sendable {
    var blockIndex: Int
    var selectedPlanIDsForShadowOCR: [Int]
    var rejectedPlanIDs: [Int]
    var planningVerdict: String
    var stopReasons: [String]
    var notes: [String]
}

struct MangaOverlayPreCropTextBoxPlanReport: Equatable, Codable, Sendable {
    var enabled: Bool
    var evaluatedBlockCount: Int
    var planCount: Int
    var shadowOCREligiblePlanCount: Int
    var selectedForShadowOCRBlocks: [Int]
    var stoppedBlocks: [Int]
    var blockSummaries: [MangaOverlayPreCropTextBoxPlanBlockSummary]
    var plans: [MangaOverlayPreCropTextBoxPlan]
    var notes: [String]
}
```

报告必须写入 `probe_report.json` 顶层。若命名不同，文档和 TXT 输出必须同步。

### 3. 在 TextRegion crop 之前生成计划
新增函数，例如：

```text
makePreCropTextBoxPlanReport(
  blocks,
  bubbleGeometry,
  preliminaryBubbleMaskReport,
  bubbleAssignmentCorrectionReport,
  bubbleSplitCandidateReport,
  bubbleSubRegionReport,
  image
)
```

执行位置建议：

```text
recognized / fused blocks
  -> post-fusion cleanup
  -> preliminary BubbleMask / assignment correction / split / subRegion
  -> preCropTextBoxPlanReport
  -> TextRegion crop control
  -> TextBox / SegmentMask downstream diagnostics
  -> cropExperiment shadow validation
```

注意：v1.8 的 `preCropTextBoxPlanReport` 必须早于 `TextRegion crop`，否则不能称为上游候选规划。

### 4. 候选 plan 来源和限制
每块最多生成这些候选，然后按 evidence score 截断到 3 个：

- `seedTightTextBox`：从 fused seed bbox 轻量扩张/收紧，作为最保守候选。
- `bubbleContainedTextBox`：seed bbox 扩张后 clamp 到当前 bubble bbox 或 corrected bubble bbox。
- `subRegionTextBox`：仅当 subRegion clamp eligible。
- `splitCandidateTextBox`：仅当 split candidate clamp eligible，且不是 decorative / protected short text。
- `maskMajorityTextBox`：根据 BubbleMask majority ID 和 safe rect 约束生成。
- `glyphAnchoredTextBox`：仅当已有 glyph/SegmentMask evidence 可用，且 glyph 不逃逸 TextBox / BubbleMask。

限制：

- `decorative`、unassigned 短保护文本、`Let's Battle!` 只允许保守 diagnostic plan。
- `segmentMaskWeak` 块不生成 glyph-driven plan。
- BubbleMask dominant coverage 低于阈值的块只能 diagnostic，不进入 shadow OCR。
- block 在 v17 已有 `localVisionCropNotPromising` 且没有新的几何证据时，应输出 stop reason，不要继续跑更多 OCR。

### 5. ground-truth-free evidence score
score 只能用生产可用信号，建议考虑：

- seed bbox 与 plan bbox 的覆盖关系。
- plan bbox 是否在当前/修正 bubble mask 内。
- dominant bubble ID 是否与 block bubbleID 一致。
- safe rect coverage。
- glyph / SegmentMask 覆盖。
- bbox 面积相对 seed 的膨胀比例。
- 与 sibling block bbox 的重叠风险。
- 是否 decorative / protected short text。
- 是否来自 split candidate、subRegion、assignment correction 等高风险信号。

不要使用 `bestGroundTruthText`、`ocrGroundTruthSimilarity`、`test/1.ground_truth.json` 或任何真值相似度。

### 6. 接入 shadow OCR 验证
可以选择以下两种实现之一：

1. 扩展 `makeCropExperimentReport(...)`，让 `preCropTextBoxPlan` 作为新的 variant 来源；
2. 新增独立 `preCropTextBoxShadowOCRReport`，但要避免与现有 `cropExperimentReport` 语义重复。

无论哪种，都必须记录：

- planID / variantName / bbox
- OCR text
- 是否空输出
- raw word preservation
- quality delta vs control
- localVisionRegression
- rawWordsLost
- introducedLikelyOCRError
- 是否因几何弱证据拒绝

本轮仍不得改变主块文本、主翻译、覆盖图译文和 `adoptedCount`。

### 7. TXT 和文档输出
更新 `1_ocr_probe_text.txt`：

- 每块列出 pre-crop TextBox plans。
- 标出 selected for shadow OCR 的 plan。
- 标出 rejected / stopped reason。
- 对比 control crop 与 best pre-crop plan OCR。
- 明确写 `shadowOnly`、`groundTruthNotUsed`、`notWrittenToFinalTextUsedForTranslation`。

更新文档：

- README：近期优化记录追加 v18 / v1.8 关键数字。
- `update_log.md`：追加版本记录、关键结论、遗留问题。
- `md/flow/flow.md`：把 pre-crop TextBox plan 放到 TextRegion crop 之前。
- `md/flow/flowchart.md`：同步流程图。
- `md/test/test.md`：若新增字段成为基线，更新 Stage Regression 关键数字。

## 验收标准
通过条件：

1. `probe_report.json` 顶层出现 pre-crop TextBox planning 报告，且字段语义清楚。
2. 该报告在 TextRegion crop 之前生成，notes 和 TXT 不得暗示它来自 crop 后派生。
3. 每块最多 3 个上游 plan，候选规模可控。
4. 候选排序、eligibility、shadow OCR 选择均不使用 ground truth。
5. `finalTextUsedForTranslation`、主译文、覆盖图主输入、`textRegionCropReport.adoptedCount` 不因本轮改变。
6. `cropExperimentReport.promotedShadowBlocks` 若仍为空，必须如实记录；不要为了好看降低晋级门槛。
7. 三条保护文本仍保留：`Let's Battle!`、`What are you even talking about?`、`We need to get results...`。
8. `frameworkComparison.consistencyPassed = true`、`fusionComparison.consistencyPassed = true` 仍成立。
9. `1_ocr_probe_text.txt` 可直接读出每块 plan、shadow OCR、拒绝原因和 stop reason。
10. README、update_log、flow、flowchart、test、version_history 与最新输出同步。

## 风险和禁止项
- 最大风险是把“上游候选规划”误写成“已经采用的 TextBox 主流程”。字段、notes、最终回复都必须强调 shadow-only。
- 第二风险是计划生成太多，导致探针运行慢或输出不可读。每块候选必须硬限制。
- 第三风险是从真值或 OCR 相似度反向调参。真值只能用于事后评估，不得参与选择。
- 第四风险是继续在 v17 已停止的块上盲目跑 crop。若没有新几何证据，应输出 stop reason。
- 第五风险是把翻译失败归因错给 OCR。clean text 仍只有 `0.4545`，Gemma 270M 不是翻译质量基准。

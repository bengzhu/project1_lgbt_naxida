# AITRANS Agent B 提示词：v2.0（GitHub Actions 云端验证与 ABC 流程收敛）

## 版本号
v2.0（云端协作流程 / GitHub Actions 云端验证与 ABC 流程收敛）

## 版本分配依据
这是协作制度、分支流、验证执行位置和 `AGENTS.md` 入口规范的结构性调整，不属于漫画探针 v1 小优化，因此新开 v2 阶段。

## 你的身份
你是 Agent B。本轮任务是实现文档和必要 CI 配置修改，不做漫画探针算法优化，不改 OCR / 翻译主流程。

你的最终回复第一行必须写：

```text
我是 Agent B。
```

## 背景
当前 AITRANS 的本地验证成本过高。Swift / Xcode build、模拟器探针、输出导出和 JSON/PNG artifact 检查会持续消耗本机资源。后续工作流要改成：

```text
人工目标
  -> Agent A 本地分析并写版本化提示词
  -> Agent B 本地实现 + 轻量检查
  -> Agent B 推送 codeb/vX.Y-短标题 分支到 GitHub
  -> GitHub Actions 云端跑 build / 探针 / JSON 检查 / artifact 上传
  -> Agent C 拉取分支，审查 diff、CI 日志和 artifacts
      -> 有 bug：C 写退回清单，B 继续修并 push
      -> 无 bug：C 更新版本号和核心文档，合并到 samlldata_test
```

分支策略必须改变：

- `main` 只作为外观展示分支，不作为日常开发主分支。
- `samlldata_test` 是本项目实际工作主分支。
- Agent B 的实现分支必须命名为 `codeb/vX.Y-短标题`。
- Agent C 验收通过后必须及时合并回 `samlldata_test`，避免堆积一批长期未合并分支。
- 严禁把 Agent B 或 Agent C 的工作合并到 `main`。

## 本轮目标
1. 精简并强化 `AGENTS.md`，让它成为更短、更硬、更快读的入口规则。
2. 把云端验证工作流写入 `AGENTS.md`、`md/test/test.md`、`md/flow/flow.md` 和 `md/flow/flowchart.md`。
3. 明确 `a:` / `b:` / `c:` 召唤规则：
   - 用户消息以 `a:` 或 `A:` 开头，表示召唤 Agent A。
   - 用户消息以 `b:` 或 `B:` 开头，表示召唤 Agent B。
   - 用户消息以 `c:` 或 `C:` 开头，表示召唤 Agent C。
   - 若没有这些前缀，则按普通 Codex 任务处理，必要时根据上下文提醒用户指定角色。
4. 明确每个 Agent 的输出身份标识：
   - Agent A 最终回复第一行必须写 `我是 Agent A。`
   - Agent B 最终回复第一行必须写 `我是 Agent B。`
   - Agent C 最终回复第一行必须写 `我是 Agent C。`
5. 把 GitHub Actions 作为重验证默认路径，降低本机 Mac 编译和模拟器压力。
6. 如果仓库当前没有 Actions workflow，则新增最小可用 `.github/workflows/ci.yml`；如果已有 workflow，则按本提示词更新。

## 非目标
- 不修改漫画 OCR、翻译、覆盖绘制、报告模型、模型下载、llama.cpp 封装或 Swift UI 业务逻辑。
- 不刷新 `output/` 漫画探针产物。
- 不追加 `metrics/version_history.csv` 漫画指标行，除非本轮确实运行了完整探针并生成新基线。
- 不合并到 `main`。
- 不把本轮流程制度变更伪装成漫画探针质量提升。

## AGENTS.md 改写要求
`AGENTS.md` 要精简优化，目标是降低每轮上下文负担。保留硬规则，压缩长历史和重复指标。

建议结构：

```text
# AGENTS.md
## 0. 角色召唤和身份标识
## 1. 项目核心事实
## 2. 每轮必读
## 3. 架构硬边界

```

精简原则：

- 不在 `AGENTS.md` 长篇复制所有历史指标；只保留“当前基线以 `update_log.md`、`metrics/version_history.csv`、最新 `output/` 为准”。
- 大段历史、详细基线和版本数字移交给 `update_log.md`、`md/test/test.md`、`md/flow/flow.md`。
- 漫画探针保留不可破坏硬规则，例如失败块不能静默跳过、ground truth 不能参与生产选择、输出目录必须清理、可信匹配可拒绝。
- 保留当前关键架构边界：`TranslationSessionStore` 是统一调度中心；漫画探针走 `MangaOverlayProbeService`；模型文件不进仓库。
- 删除重复解释和低频细节，避免入口文档过长影响模型性能。

## 分支与合并规则
写入 `AGENTS.md`、`md/flow/flow.md` 和 `md/test/test.md`：

- `main`：展示分支。禁止 Agent B / C 把日常开发成果合并到 `main`。
- `samlldata_test`：实际工作主分支。Agent C 验收通过后合并到这里。
- `codeb/vX.Y-短标题`：Agent B 候选实现分支。示例：`codeb/v2.0-cloud-ci-workflow`。
- Agent B 每轮从最新 `samlldata_test` 开分支，完成后 push。
- Agent C 从远端拉取 `codeb/...` 分支验收；通过后合并到 `samlldata_test` 并 push。
- Agent C 合并后应确认候选分支是否已不再需要；可以记录建议删除远端分支，避免堆积。若没有权限删除，必须说明。
- 任何 Agent 在执行 `git push`、`git merge`、删除远端分支或改远端状态前，都必须确认目标分支不是 `main`。

## GitHub Actions 要求
如果仓库当前没有 `.github/workflows/ci.yml`，新增一个最小可用 workflow。

最低要求：

- 触发分支：
  - `samlldata_test`
  - `codeb/**`
- 不触发或不要求保护 `main` 的日常开发验证。
- 至少包含：
  - `git diff --check`
  - `python3 -m json.tool test/1.ground_truth.json`

  - Xcode build：`xcodebuild -project AITRANS.xcodeproj -scheme AITRANS -destination 'generic/platform=iOS Simulator' -derivedDataPath .derivedData CODE_SIGNING_ALLOWED=NO build`
- 尽量上传 build 日志和可用的 `output/` artifacts。

Stage Regression / 漫画探针云端运行：

- 如果 GitHub-hosted macOS runner 无法稳定启动模拟器、无法安装 GGUF、无法访问 App 容器，workflow 必须明确输出“未运行完整探针”的原因。
- 不允许伪造 `output/` 或把旧 artifact 当新结果。
- 若完整漫画探针不能在 CI 跑通，本轮先把 Actions 定位为 build + JSON/static gate，并在 `md/test/test.md` 写清楚限制和后续补齐条件。

注意：GitHub-hosted runner 上默认没有本地 GGUF 模型。不要把模型文件提交到仓库。需要真实 Local 模式探针时，后续应通过缓存、Release asset、外部下载或手动 artifact 方案设计，但本轮不要擅自加入大模型文件。

## Agent A/B/C 新职责
### Agent A
- 召唤方式：用户消息以 `a:` 或 `A:` 开头。
- 最终回复第一行：`我是 Agent A。`

### Agent B
- 召唤方式：用户消息以 `b:` 或 `B:` 开头。
- 最终回复第一行：`我是 Agent B。`

- 按 Agent A 提示词实现。
- 默认本地只跑轻量检查；不要为了完整本机编译和探针消耗 Mac，除非用户明确要求。

- 最终回复必须列出分支名、push 结果、CI 链接或待用户查看的 Actions 入口、本地已跑检查、未跑测试原因。

### Agent C

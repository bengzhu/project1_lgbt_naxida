## 3. 当前事实与必须解决的问题

当前可用能力必须保留：

- 手机使用文本 / 图片 / 音频 / 历史 / 设置五个主入口。
- iPad 使用 `NavigationSplitView`。
- `TranslationSessionStore` 是唯一 UI 状态与业务调度中心。
- 工作台可翻译、切换语言、选择提示词、归档会话并查看最近结果。
- 历史支持搜索、恢复、导入、导出和清空。
- 提示词支持方向切换、新建、复制、编辑、删除和选择。
- 模型页支持 Mock / Local、GGUF 下载 / 导入 / 移除、自检、采样参数与诊断。
- 图片页支持导入、OCR、旁贴 / 覆盖、导出。
- 音频页支持文件识别、实时识别、取消、翻译和 v1.86 识别摘要。
- Pro 锁定 / 解锁、StoreKit 骨架和开发者模式继续存在。
- 漫画探针入口及报告展示继续存在于开发路径中。

当前需要正面解决：

- `ContentView.swift` 超过 3000 行，页面、组件、主题和格式化逻辑混在一起。
- `AppTheme.swift` 只有少量散落颜色，无法支撑统一的企业级设计系统。
- 大量固定字号、固定透明度、20+ 圆角和重复 `.panelStyle()` 造成层级单一、卡片套卡片和小屏拥挤。
- 当前深色背景、渐变和发光效果偏装饰，真正的状态层级、操作优先级和数据可扫描性不足。
- 空状态、加载、失败、成功、禁用、锁定等状态缺少统一组件语义。
- 当前仍有 `PreviewProvider`、大量局部视图类型和重复按钮实现，维护成本高。
- 仅“能编译”不足以验收本轮；必须有当前 HEAD 的多尺寸、多状态视觉证据。

## 4. 核心目标

### 4.1 建立 AITRANS 设计系统

把视觉规则集中到明确的主题 / token 层，至少覆盖：

- 语义颜色：canvas、surface、surfaceRaised、border、textPrimary、textSecondary、accent、accentStrong、success、warning、danger、locked。
- 间距：页面边距、区段间距、组件内边距、紧凑 / 标准密度。
- 圆角：企业工具界面默认不超过 8pt；圆形录音按钮、系统胶囊状态等确有语义的控件除外。
- 描边、阴影和材质：只保留能表达层级、焦点或浮层关系的效果。
- 动效时长、曲线和 Reduce Motion 回退。
- 触控尺寸：所有可交互目标至少 44x44pt。
- 布局宽度：手机紧凑区、平板内容区、设置 / 诊断高密度区。

视觉基调：

- 以接近黑色的中性炭灰、清晰冷白和高亮电光青作为主轴。
- 绿色、琥珀色、红色只承担成功、警告、错误语义；可有少量辅助色，但不能把整站做成单一蓝紫或满屏渐变。
- 科技感来自精确排版、清晰状态、细分隔线、实时反馈、数据读数和克制材质，不来自发光球、bokeh、渐变 orb 或持续闪烁。
- 大面积背景保持稳定、低噪声；禁止每个区块都浮成卡片。
- 卡片只用于可重复数据项、独立工具和弹层；页面区段采用无框分组、分隔线或全宽带状层级。
- 禁止卡片套卡片；禁止用大圆角和半透明面板掩盖信息结构问题。
- 重要主操作可以明亮醒目，但同屏只能有清楚的一个最高优先级。
- “秒译”品牌在首屏可见但保持紧凑，禁止新增营销 landing page、超大 hero 或功能说明墙。

实现要求：

- 保持 iOS 17 deployment target，不能无保护地使用 iOS 18 / 26 only API。
- 使用 SwiftUI / SF Symbols，不新增第三方 UI、动画或快照框架。
- 优先语义字体和 Dynamic Type；避免散落 `.font(.system(size: ...))`。
- 优先 `foregroundStyle()`、`clipShape(.rect(cornerRadius:))`、`Label`、`ContentUnavailableView`、`ViewThatFits`、`containerRelativeFrame()` 等与 iOS 17 兼容的现代 API。
- 不因新 API 偏好强行迁移整个 `ObservableObject` / `@EnvironmentObject` store；本轮保留现有状态架构，避免 UI 重构扩大为 24000+ 行 store 迁移。

### 4.2 重构代码边界

`ContentView.swift` 最终只保留 App 根路由、手机 / 平板导航选择和极少量根级类型。把功能页面和复用组件按职责拆开。

建议结构可按现有工程实际调整，但必须达到同等清晰度：

```text
AITRANS/Views/
  ContentView.swift
  DesignSystem/
    AppTheme.swift
    AppComponents.swift
  TextTranslationView.swift
  HistoryView.swift
  PromptLibraryView.swift
  SettingsView.swift
  ModelManagementView.swift
  DeveloperConsoleView.swift
  ImageTranslationViews.swift
  AudioTranslationView.swift
  ProFeatureViews.swift
  PreviewSupport/
    AppPreviewFixtures.swift
```

边界要求：

- 每个顶层 feature view 独立文件；可复用组件不藏在某个页面文件底部。
- 不要为了文件数量机械创建几十个单行类型；真正独立、可复用或复杂的类型才拆分。
- View `body` 不承载业务逻辑、排序、持久化、模型调用或 Speech 控制。
- 按钮只调用 store 现有方法，或调用 view 内极短的 UI 编排方法。
- 不复制 `TranslationSessionStore` 状态，不创建第二套 store，不让页面直接写 `state.json`。
- 保持 `LocalLanguageModeling`、Vision OCR、Speech 和漫画探针调用边界不变。
- 避免 `AnyView`、高成本嵌套 blur、在 `body` 中重复 filter / sort，以及无必要的 `GeometryReader`。
- 列表数据较多时使用 `LazyVStack` / `LazyVGrid`，并保证稳定 identity。
- Preview fixture 只能构造展示状态，不能污染真实持久化或生产数据。

### 4.3 重做全局导航与页头

手机：

- 保留五个核心入口，避免用户重新学习产品结构。
- 底部导航保持系统行为、清晰选中态和可读标签，不能做成悬浮装饰条遮挡内容。
- 选中态不能只靠颜色，需同时有图标 / 形态或文字层级变化。
- 页面滚动、键盘和安全区下不能遮挡主要操作。

iPad：

- 保留 `NavigationSplitView`，侧边栏应适合高频扫描，明确当前页和模型状态。
- detail 区设置合理最大宽度与双栏机会，不能简单把手机窄列拉宽。
- 横屏利用额外空间并排展示输入 / 输出、主内容 / 状态或列表 / 详情；竖屏安全降级。

页头：

- 品牌、页面名、模型状态、当前任务状态层级明确。
- 不在每页重复巨大 logo 和解释性副标题。
- 状态文案短、可操作；详细说明放到对应详情或帮助弹层，不占首屏核心空间。

### 4.4 重做文本翻译工作台

这是全 App 最高优先级页面，必须在首屏完成主要任务：

- 输入语言、交换、目标语言形成紧凑清楚的控制条。
- 输入区和译文区是页面视觉主角，不能被装饰 hero、指标卡或说明文案抢占。
- 主要“翻译”操作始终醒目；输入为空、处理中、成功和失败有明确状态。
- Prompt 选择、模型状态、最近生成状态可见但为次级层级。
- iPad 宽屏优先输入 / 输出并排；iPhone 纵向排列。
- 长文本可滚动、可选择、不会挤压按钮；键盘弹出后仍能提交和切换语言。
- 译文空状态使用系统语义空状态或克制占位，不显示像已生成的伪内容。
- 处理过程允许使用短暂、克制的状态动效和 `sensoryFeedback()`；Reduce Motion 时改为淡入淡出或无位移动效。
- 保留会话归档、历史恢复和新会话路径，操作位置符合用户心智。

### 4.5 重做图片翻译体验

- 无图片时，主入口明确指向选择图片 / 测试图片，不堆叠说明卡。
- 有图片时，图片是真正的主视觉，不能缩在装饰卡片内部。
- “旁贴 / 覆盖”使用 segmented control；导入、重新识别、导出使用清楚的图标命令。
- OCR / 翻译进度、失败原因、块数量和导出状态统一使用状态组件。
- 覆盖块必须保持可读，不遮住页面工具栏，不因 hover / loading 文案改变整体尺寸。
- iPad 使用更大的图像检查区和独立结果 / 控制区域；iPhone 保持单列并避免超宽按钮。
- 不改变 `VisionOCRService`、bounding box、图片导出和漫画探针的任何业务语义。

### 4.6 重做音频与 Pro 体验

- 音频识别页面以“选择音频 / 长按说话”和当前运行状态为核心。
- `idle / checking / recognizing / translating / completed / failed / cancelled` 必须有一致且可区分的视觉状态。
- v1.86 的运行摘要保留 locale、本机识别、耗时、词数、片段、置信度和失败原因，但改为高密度、易扫描的仪表式布局；不要再套第二层卡片。
- 录音按钮要有明确按压、录制和停止反馈，支持 VoiceOver、Voice Control 和 Reduce Motion。
- Pro 锁定态必须说明动作影响，但不能让整个页面变成营销页；已解锁态直接进入可用工具。
- StoreKit、开发解锁、Speech run UUID、取消和旧回调隔离逻辑不得修改语义。

### 4.7 重做历史、提示词、设置、模型和开发页

历史：

- 搜索、记录列表、打开、删除、导入 / 导出、清空形成明确命令层级。
- 空历史和无搜索结果使用 `ContentUnavailableView`。
- 历史项重点显示语言方向、译文摘要、时间和状态；不要把每项做成巨大卡片。
- 删除与清空必须保留确认和 destructive 语义。

提示词：

- 选择、方向、标题、语气、编辑 / 复制 / 删除一眼可辨。
- 使用 segmented control 切换英译中 / 中译英。
- 编辑器在键盘、长文本和 Dynamic Type 下不溢出。
- 内置提示词锁定态不能只靠颜色表达。

设置 / 模型：

- 按“运行引擎、模型文件、生成参数、数据管理、Pro、开发诊断”建立清晰分组。
- 模型未安装、下载中、可用、校验失败和 Local 启动失败使用统一状态语义。
- 数值参数使用合适的 Slider / Stepper / 输入控件，不用文字按钮伪装控件。
- 危险操作与普通设置分开，避免误触。

开发页：

- 保持高密度、工具化和可扫描，不套用营销式大卡片。
- raw prompt、raw output、错误和探针摘要使用等宽数字 / 文本、可选择内容和明确的 copy 操作。
- 普通用户界面不得泄漏开发入口、密码或调试细节。
- 不更改漫画探针执行、报告字段、ground truth 边界或 output 行为。

## 5. 完整状态要求

不能只设计“有数据且成功”的理想截图。至少覆盖并可预览 / 复现：

- 文本：空输入、已输入、处理中、成功、模型错误。
- 图片：空、已选图、OCR 中、翻译中、成功、部分失败、导出成功 / 失败。
- 音频：idle、recognizing、translating、completed、failed、cancelled。
- 历史：空、多条记录、搜索无结果、导入失败。
- 提示词：内置选中、自定义、编辑、锁定、删除确认。
- 模型：Mock、Local 未安装、下载中、ready、错误。
- Pro：锁定、已解锁、StoreKit 商品不可用。
- 开发：关闭、已开启、raw probe 运行中、错误和漫画报告有数据。

使用 `#Preview` 建立代表性 preview matrix。Preview 必须隔离持久化和真实模型调用，不允许启动下载、Speech、OCR 或漫画探针。

## 6. 无障碍与本地化硬门槛

- 关键正文使用语义字体，支持 Dynamic Type；不得靠大量 `minimumScaleFactor` 把文字缩到不可读。
- 在 Standard、XXL 和一个 Accessibility size 下检查核心页面。
- 所有按钮、Menu、录音、导入、导出、删除、切换控件有准确的可访问名称、值和 hint；视觉 icon-only 仍需保留文字 label。
- 纯装饰图标对 VoiceOver 隐藏；状态图标提供真实语义。
- 颜色不是唯一状态信号；同时使用图标、文字、描边或形态。
- 支持 `accessibilityDifferentiateWithoutColor`、Increase Contrast 和 Reduce Motion。
- 所有交互区至少 44x44pt，焦点顺序与视觉顺序一致。
- 不使用普通 `onTapGesture()` 代替 Button，除非确实需要点击位置或次数，并补足 accessibility traits。
- 用户可见文案继续使用自然、简洁的中文；不在界面展示设计说明、键盘教学或“科技感”等自我描述。
- 长文案和最长语言 / 模型状态不得截断到无法理解，也不得覆盖相邻控件。

## 7. 动效与反馈规范

- 动效只表达导航、状态切换、任务开始 / 完成和直接操作反馈。
- 禁止循环脉冲、持续漂浮、背景粒子、发光 orb、大面积视差和会降低可读性的动画。
- 常规过渡建议 150-250ms，重要状态可使用 SwiftUI spring，但避免多个层级同时运动。
- 使用 `.animation(..., value:)` 或明确 `withAnimation`，禁止无 value 的全局 animation。
- Reduce Motion 下去掉缩放 / 位移，改为 opacity 或无动画。
- 成功、失败和开始录音可使用克制的 `sensoryFeedback()`，不能影响业务逻辑或在状态重复刷新时连发。

## 8. 明确非目标

本轮不做：

- 不更换 Gemma 模型，不下载或提交新 GGUF，不引入云端模型。
- 不改翻译 prompt、采样策略、clean text、OCR、bubble fusion、Koharu 报告或 promotion gate。
- 不用 ground truth 参与任何生产路径。
- 不改 Speech on-device 约束、授权流程、run UUID 隔离、翻译回调隔离或 StoreKit 业务语义。
- 不迁移 `TranslationSessionStore` 到新的 Observation 架构，不进行全仓并发重构。
- 不改 `state.json` schema；如确需保存纯 UI 偏好，必须先说明迁移和默认值，且不得破坏旧数据。
- 不新增登录、云同步、团队后台、Share Extension、ReplayKit Extension 或新的付费功能。
- 不做营销首页、首次启动宣传轮播或纯装饰 3D / Canvas 场景。
- 不添加第三方依赖。
- 不为了视觉改造删除现有可用功能、失败信息、诊断字段或危险操作确认。

## 9. 建议实施顺序

### Phase 1：审计和设计系统

1. 列出当前主导航、核心任务和完整状态，不要直接从颜色开改。
2. 建立主题 token、表面层级、按钮、状态、区段标题、空状态和自适应布局原语。
3. 用一页 preview / fixture 验证 typography、颜色对比、按钮尺寸和 Reduce Motion。

### Phase 2：根导航和文本工作台

1. 瘦身 `ContentView.swift`，先拆根导航和共享组件。
2. 完成 iPhone Tab 与 iPad SplitView。
3. 完成文本输入 / 输出、语言、Prompt、模型状态和主操作。
4. 先让核心首屏达到最终质量，再迁移其他页面，避免旧新风格混杂。

### Phase 3：图片、音频和 Pro

1. 迁移图片检查区与工具栏。
2. 迁移音频运行状态和 v1.86 摘要。

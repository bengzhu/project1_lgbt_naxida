# v1.92 提示词：External TextBox 透视校正 Shadow OCR

## 目标

在不改变主 OCR、翻译和覆盖图的前提下，把 external artifact 的合法四点 `linePolygons` 从 unsupported 账本升级为真实透视校正 shadow OCR 执行路径，并保持失败可拒绝、结果可审计。

## 非目标

- 不伪造或生成 active Koharu 四件套。
- 不实现任意角度 deskew，不替换 Vision / GGUF，不晋级 shadow 文本。
- 不使用 ground truth 选择 polygon、OCR 候选或 promotion。
- 不改 Speech 与 UI。

## 分支

`codeb/v1.92-koharu-line-polygon-warp` -> `smalldata_test`，严禁 `main`。

## 实现要求

- 将 original-image top-left pixel polygon 正确转换到 Core Image 坐标并执行 perspective correction。
- 逐 line OCR 后按输入顺序合并；warp 无输出时保留 bbox / bounded rotation fallback。
- candidate / block summary 必须区分 warp 执行、失败、rotation fallback 与 unsupported arbitrary angle。
- `linePolygonWarpUnsupported` 只能在 warp 未执行或失败时出现；成功执行不得残留该 blocker。
- `finalTextUsedForTranslation`、overlay、`blockPassed`、主流程来源和 active artifact 目录保持不变。

## 验证

- 本地：`git diff --check`、Swift parse、v1.92 contract、validator orientation fixture、active allow-missing、workflow YAML / JSON parse。
- 云端 push：Xcode build + static contracts + 未加密 CI result artifact。
- 真实四件套可用时：另行 `workflow_dispatch probe_mode=ci-fast`，核对 exact commit SHA、identity matched、warp/coverage/orientation 与 shadow OCR 成功数。

## 验收标准

- fixture 输出 `currentShadowOCRSupport.linePolygonWarp = true` 和非空 `orientationLinePolygonWarpSupportedTextBoxIDs`。
- fixture 不再输出 `linePolygonWarpUnsupported`，13 度样例仍输出 `arbitraryRotationUnsupported`。
- Swift 执行路径只有 warp 成功时 `deskewExecuted = true`；失败保持 blocker。
- 无真实四件套时仍为 `manifestMissing`，不得触发或声称真实 artifact probe 通过。

## 4. 首页信息架构：真正极简

### 4.1 第一视口优先级

首页第一视口按以下层级组织：

1. 紧凑品牌 / 模型状态页头。
2. 输入语言、交换、目标语言控制条。
3. 原文输入区及其“粘贴”快捷动作。
4. 唯一最高优先级的“翻译”主按钮。
5. 译文结果 / 处理 / 失败状态。

Prompt、会话命令和最近翻译必须保留，但降为次级：Prompt 可以是输入区工具行中的紧凑命令；新会话、归档和最近翻译放在主要工作区之后，不得抢占第一视口，不得做成巨大卡片。

不得删除这些既有能力来换取“极简”：语言选择、交换、目标语言 Pro 锁定反馈、Prompt 入口、翻译、新会话、归档、最近结果、错误状态和文本选择。

### 4.2 布局

- 紧凑 iPhone 纵向排列输入 / 输出；键盘显示时仍应看到输入区核心操作和 keyboard toolbar。
- iPad / regular width 继续输入 / 输出并排，不得退化为拉宽的手机单列。
- 输入 / 输出是页面主体，可以有清晰边界，但不要卡片套卡片。
- 控件尺寸稳定，状态、图标和 loading 不得引发布局跳动。
- 页面允许滚动；页头和模型状态继续位于工作区 `ScrollView` 外的顶部 safe-area inset。
- 底部 Tab、安全区和软件键盘不得遮挡按钮或译文。

### 4.3 文案与密度

- 删除不帮助操作的解释性副标题和重复标签；不要在 UI 中写“极简”“科技感”“一键粘贴”等设计说明。
- “秒译”品牌保持紧凑，不能变成 hero。
- 空译文状态一句短提示即可，不需要功能说明墙。
- 使用语义字体和自然中文，避免固定大字号和超大留白。

## 5. 首页专属高科技背景

纯色背景必须被明显重做，但背景必须服务于翻译工作台，而不是变成视觉噪声。

### 5.1 建议视觉构成

实现一个仅供 `TextTranslationView` 使用的 `TextWorkspaceBackground` 或同等组件：

- 基础层：非单一纯色的冷中性明暗场，日间使用冷白 / 浅钢灰，夜间使用炭黑 / 深石墨；避免整页只剩蓝紫或单一青色。
- 结构层：细密但克制的技术网格、线路 / 节点轨迹、分区刻度或扫描仪式的静态结构线；密度要低，不能妨碍阅读。
- 焦点层：围绕输入到译文方向形成一条克制的能量路径、边缘高光或局部层次，让用户自然看到翻译主流程。
- 表面层：输入区与译文区在背景上有足够实色 / 材质承托，正文对比度不能依赖背景恰好较暗。

允许使用 iOS 17 兼容的 SwiftUI `Shape`、`Canvas`、`LinearGradient` / `RadialGradient` 的克制组合，但必须满足：

- 不使用离散发光球、gradient orb、bokeh、漂浮粒子、星空、持续扫描动画或大面积模糊。
- 不加入营销 hero、3D 场景、装饰性插画或第三方素材包。
- 不做持续动画；若有状态变化，只能在开始 / 完成时短暂反馈，并提供 Reduce Motion 回退。
- 背景绘制不应在每次状态变化时进行高成本随机计算；几何和 identity 必须稳定。
- 日间 / 夜间都必须明显不是旧纯色背景，同时保持正文、边框和按钮对比。
- Increase Contrast、Differentiate Without Color 和 Reduce Transparency 下仍可读。

如果视觉证据中背景淡到与旧纯色几乎无差别，或强到抢过输入 / 译文，本轮都不能验收。

## 6. 颜色与操作区分

用户要求“一眼分清各种按钮”。必须建立有限但鲜明的首页动作色映射，不能所有按钮继续使用同一灰面板，也不能做成无语义彩虹。

建议映射，可按最终对比度微调：

| 操作 | 视觉角色 | 要求 |
| --- | --- | --- |
| 翻译 | 电光青 / 清亮蓝主动作 | 同屏唯一最高优先级，实色、高对比、带翻译图标和文字 |
| 粘贴 | 青绿 / teal 工具动作 | 与翻译明显不同，带 `doc.on.clipboard` 或系统等价图标和“粘贴”文字 |
| Prompt | 琥珀 / 金黄次级动作 | 带 `text.badge.star` 和当前 Prompt 名，不与警告状态混淆 |
| 交换语言 | 紫红或受控紫色紧凑动作 | 仅小面积使用，图标明确，不能让页面变成紫色主题 |
| 新会话 / 归档 | 中性或低饱和辅助动作 | 放在主工作区之后，不与翻译争夺层级 |
| 清空输入（若保留） | 红色 destructive | 必须使用 destructive 语义，避免误触；不要把红色用于普通操作 |

硬要求：

- 颜色不是唯一识别方式；每个动作同时有 SF Symbol、文字 / accessibility label 和形态层级。
- 所有可交互目标至少 44x44pt。
- 禁用态仍能识别操作类型，不能只把 opacity 降到近乎消失。
- 日间 / 夜间、Increase Contrast 和色觉差异场景中保持足够对比。
- 同屏只允许“翻译”一个主按钮；粘贴、Prompt、会话命令都是次级。
- 熟悉的清空、交换等图标可紧凑显示，但必须有 accessibility label / hint；不熟悉命令使用图标加文字。

## 7. 一键剪贴板粘贴

### 7.1 行为契约

- 输入区附近提供始终可发现的“粘贴”动作，一次点击完成，不再打开菜单、sheet 或确认框。
- 优先使用 SwiftUI `PasteButton(payloadType: String.self)` 或同等系统隐私友好 API。
- 只响应用户明确点击，不在页面出现、`.task`、定时器或后台状态变化时读取剪贴板。
- 只接收纯文本；图片、URL 对象或其他类型不得误写入输入框。
- 剪贴板文本为空或没有兼容文本时，按钮使用系统禁用 / 无内容反馈，不崩溃，不清空现有输入。
- 输入框为空时，粘贴内容直接成为 `store.draftText`。
- 输入框已有非空文本时，不得静默覆盖用户内容；在末尾追加一个换行后再追加剪贴板文本。不要弹二次确认，以保持一键完成。
- 不自动触发翻译；粘贴后让输入区保持可编辑，并把焦点合理留在输入区。
- 不改写系统剪贴板，不把剪贴板内容写入日志、诊断、analytics 或新增持久化字段。

允许在 `TranslationInputPane` 内用很短的 UI helper 更新 `store.draftText`；不要为了粘贴新增第二套 draft state，也不要把剪贴板逻辑塞进漫画探针或模型 service。

### 7.2 无障碍

- 可访问名称为“粘贴剪贴板文本”或同等清楚文案。
- hint 说明空输入会填入、有内容会追加；不要让 VoiceOver 用户猜测是否覆盖。
- 粘贴完成可使用一次克制的 sensory feedback，但不能连发，也不能在 Reduce Motion 下产生位移动画。

## 8. 键盘必须能明确收起

现有 `.scrollDismissesKeyboard(.interactively)` 只能作为辅助，不能继续当作唯一收起方式。

必须同时做到：

1. 保留 `@FocusState` 和 interactive scroll dismiss。
2. 在软件键盘 toolbar 中提供右侧“完成”按钮，使用 `ToolbarItemGroup(placement: .keyboard)` 或 iOS 17 兼容的等价实现。
3. 点击“完成”必须执行 `inputFocused = false`，一次点击收起键盘。
4. 点击“翻译”时先结束输入焦点，再调用 `store.submitDraft`；键盘不能遮住处理中和结果状态。
5. 切换页面或新会话后不能留下错误焦点状态。
6. keyboard toolbar 在紧凑 iPhone、XXL 和 Accessibility Dynamic Type 下不截断、不与系统建议栏冲突。
7. “完成”有准确 accessibility label；不得用只有颜色或无标签的 chevron 代替。

不要通过全局 UIKit appearance、隐藏系统键盘按钮或私有 API 实现。不要给整页加抢占 Button / Menu 点击的全屏 `onTapGesture`。

## 9. 状态、动效与无障碍

至少覆盖这些首页状态：

- 空输入。
- 剪贴板可粘贴 / 无兼容内容。
- 已输入，键盘打开。
- 粘贴追加后。
- 翻译处理中。
- 翻译成功。
- 模型失败。
- Local 模型缺失。
- Prompt 名较长。
- Standard、XXL、Accessibility Dynamic Type。
- 日间、夜间、Increase Contrast、Reduce Motion。

要求：

- 处理中、成功、失败不能只靠颜色，继续使用图标和文字。
- 输入与译文支持长文本、滚动和选择，不能被背景或浮层遮挡。
- 装饰性网格 / 线路对 VoiceOver 隐藏。
- 背景不参与焦点顺序，不响应手势，不截获粘贴、翻译或滚动操作。
- 只对直接操作提供短反馈；禁止循环脉冲、持续发光、漂浮和背景动画。
- 使用 `.animation(..., value:)` 或明确 `withAnimation`，禁止无 value 的全局 animation。

## 10. 代码边界与性能

- 保持 iOS 17 deployment target，不无保护使用 iOS 18 / 26 API。
- 使用 SwiftUI 和 SF Symbols，不新增第三方 UI / animation / snapshot 依赖。
- 不更改 v1.87 页头位于 `ScrollView` 外的安全区契约。

# 漫画浏览器翻译状态契约

> 状态：设计基线（schema v1）。本文只定义后续漫画浏览器 OCR、翻译与网页覆盖层必须共同遵守的状态契约，不代表相关业务代码已经实现。

## 1. 目标、范围与规范用语

本契约覆盖漫画内嵌浏览器中“抓取当前可见网页内容 → OCR → LLM 或 Apple Translation → 将译文重绘回网页文字区域”的状态、身份、缓存和资源生命周期。首版处理单位是**一个稳定的可见视口**，不是整张无限长网页。

本文中的“必须”“不得”是正确性要求；“应”是默认策略，只有留下明确的替代设计和验证证据时才可偏离。

本契约不决定 OCR 算法、翻译质量门槛、气泡擦除样式或 UI 视觉稿，也不允许诊断探针、ground truth、参考译文或 fixture 进入生产候选生成与选择。

## 2. 与现有架构的对齐

本设计扩展现有约定，不建立第二套状态中心：

- `BrowserModel` 继续只拥有 `BrowserTab.id`、`activeTabID`、页面阶段、URL、滚动位置、导航能力、内存缩略图以及 WKWebView 意图。它负责产生可信的网页身份事实，但不得拥有 OCR、翻译引擎、翻译缓存或持久化。
- `TranslationSessionStore` 继续是唯一翻译业务状态与异步调度中心。漫画浏览器任务 ID、状态机、结果、取消、缓存和对 UI 的投影必须由 Store 原子管理。
- `BrowserWebView.Coordinator` 只充当 WKWebView 适配边界：上报导航/滚动/布局事件、抓取像素、提供网页坐标到覆盖层坐标的变换。它不得直接调用 OCR 或翻译引擎，也不得自行接受异步译文。
- OCR 层继续输出产品级文字块，区域主几何复用 `NormalizedImageRect` 的有限、正面积、左上原点单位坐标约定。OCR 内部 candidate、owner、shadow ledger 和临时裁片不得进入页面业务状态。
- 翻译层继续复用 `ModelGenerationRequest`、`TranslationRequestProfile.mangaBlocks`、确认术语记忆和只读前批摘要。当前 GGUF 路径由 `GemmaLocalService`/`LlamaRuntime` 串行执行；未来 Apple Translation 适配器也必须接受同一任务信封和回写门禁。
- 漫画浏览器当前不持久化。schema v1 的任务、网页结果和缓存均为内存态，不加入 `AppPersistenceSnapshot` 或 `state.json`；若以后需要磁盘缓存，必须另行定义隐私、配额、文件认证和迁移契约。

现有图片翻译已经采用“新任务先取消旧 `Task`、旋转 UUID、递增 revision、回调再次核对 task/content/block”的做法。本契约将同一原则扩展为浏览器的 `taskID + document identity + viewport generation + region fingerprint` 四重门禁。`Task.cancel()` 只是节省工作量的协作信号，身份门禁才是防止旧结果回写的正确性边界。

## 3. 状态所有权与数据流

| 层 | 唯一拥有的状态 | 明确不得拥有 |
| --- | --- | --- |
| `BrowserModel` | 标签、活动标签、导航/文档/布局/视口世代、当前网页测量值 | OCR 块、译文、模型上下文、翻译任务状态 |
| WKWebView 适配边界 | 当前 WebView 引用、抓取过程、坐标变换的瞬时测量 | 可长期保存的业务结果、缓存判定、模型调用 |
| `TranslationSessionStore` | 活动任务信封、状态机、区域结果、缓存、取消与可渲染快照 | WKWebView、滚动代理、DOM 对象、长期位图 |
| OCR 服务 | 一次调用内的图像工作缓冲、候选和识别输出 | 页面是否仍有效、UI 回写、翻译缓存 |
| 翻译适配器 | 一次请求的 prompt/session、模型调用和原始结果 | 页面坐标、活动标签、覆盖层 |
| 覆盖层 | Store 发布的只读可渲染快照和当前坐标变换 | 任务调度、OCR/翻译调用、绕过 Store 改结果 |

标准数据流为：BrowserModel 签发视口租约 → 适配边界抓取并形成不可变页面快照 → Store 校验后进入 OCR → Store 校验后进入翻译 → Store 校验并原子提交区域结果 → 覆盖层只渲染当前可渲染快照。任一服务返回值都不得直接流向 View。

## 4. 页面与当前屏幕身份

### 4.1 两层身份

必须区分“当前结果能否回写”的**实时身份**和“内容是否足够相同、可以复用”的**缓存身份**。导航世代不同的两个页面永远不是同一个实时页面，即使 URL 和截图完全相同；它们可以在重新抓取并验证内容摘要后命中同一个缓存键。

实时身份由以下两层值组成。

#### 文档身份 `BrowserDocumentIdentity`

| 字段 | 约定 |
| --- | --- |
| `tabID` | 直接复用现有 `BrowserTab.id`。不得用标签数组下标代替。 |
| `navigationGeneration` | 每个标签单调递增。任何顶层 load、reload、retry、前进、后退、恢复后台标签的 WebView 重建，都必须在动作发出前递增。相同 URL 的刷新也必须产生新值。 |
| `documentID` | 顶层导航提交新文档时生成的 UUID。网页尚在 `.start`/`.loading`、导航失败或内容进程终止时不得签发可翻译的 `documentID`。 |
| `canonicalURL` | 顶层 frame 最终提交的规范化 URL；只用于联合校验和诊断，不能单独证明内容相同。 |
| `contentGeneration` | 同一 document 内发生会改变可见内容的 SPA 路由、DOM 替换、图片源变化或延迟加载时单调递增。 |
| `layoutGeneration` | 会改变网页元素文档坐标的重排、字体/图片尺寸落定、视口宽度变化或方向变化时单调递增。纯覆盖层动画不改变它。 |

#### 视口身份 `BrowserViewportIdentity`

| 字段 | 约定 |
| --- | --- |
| `documentIdentity` | 上述完整文档身份的不可变副本。 |
| `viewportGeneration` | 用户开始滚动/缩放、程序跳转锚点、视口尺寸改变或签发新抓取时立即递增；浮点滚动值不得直接承担世代职责。 |
| `captureID` | 每次被 Store 接受的像素抓取 UUID。一次重试或重新抓取必须使用新值。 |
| `visibleRectDocumentCSS` | 抓取时可见内容在网页文档坐标中的矩形，单位为 CSS point，左上为原点。 |
| `layoutViewportSizeCSS`、`contentSizeCSS` | 抓取时的网页布局视口和文档尺寸，用于识别重排、延迟加载和坐标漂移。 |
| `pageScale`、`devicePixelRatio` | 抓取时 CSS 坐标与设备像素的关系，只用于映射，不能代替世代号。 |
| `capturePixelSize`、`captureContentRectPixels` | 原始抓图尺寸，以及真正交给 OCR 的内容矩形。内容矩形必须排除 App 胶囊、翻译球、安全区空白和其他原生覆盖物。 |
| `captureSHA256` | 对规范化后的 OCR 输入像素计算的摘要。抓取完成前为空；为空时不得读取 OCR/翻译缓存或发布覆盖层。 |

一个页面任务的严格 `PageSnapshotIdentity` 是上述全部实时字段与抓取摘要的组合。Store 比较结构化字段，不使用拼接字符串或 URL 猜测相等。

### 4.2 URL 规范化

`canonicalURL` 必须由顶层 frame 的最终 URL 生成：scheme 与 host 小写、移除默认端口、空路径归一为 `/`，保留 path 的百分号编码语义以及 query 的字段和值顺序。不得删除“跟踪参数”、排序 query 或做站点特例，因为这些变化可能影响实际漫画内容。

fragment 不进入文档资源键，但原始 URL 仍保留用于显示。仅作为锚点滚动的 fragment 变化更新视口世代；无法证明只是锚点时，按 SPA 内容变化处理并更新 `contentGeneration`。非 HTTP(S)、缺少有效 host 或无法稳定规范化的 URL 不可进入翻译管线。

### 4.3 世代更新与失效矩阵

| 事件 | 身份变化 | 对进行中任务/覆盖层的要求 |
| --- | --- | --- |
| load、reload、retry、前进、后退 | 先递增 `navigationGeneration`，旧 `documentID` 失效 | 先撤销回写资格，再取消任务并清空旧文档活动覆盖 |
| 同次顶层导航中的重定向 | 保持同一 navigation 世代，更新候选 URL；提交时生成 `documentID` | `.loading` 期间不得新建翻译任务 |
| 顶层导航完成且布局稳定 | 固化最终 URL、文档与布局身份 | 才可签发视口抓取租约 |
| SPA 路由、DOM 内容替换、延迟图片加载 | 至少递增 `contentGeneration`；影响几何时同时递增 `layoutGeneration` | 取消旧任务；旧区域不得继续渲染 |
| 用户开始滚动或程序改变 offset | 立即递增 `viewportGeneration` | 取消仍在抓取/OCR/翻译的当前视口任务；完成区域可按文档坐标移动，离开可见范围即不渲染 |
| 滚动/减速结束并稳定 | 签发新视口世代与新 `captureID` | 自动模式可排队新任务；手动模式等待用户触发 |
| 纯视觉缩放且网页未重排 | 更新当前投影测量；开始手势时仍使进行中视口任务失效 | 已完成区域按文档坐标重投影，不复用旧屏幕像素坐标 |
| 横竖屏、Split View、动态字体或缩放导致重排 | 递增 `viewportGeneration` 和 `layoutGeneration` | 旧几何全部隐藏，重新抓取/OCR；不得靠拉伸旧框蒙混 |
| 切换/关闭标签 | 活动任务的 tab 不再匹配 | 取消任务并释放位图；关闭标签同时移除其轻量结果。后台标签不持有 WebView 或任务 |
| 返回后台标签 | WebView 重建视为新顶层导航 | 即使 URL 相同也不得直接显示旧覆盖；新抓取摘要验证后才可走缓存 |
| 网页内容进程终止 | 旧 `documentID` 永久失效 | 取消任务、清除文档覆盖和抓取资源，等待重新加载 |

滚动、缩放和布局稳定的 debounce 时长属于实现策略，不属于身份。硬规则是：拖动、减速、缩放或布局变更仍在进行时不得抓取；一旦用户动作开始，旧的进行中任务已经失去回写资格。

### 4.4 可渲染判定

覆盖层显示一个区域前必须同时满足：

1. 当前 `activeTabID` 与区域 `tabID` 相同。
2. 当前 `documentID`、`navigationGeneration`、`contentGeneration`、`layoutGeneration` 与结果一致。
3. 区域状态为已完成，且来源任务曾通过完整回写门禁。
4. 区域的网页文档矩形与当前可见文档矩形相交。
5. 当前坐标变换全部有限、尺寸为正，映射结果仍落在 WebView 内容区域内。
6. 覆盖快照的 `renderRevision` 仍是 Store 发布的最新值。

任一条件不满足时必须 fail closed：不绘制、不定位、不用最近一次坐标兜底。隐藏旧结果不等于删除缓存；只有通过新的页面快照验证后，缓存结果才能重新进入当前可渲染快照。

## 5. 区域身份与坐标契约

### 5.1 区域字段

一个产品级浏览器文字区域至少包含：

| 字段 | 作用 |
| --- | --- |
| `regionID` | OCR 本次产物中的 UUID，只在当前页面快照内唯一；不得由识别顺序或数组下标充当。 |
| `pageSnapshotIdentity` | 创建该区域的完整页面快照身份。 |
| `readingOrder` | 当前快照内稳定的零基顺序。它用于批处理顺序，不是身份。 |
| `boundingBox` | 复用 `NormalizedImageRect`，相对 `captureContentRectPixels` 归一化。 |
| `automaticBoundingBox` | 可选的初始 OCR 几何；将来人工修正只改变当前框，不篡改自动基线。 |
| `documentRectCSS` | `boundingBox` 经抓取元数据映射到网页文档坐标后的矩形，是滚动和纯缩放时重投影的锚点。 |
| `original`、`translation` | OCR 原文与译文；原文为空时不得创建可翻译区域。 |
| `confidence`、`sourceDirection`、`textKind` | 沿用现有图片文字块语义；引擎原始置信度不得跨引擎当作同一标尺。 |
| `sourceFingerprint` | 规范化原文、区域裁片摘要、几何和 OCR 配置的稳定摘要，用于回写核对与缓存。 |

同一段文字可能在一屏出现多次，因此原文摘要不能充当 `regionID`。数组重排也不得改变已经创建的 `regionID`；结构性拆分/合并必须生成新 ID、递增区域集合 revision，并使旧区域任务失效。

### 5.2 坐标空间

`NormalizedImageRect` 继续采用左上原点、x 向右、y 向下，所有分量位于 `[0, 1]`，宽高必须大于零。Vision 的左下原点坐标必须像当前普通图片 OCR 一样在 OCR 边界转换一次；后续层不得再次翻转 y。

映射只能按以下链路进行：

1. OCR 返回相对 `captureContentRectPixels` 的单位矩形。
2. 把单位矩形乘以抓取时的 `visibleRectDocumentCSS`，得到 `documentRectCSS`。
3. 渲染时使用当前 WebView 的文档 offset、content inset 和 scale，将 `documentRectCSS` 转为当前覆盖层坐标。

不得把设备像素、UIKit point、CSS point、Vision 单位坐标混存在同一字段中，也不得持久化 SwiftUI `GeometryProxy` 或 UIKit view 坐标。`capturePixelSize`、内容裁切、scale 和坐标空间版本必须与 OCR 框一起传递，不能依赖调用方猜测。

所有 OCR 几何在进入 Store 前都必须通过与 `NormalizedImageRect.normalizedToUnit()` 等价的有限值、裁切和正面积检查。映射后的矩形若出现 NaN、无穷值、非正面积、越过内容边界或明显与抓取覆盖无交集，该区域进入显式失败记录，不得静默删除后继续宣称整页完成。

### 5.3 旋转、缩放和网页重排

- 纯缩放只改变 CSS 文档坐标到覆盖层坐标的投影；`boundingBox` 和 `documentRectCSS` 不变。
- 安全区、原生工具条和翻译球不属于网页内容坐标，任何布局变化都不得被加进 OCR 单位框。
- 横竖屏或视口宽度变化若触发网页重排，旧 `documentRectCSS` 不再可信，必须换 `layoutGeneration`、隐藏旧框并重新识别。
- 若网页只是改变原生显示尺寸而 CSS 布局和元素文档坐标未变，可用新投影重绘；是否“未重排”必须由布局测量证明，不能由 URL 相同推断。

## 6. 任务身份、状态机与回写门禁

### 6.1 不可变任务信封

每次“翻译当前页”必须创建新的 UUID `taskID`，并冻结以下输入：完整 `PageSnapshotIdentity`、手动/自动模式、源/目标语言、OCR profile 与版本、翻译引擎标识与模型 revision、prompt ID 与内容摘要、产品采样配置、`TranslationRequestProfile`、确认术语摘要、上下文摘要、契约 schema 版本和 `requestConfigurationRevision`。

用户重试也必须创建新 `taskID`，不得把取消或失败任务改回排队态。语言、引擎、模型文件、prompt、采样、术语或上下文策略变化时，Store 必须先递增配置 revision 并取消旧任务。

### 6.2 页面任务状态机

| 状态 | 允许来源 | 允许去向 | 可持有资源 |
| --- | --- | --- | --- |
| `queued` | 新请求 | `capturing`、`cancelled`、`failed` | 任务信封，不持有截图 |
| `capturing` | `queued` | `recognizing`、`cancelled`、`failed` | 唯一活动抓图和映射元数据 |
| `recognizing` | `capturing` | `translating`、`completed`、`cancelled`、`failed` | 有界 OCR 工作图与区域列表 |
| `translating` | `recognizing` | `completed`、`cancelled`、`failed` | 轻量区域列表、当前有界 batch 和只读上下文 |
| `completed` | `recognizing`、`translating` | 无 | 只保留文本、几何、来源摘要、成功/失败区域清单 |
| `cancelled(reason)` | 任一非终态 | 无 | 不持有截图、裁片、prompt、模型 session 或可回写句柄 |
| `failed(stage, reason)` | 任一非终态 | 无 | 同 `completed` 的轻量诊断；不得保留大资源 |

OCR 没有区域时可以从 `recognizing` 进入 `completed`，结果为明确的 empty outcome。部分区域翻译失败时，页面进入 `completed(partial)` 并保留失败区域及原因；不得为了显示“完成”而删除失败块。只有任务级基础设施故障才进入 `failed`。

每个区域还需有 `recognized → queuedForTranslation → translating → completed/failed/cancelled` 的子状态。页面进度由这些子状态派生，View 不维护第二份计数。

### 6.3 原子回写条件

Store 是 `@MainActor` 的唯一提交者。每次阶段切换、每个 OCR 回调、每个翻译 batch/区域结果以及每次错误处理，在修改状态前都必须一次性核对：

- `taskID` 等于 Store 当前活动浏览器任务 ID；
- `PageSnapshotIdentity` 等于 BrowserModel 当前签发且仍有效的页面/视口身份；
- `requestConfigurationRevision` 仍是当前配置 revision；
- 区域仍存在，且 `regionID + sourceFingerprint` 与请求时完全一致；
- 当前 Swift Task 未取消；
- 目标状态是状态机允许的单向转换。

任何一项不匹配，回调只能无副作用退出：不得改进度、错误提示、当前覆盖、缓存、历史或全局 `isProcessing`。旧任务的 `CancellationError` 也不得把新任务改为取消状态。

允许在一个当前任务中逐区域发布已完成译文，但每次发布都要通过同一门禁并生成新的 Store `renderRevision`。Renderer 只能消费不可变的 `RenderableOverlaySnapshot`，不能把翻译回调直接写进现有 overlay 对象。

### 6.4 取消顺序与触发条件

取消必须按固定顺序执行：

1. 先旋转活动任务 ID/页面或配置世代，使旧任务立即失去回写资格。
2. 将旧状态记录为 `cancelled(reason)`；若新任务马上替换，可只对外发布新任务状态，但诊断必须能区分替换原因。
3. 调用 Swift Task、OCR 请求和引擎适配器的取消能力。
4. 释放抓图、裁片、prompt、当前 batch 和引擎 session。
5. 发布不包含旧进行中结果的新 `renderRevision`。

触发取消的事件包括：新请求替换、用户取消、任何顶层导航、开始滚动/缩放、影响内容或几何的 DOM 变化、标签切换/关闭、WebView 拆除、网页内容进程终止、语言/引擎/prompt/术语配置变化、进入资源紧张处置以及 Store 销毁。

由于当前 `LlamaRuntime.generate` 是锁内同步生成，取消可能无法立刻停止已经进入 native runtime 的计算；这种情况下，身份门禁必须丢弃迟到结果。后续即使增加 cooperative abort，也不得移除门禁。

### 6.5 并发上限

现有浏览器只有一个活动 WKWebView，因此全局同时最多有一个活动页面抓取/OCR 任务和一个翻译引擎请求。区域不得无界并发地启动模型调用。

LLM 漫画批处理沿用普通图片路径的稳定上限：每批最多 8 个区域、合计最多 1,800 个源字符，并由具体模型的 token/context 上限进一步收紧；只允许携带紧邻的一个已完成前批只读摘要。Manga OCR 的单批裁片最多 4 个。Apple Translation 若支持批量，也必须服从页面任务身份、内存预算和有界并发，不得自行并行回写。

## 7. 缓存键与复用

### 7.1 缓存层级

| 缓存 | 键的必备字段 | 值 |
| --- | --- | --- |
| 页面像素键 `PageContentKey` | schema、规范 URL 摘要、`captureSHA256`、内容像素尺寸与坐标空间版本 | 只作为下级键前缀，不保存截图 |
| OCR 键 `OCRCacheKey` | `PageContentKey`、源语言/布局、预处理版本、OCR/检测器模型 revision | 文字、置信度、单位几何、方向、阅读顺序和区域裁片摘要 |
| 区域键 `RegionContentKey` | `OCRCacheKey`、量化后的单位几何、区域裁片 SHA-256、规范化原文摘要、方向/文本类型 | 稳定区域内容身份；解决同页重复台词冲突 |
| 译文键 `TranslationCacheKey` | `RegionContentKey`、源/目标语言、引擎与模型 revision、translation profile、prompt ID 与内容摘要、产品采样摘要、确认术语摘要、前批上下文摘要、契约版本 | 译文、质量结果、创建/最近访问时间和来源元数据 |

单位几何量化只用于产生稳定缓存键，不能替代渲染用的原始 Double 几何。量化精度必须写入坐标空间版本；改变精度即升级版本并清空旧缓存。

模型 revision 对 GGUF 至少包含模型文件身份或 SHA-256 与 prompt profile；对 Apple Translation 至少包含适配器版本、语言对、可获得的系统/语言资产版本。无法获得资产版本时，必须把 App build 与 OS 主/次版本纳入 revision，宁可少命中也不能复用语义来源不明的译文。

### 7.2 命中顺序与门禁

缓存不得仅凭 URL、滚动百分比、OCR 原文或 `regionID` 命中。正确顺序是：对当前稳定视口重新抓取 → 验证当前任务身份 → 计算 `PageContentKey` → 尝试 OCR 命中 → 以区域裁片/文字/几何确定 `RegionContentKey` → 尝试译文命中 → 再次通过当前任务和区域门禁 → 发布新的当前结果。

因此，同 URL 刷新、后台标签恢复或 App 内再次访问可以复用完全相同的页面/气泡，但旧覆盖不会在像素摘要确认前闪现。页面中两处相同台词因裁片和几何不同不会互相冒充；同一气泡的 OCR 文本、语言、prompt、术语、上下文或引擎变化也不会误命中。

取消结果、空译文、质量失败、解析失败和任务级错误不得写入成功缓存。可选的失败退避只能单独保存短时错误类型，不能作为译文结果，也不能跨配置 revision。

### 7.3 缓存生命周期

schema v1 只使用 Store 管理的内存 LRU：页面/OCR/译文缓存合计成本上限 16 MiB，同时最多保留 8 个页面内容键和 2,000 条区域译文；任一上限先到即按最近最少使用淘汰。缓存成本必须按字符串、集合和元数据的估算字节计，不得把 UIImage、CGImage、CVPixelBuffer、区域裁片、WKWebView、模型上下文或闭包放入缓存值。

标签关闭时应删除该标签仅有的活动投影，但内容寻址缓存可继续受 LRU 管理。用户清除浏览数据、切换隐私策略、契约/坐标/OCR schema 升级或收到内存压力时必须可整体清空。内存缓存不得进入翻译历史，也不得改变文本/普通图片会话。

## 8. 内存与资源边界

### 8.1 硬上限

- 继续保持全 App 只有一个活动 WKWebView；后台标签只保留现有轻量值快照，不持有 WebView。
- 同时最多一个浏览器像素抓取。禁止整页长截图；只抓稳定可见内容矩形。
- OCR 工作图最长边不超过 4,096 像素且像素数不超过 6,000,000。超限时必须先等比下采样，并保留原始抓取到工作图的精确映射。
- 同时最多持有一份抓取解码图和一份 OCR 工作图，位图瞬时预算为 48 MiB；包含裁片和临时渲染在内的浏览器翻译瞬时预算为 64 MiB，不含 WKWebView 与服务级模型权重。
- 单视口最多接受 256 个产品区域。超限必须形成显式 `partial/regionLimitExceeded`，不能静默截断后宣称成功。
- LLM 每批与 Manga OCR 每批上限遵守第 6.5 节；任何引擎自身更小的 token、内存或批量限制优先。

预算无法通过下采样、分批和释放前序缓冲满足时，任务必须以 `failed(memoryBudgetExceeded)` 收口，不得继续冒险申请大对象。

### 8.2 持有与释放时机

| 资源 | 最早创建 | 最迟释放 |
| --- | --- | --- |
| 原始视口抓图 | `capturing` | OCR 工作图和 `captureSHA256` 生成后立即释放；不得等翻译结束 |
| OCR 工作图/CVPixelBuffer | `recognizing` | OCR 返回产品区域或抛错/取消后立即释放 |
| 区域裁片、warp、MultiArray | 单个 OCR 有界 batch | 该 batch 返回后释放；不得附着到区域模型或缓存 |
| OCR candidate/owner/shadow ledger | OCR 内部 | 产品区域确定后释放；诊断模式也不得晋级为业务状态 |
| 产品区域文字与几何 | OCR 完成 | 当前文档失效或进入受限 LRU；终态只保留轻量字段 |
| prompt、token、前批摘要 | 当前翻译 batch | batch 成功、失败或取消后释放；下一批只接收约定的只读摘要 |
| Apple Translation session | 首个未命中 batch | 页面任务终态、语言对变化、后台/内存处置时释放 |
| GGUF 请求 KV/context 内容 | 每次 generate | 每次生成结束前清空；模型权重是否常驻由模型服务统一决定 |
| 可渲染快照 | Store 提交结果 | 被新 `renderRevision` 替换后释放；View 不留历史副本 |

现有 `MangaOCRService.shared` 和 `GemmaLocalService` 静态 runtime 会让服务级模型保持 warm；它们不属于某个页面任务，页面取消不得通过销毁 Store 私自重建模型。`LlamaRuntime` 当前每次生成会清空 memory/sampler，并用锁串行保护 1,024 token context。未来若增加显式 unload/purge，只能由统一资源策略在没有活动推理时调用。

### 8.3 生命周期事件

- 切页、切标签、取消、失败：立即释放所有任务级位图、裁片、prompt 和 session；只留下允许缓存的轻量成功结果与终态原因。
- App 进入后台：取消进行中抓取/OCR/翻译，释放任务级大对象；轻量文本缓存可保留。
- 收到内存警告：先清空全部页面/OCR/译文 LRU 和非活动标签缩略图，再释放空闲引擎 session；不得删除当前 Store 的文本/普通图片业务状态。
- 网页内容进程终止：除上述释放外，移除该 `documentID` 的所有活动覆盖和坐标投影。
- Store/View 销毁：旋转任务身份、取消所有子任务并断开回调；闭包必须弱引用 Store/WebView，不能形成环。

## 9. UI、OCR、翻译与重绘的接口约束

- UI 只能向 BrowserModel 发网页意图、向 Store 发“翻译/取消/切换模式”业务意图，并展示 Store 投影。UI 不自行拼页面键、改任务状态或保存译文。
- BrowserModel 只发布不可变身份/测量值；不得为了方便把 `TranslationSessionStore`、模型服务或 OCR 服务塞入 `BrowserTab`。
- OCR 输入只包含规范化像素、坐标元数据和 OCR profile；OCR 不知道活动标签、翻译引擎或 UI。
- 翻译输入只包含字符串、语言、profile、确认术语和有界只读上下文；翻译引擎不接收 URL、CGRect、WKWebView 或覆盖层引用。
- 重绘输入只包含 Store 已认证的区域译文、`documentRectCSS`、页面身份和 `renderRevision`；重绘层不得读取缓存或接受引擎 callback。
- BrowserModel 的 notice revision、View 的菜单/拖拽/原文译文切换仍是展示状态，不能充当任务或页面身份。
- 浏览器 OCR/翻译结果不得写入普通图片 blocks、OCR-only 工作台或现有文本 transcript，除非未来有显式“保存到历史”产品动作及独立契约。

## 10. 必须验证的竞态与验收断言

后续实现只有同时通过以下断言，才算遵守本契约：

1. 第 5 页任务尚未返回时滚到第 2 页：第 5 页回调不能改第 2 页进度、错误、缓存或覆盖；已完成的第 5 页区域只在其文档矩形重新可见且身份仍有效时重投影。
2. 同 URL 刷新或后退再前进：实时 `documentID` 必须变化，旧覆盖先隐藏；只有新抓取摘要和全部配置键一致时才可命中缓存。
3. A 标签翻译中切到 B：A 任务先失去回写资格并释放位图；B 不显示 A 的状态。返回 A 因 WebView 重建而重新验证内容。
4. OCR 返回前旋转屏幕：旧 layout 世代的区域不得进入 Store；新布局重新抓取。纯缩放不改变区域单位几何，重投影后框仍贴合。
5. 页面在相同 URL 延迟加载下一张漫画：内容/布局世代改变，旧任务取消；URL 相同不能绕过失效。
6. 同一气泡在语言、引擎、模型、prompt、术语或前批上下文任一变化后：旧译文缓存不得命中。
7. 旧任务在新任务完成后抛出 `CancellationError` 或普通错误：新任务的 completed 状态和 UI 提示不得被回滚。
8. 同屏两处原文相同：区域 ID 与缓存键仍不同，译文不会因数组顺序变化贴错框。
9. 发生无效/越界/NaN 几何：该区域不渲染并保留失败原因，页面不得伪装成全成功。
10. 连续快速滚动、刷新和切标签：活动抓图、OCR、翻译引擎请求都不超过规定并发，缓存与瞬时内存不越过硬上限。
11. 内存警告或 App 退到后台：大对象可被释放，迟到回调无副作用；恢复后通过新身份重新开始。
12. View、OCR、翻译适配器和 renderer 的单元/合同测试可分别使用契约值替身运行，不需要互相持有具体实现。

## 11. 版本与演进

本契约初始 `schemaVersion = 1`。新增不影响身份相等、坐标含义或缓存语义的可选字段可以保持版本；以下变化必须升级 schema 并清空不兼容缓存：URL 规范化、坐标原点/单位、几何量化、页面摘要算法、OCR profile 身份、翻译缓存输入集合、状态机终态语义或持久化策略。

未来实现可以新增全页分块、跨视口预取或磁盘缓存，但不得弱化本契约的四个核心不变量：**URL 不等于页面身份；只有 Store 能提交业务结果；每次异步回写都重新核对身份；大像素与模型上下文绝不附着到长期页面状态。**

# AITRANS Agent X 提示词：114514云端改造

## 版本分配依据
这是协作制度、分支流、验证执行位置和 `AGENTS.md` 入口规范的结构性调整，不属于漫画探针 v1 小优化，因此新开 v2 阶段。

## 你的身份
你是 Agent X。本轮任务是修改工作流程转云端、build测试构建和必要 CI 配置修改，不做漫画探针算法优化，不改 OCR / 翻译主流程。

## 背景
当前 AITRANS 的本地验证成本过高。Swift / Xcode build、模拟器探针、输出导出和 JSON/PNG artifact 检查会持续消耗本机资源。后续工作流要改成：

```text
人提出工目标
  -> Agent A 本地分析并写版本化提示词
  -> Agent B 本地编程实现 + 超轻量检查
  -> Agent B 推送 codeb/vX.Y-短标题 分支到 GitHub
  -> GitHub Actions 云端跑 build / 探针 / JSON 检查 / artifact 上传
  -> Agent C 拉取分支，审查 diff、CI 日志和 artifacts
      -> 有 bug：C 写退回清单，B 继续修并 push
      -> 无 bug：C 更新版本号和核心文档，合并到 samlldata_test
```

分支策略必须改变：

- `main` 只作为外观展示分支，不作为日常开发主分支。
- `samlldata_test` 是本项目实际工作主分支。
- Agent B 的实现分支必须命名为 `codeb/vX.Y-短标题`。
- Agent C 验收通过后必须及时合并回 `samlldata_test`，避免堆积一批长期未合并分支。
- 严禁合并到 `main`分支。

默认验证策略必须改变：

- 除非人工明确要求本机测试，否则所有 build、Xcode 测试、漫画探针、报告生成和重验证默认在 GitHub Actions 云端执行。
- 本地仍保留测试和编译能力，作为人工明确要求、紧急排查或云端环境故障时的备用路径。
- Agent 不得因为“Swift 代码变了”就默认在本机跑 Xcode build；默认动作是推送分支，让云端跑。
- 如果人工没有要求本机测试，最终回复要明确写“未跑本机 build / 探针，按规则交给云端验证”。
- 若某项验证不能在云端稳定运行，Agent 必须告诉人工缺失的依赖、失败原因和后续补齐条件，不得伪装成已通过。

## 云端结果包和版本追踪要求
Agent B 的云端 Xcode 测试必须把结果打包成 GitHub Actions artifact，供 Agent C 验收。

最低 artifact 内容：

- `.xcresult`：Xcode 结果包，例如 `TestResults/AITRANS-${version}-${short_sha}.xcresult`。
- `junit.xml`：CI 可读测试/构建结果摘要。若当前没有 XCTest，可先生成 build smoke 的 JUnit 摘要；后续有 XCTest 后再接入真实 test report。
- `xcodebuild.log`：完整构建日志。
- `ci-artifact-manifest.json`：结果包索引，必须包含 `version`、`branch`、`commitSha`、`runId`、`runAttempt`、`workflowName`、`createdAt`、`xcodeVersion`、`scheme`、`destination`、`resultBundlePath`、`junitPath`、`probeReportPath`。
- 若运行漫画探针：上传 `output/probe_report.json`、`output/clean_text_diagnostic.json`、`output/1_ocr_probe_text.txt` 和关键 PNG。

artifact 命名建议：

```text
aitrans-ci-${version}-${branch_slug}-${short_sha}-run${run_id}-attempt${run_attempt}
```

版本取用规则：

- Agent B 最终回复必须写清楚 `version`、`branch`、`commitSha`、`runId`、`runAttempt` 和 artifact 名称。
- Agent C 只能验收与当前 `codeb/...` 分支 HEAD 完全一致的 `commitSha`。
- Agent C 必须核对 artifact manifest 中的 `branch`、`commitSha`、`runId`、`runAttempt`，确认没有拿旧包、错包或其他分支的包。
- 如果 B 修复后再次 push，C 必须丢弃旧 run 的结果，只看最新 HEAD 对应的 run。
- 如果 Actions 重跑，C 必须记录使用的是哪个 `runAttempt`。
